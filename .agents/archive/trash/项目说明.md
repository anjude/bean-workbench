# 项目说明

接手这个项目前先读这份文档，它说明项目是什么、东西放在哪。具体怎么操作由工作台的 bn 系列 skill 规定，不写在这里。

## 这是什么

豆小匠 Note（beannote），一个面向理财自媒体的内容管理库，覆盖从选题到发布的完整内容生产。

- 账号定位：中产上班族视角的理财分享
- 内容方向：基金、ETF、股票、期权、保险、资产配置、理财误区、工资分配与家庭财务规划
- 主要平台：公众号（默认）、小红书
- 主要形式：图文为主，兼容短视频和口播脚本

## 目录长什么样

```text
beannote/
├── topics/          一篇选题一个目录，从选题到复盘都在这里
│   ├── 索引.md      状态看板
│   ├── 2026-05/     往月归档，按选题记录日分
│   └── …当前月的选题直接放 topics/ 根
├── knowledge-base/  跨选题的长期素材
├── data/            发布记录与高频问题
└── docs/            本文件、账号定位、内容手册
```

`topics/` 是唯一生产区。根只放当前月在做的选题，跨月后按选题记录日搬进 `YYYY-MM/`，归档只换目录不改名字。

一个选题建一次目录，路径之后只在两种情况下变：跨月归档、发布或废弃时改目录名前缀。

| 前缀 | 含义 |
|---|---|
| 无 | 在制，包括只有大纲还没动笔的 |
| `done-` | 已发布 |
| `drop-` | 已归档，废弃或过期，不进数据统计 |

每个选题目录里按编号放文件，编号就是流程顺序：

| 槽位 | 内容 |
|---|---|
| `01_大纲.md` | 内容层三件事：选题方向 + 事实依据 + 逻辑脉络（不含写法） |
| `02_脚本.md` | 读者推进节奏、图文分页结构 |
| `03_正文.md` | 跨平台纯享长文 |
| `04_发布稿.md` | 公众号终版 |
| `05_检查清单.md` | 发布前自检 |
| `06_复盘.md` | 数据表现、原因分析、规则沉淀 |
| `manifest.yaml` | 本篇唯一状态源：状态、结论、决策、卡点、数据 |
| `assets/` | 封面和配图 |

不是每篇都要凑齐六个，按需生成，缺哪号就是卡在哪步。

每个选题目录里还有一份 `manifest.yaml`，是本篇的唯一状态源：记录 `status`（在制 / 已发布 / 已归档）、`conclusion`（本篇主张）、`decisions`（定了什么、被否掉的切口）、`blockers`（卡点）、`metrics`（发布数据）等。`status` 必须与目录名前缀一致。`topics/索引.md` 由它派生，改完 manifest 重跑脚本即可，不要手改索引。

`topics/索引.md` 是全部选题的状态看板，按在制 / 已发布 / 已归档分组，目录列带 `YYYY-MM/`，一眼能看到每篇走到哪一步、归档在哪个月。

## 数据在哪

- `data/发布记录总表.csv`：已发布内容的数据，字段含曝光、点赞、收藏、评论、涨粉、链接
- `data/高频问题记录.md`：评论区和私信里的高频提问
- 每篇自己的 `06_复盘.md`：生产过程、用户反馈、规则沉淀

## 规则在哪

内容创作的规范不写在这个仓库的文档里，全部由工作台 `.agents/skills/` 下的 bn 系列 skill 承载，按用户交互回合划分：

| 阶段 | skill | 什么时候用 |
|---|---|---|
| 00 选题与大纲 | `bn-0000-outline-flow` | "想写 XX"、"这个热点能不能写"。只定内容层：选题方向 / 事实依据 / 逻辑脉络 |
| 01 成稿 | `bn-0101-draft-flow` | 大纲确认后，先设计表达（入口/视角/节奏/化链/收尾）再一次成稿 |
| 02 审稿 | `bn-0201-review-flow` | 接反馈改稿、跑发布检查 |
| 03 发布 | `bn-0301-publish-flow` | 推公众号草稿箱、登记数据 |
| 03 复盘 | `bn-0302-retro-flow` | 发布后复盘与经验沉淀 |

工具 skill：`bn-tools-content-context`（目录与状态约定）、`bn-tools-writing-rules`（写作硬规则）、`bn-tools-knowledge-base`（素材整理）。

账号定位和文风偏好在 `docs/content-playbook.md`，它的优先级高于 skill 里的旧规则。

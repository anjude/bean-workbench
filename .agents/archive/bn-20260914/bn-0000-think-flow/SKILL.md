# 思考（00 阶段）

## 这一步解决什么

把一个"听说了"的东西，变成"懂了"。没懂的题，后面怎么组织、怎么措辞都救不回来。

| | |
|---|---|
| 用户在这一步说什么 | 抛一个热点 / 概念 / 一句话想法；或追问某个细节、质疑某个说法 |
| agent 做什么 | 接住 → 拆层 → 追问 → 找反常识点 → 排雷 → 给判断 |
| 产物 | 一句话本质、这题的反常识点、写不写的判断 |
| 停下等什么 | 用户认可「本质是这个」 |

上游：用户的一句话输入
下游：`bn-0100-shape-flow`

通用交互规则（一次最多问 3 个问题、每步结束必须停、先给判断再解释、不辩解）见 `bn-tools-content-context`。

## 动作顺序

先问后判。答案摆出来之前不谈方向，更不谈反常识。

1. **接住**：用户抛来的往往只是一个词或一句话，先确认它指向哪件事，别急着展开。
2. **提问**：问这件事最基本的问题——它是什么？为什么现在值得关注？谁在参与、各自图什么？历史上发生过几次、结果怎样？问题要问到答案能浮出来为止。
3. **回答**：该查的查，一手源优先，答不上来的标"待核"。答不上来的问题本身就是选题风险，不是待会儿再补的细节。
4. **从答案里挖方向**：把答案摊开，看哪几个切口能撑起一篇。列 3-5 个候选，每个一句话。这时才用得上反常识做筛选——跟多数人已有认知完全重合的候选先砍掉。
5. **排雷**：命中任一条直说——看标题就能猜到全文结构、换数字换马甲的通用模板、名人语录汇编、指向具体标的。别指望靠文风救选题。
6. **收敛本质**：选定方向后，一句话说清这件事到底是什么。术语清零，念出来外行能懂。

反常识是**筛选候选方向的判据**，不是第一步的独立动作。没提问就先找反常识，等于还没弄懂就在挑角度。

## 讨论里的规矩

- **对话优先**：这一步的东西默认留在对话里，用户说"写入 / 落库 / 存下来"才落盘。讨论阶段改主意不需要回滚文件。
- 用户抛想法时先判断再反问；反问是补信息，不是把判断推回给用户。
- 事实先标"待核"，不核实就当结论用是虚空索敌；传闻类前提如果要写进正文，必须在开头声明，不能讲完一通才补一句"不过这是传闻"。
- 用户纠正时先改，改完再判断是不是规则盲区。

## 走偏信号

命中任一项，先回到提问：

- 开场就谈"怎么写更有冲击力""用什么案例砸"
- 问题还没答上来，就在列方向、排结构、挑标题
- 直接抛反常识点当开场，跳过了"它是什么""为什么现在值得关注"

## 交接

把三样东西交给 `bn-0100-shape-flow`：

1. 一句话本质
2. 反常识点
3. 事实风险（哪些还没核实、哪些是传闻）

不交接素材清单，不交接结构，不交接写法。

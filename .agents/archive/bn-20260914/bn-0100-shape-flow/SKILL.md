# 梳理（01 阶段）

## 这一步解决什么

素材和主题是两回事。这一步把散的东西收成一个能讲清的形状——先读厚，再读薄。

| | |
|---|---|
| 用户在这一步说什么 | "然后呢"、"这题怎么展开"、"先定一下要讲什么" |
| agent 做什么 | 读厚 → 定主题句 → 列小点 → 绑依据 → 逆推删减 |
| 产物 | 主题句一句 + 小点 3-5 条（每条标事实 / 判断，各自带依据） |
| 停下等什么 | 用户确认「就是这个主题，就这几个点」 |

下游：`bn-0200-express-flow`

## 读厚

往里装，装到能回答"别人会怎么反驳我"：

- 一手源：原始报道、公告、财报、论文。二手汇总里的数字必须回到一手源核过才用；核不到就标待核，不用。
- 反方意见：这题最有力的反对是什么。
- 历史同类：以前有没有发生过、结果怎样。
- 知识库：现有条目里能直接用的部分。

读厚不是要写进文件，是要过一遍。没过这一遍，读薄就是拍脑袋。

## 读薄

1. **主题句**：这篇只回答哪一个问题。一句话，能念出来。回答两个问题的文章，两个都没答好。
2. **小点清单**：读者合上手机带走 3-5 条。每条一句话，标「事实」还是「判断」。
3. **绑依据**：每条点标上凭什么——哪条事实、哪个数字、哪次经历。标不上依据的点，是还没想清楚，不是排版问题。
4. **逆推删减**：删掉任一条小点，主题句还站得住吗？站得住就删。

## 以终为始

先想"读者读完记住什么"，再倒推"该放什么"。
反过来做——先攒素材再想主题——出来的都是资料汇编，不是文章。

## 走偏信号

- 小点之间只是并列，没有推进关系（说明主题句太宽，装什么都行）
- 某条小点跟主题句没关系，但"这个数据挺有意思舍不得删"
- 依据栏里全是"待核"（说明读厚没做完）

## 交接

主题句 + 小点清单（含各自依据）交给 `bn-0200-express-flow`。
顺序可以标建议，但不是最终讲法——那是下一阶段的事。

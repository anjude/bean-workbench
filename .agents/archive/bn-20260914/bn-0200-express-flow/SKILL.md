# 表达（02 阶段）

## 这一步解决什么

内容和讲法是两件事。小点全对，读者还是可能读不下去——因为那是按"我知道什么"排的，不是按"你怎么听懂"排的。

| | |
|---|---|
| 用户在这一步说什么 | "写吧"、"成稿"、"这段换个说法" |
| agent 做什么 | 定入口 / 定顺序 / 定落点 / 定收尾 → 一次成稿 → 念一遍体检 |
| 产物 | 正文（`03_正文.md` 或 `04_发布稿.md`，按平台） |
| 停下等什么 | 用户反馈；归层见 `bn-0301-review-flow` |

## 动笔前先定四件事

1. **入口**：从读者已经知道或刚看到的那个东西开口。不从定义开口，不从背景开口。
2. **顺序**：小点怎么排，读者能自己走过去。排完念一遍，出现"还有一个""最后再看"就是断了，补桥或删。
3. **落点**：抽象机制必须落到一个具体数字、动作或场景。落不下去的，是自己也没真懂，回去补。
4. **收尾**：讲完就停。不升华，不号召，不给读者打气。

## 成稿

- 一次写完，不一段段对。边写边改出来的东西前后气口不一致。
- 写完念一遍，两条自检：像不像人说话；有没有在念提纲——把小点逐个翻译成段落，就是念提纲，读者读出来是"在给我念要点"。
- 交付时主动点出拿不准的两三处，不甩一篇全文让用户自己找。

## 表达红线

`references/表达红线.md` 是纠错清单，不是写作模板。按清单写出来的东西没人味——它的用法是写完对照排查，不是动笔前照着填。用户实践中迭代。

参考锚点（风格，不是模板）：`business-repo/beannote/topics/2026-09-12_智谱融资条款拆解/03_正文.md`。看它怎么从读者刚看到的那个数字开口、怎么把抽象条款落到一个具体价格上、怎么收尾。

## 走偏信号

- 开头在交代背景、下定义、铺垫重要性
- 段落之间靠"此外""另一方面"接
- 结尾在总结全文、呼吁行动、升华价值

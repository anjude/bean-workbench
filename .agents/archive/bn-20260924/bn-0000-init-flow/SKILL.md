# 选题初始化（00 阶段）

## 这一步解决什么

开题时把舞台一次搭齐。之后各阶段只往里填内容，不再操心文件叫什么、放哪。

| | |
|---|---|
| 输入 | 主题名 |
| 输出 | 一个选题目录 + 五个槽位文件 + `process/` + `source/` + `manifest.json` |
| 停下等什么 | 建完报路径，不问别的 |

## 触发

用户开新选题（"开个 topic""起个主题"之类）并给出主题名。主题名没给就问一句，问完直接建，不再确认。

## 做什么

1. 建目录：`business-repo/beannote/topics/{YYYY-MM-DD}_{主题}/`，含空的 `source/` 和 `process/`
2. 建五个槽位文件，`md`，各写一行 H1 `{槽位名} - {主题}`：

   | 文件 | 用途 |
   |---|---|
   | `01-1-问答录-{主题}.md` | 讨论的结论：问了什么、答了什么、哪些没答上来。只留结论，不放原文 |
   | `01-2-素材-{主题}.md` | 选题素材：有意思的知识点、故事、数字，带出处和可用在哪 |
   | `01-3-大纲-{主题}.md` | 用途待定，用户没说之前不填 |
   | `02-1-公众号-{主题}.md` | 公众号正文 |
   | `02-2-小红书-{主题}.md` | 小红书正文 |

   编号规则：`{阶段号}-{阶段内序号}-{槽位名}-{主题}`。阶段号固定两位，不动；同阶段多个文件靠中间那一位序号排，**序号即流程顺序**，新增文件插在中间时要重排序号并同步已建 topic 的文件名。

   `source/` 放原始素材：查到的原文摘录、数据表格、网络内容快照。命名 `{序号}-{来源}-{内容}.md`，文件头写来源 URL、数据口径、抓取时间。**槽位文件只放结论，`source/` 放原始件**——这样问答录不膨胀，事实也能追溯。

3. 写 `manifest.json`

## process/ 的分工

一个阶段走过的过程留 `process/{阶段号}-{环节名}.md`，和槽位文件并列但各管一头：

| | 槽位文件（`01-1-问答录` 等） | `process/` |
|---|---|---|
| 怎么组织 | 横向，按题号 / 平台 | 纵向，按阶段和时间 |
| 会不会被改 | 会，结论被刷新就覆盖 | 不会，只增不改 |
| 里面躺着什么 | 定下来的结论 | 当时怎么想的、走了什么弯路、哪条判断后来被推翻 |

理由：结论会被反复改写，改完就看不到当初为什么那么定了。`process/` 留那条被推翻的路径。

| 目录 | 放什么 |
|---|---|
| `source/` | 第三方原文、数据表、网页快照 |
| `process/` | 自己的思考轨迹 |
| 槽位文件 | 当下这一版的结论 |

## manifest.json

```json
{
  "topic": "黄金",
  "status": "draft",
  "created": "2026-09-14",
  "slots": ["01-1-问答录", "01-2-素材", "01-3-大纲", "02-1-公众号", "02-2-小红书"]
}
```

| 字段 | 含义 |
|---|---|
| `topic` | 主题名，建题后不改 |
| `status` | `draft` / `published` / `archived` |
| `created` | 建题日期 |
| `slots` | 已建的槽位 |

## 规矩

- 只建骨架：目录、槽位文件的 H1、`manifest.json`。
- 只建用户要的文件。
- 目录建好就停，把路径报给用户。
- **本 skill 是目录骨架的唯一定义处。** 新增槽位、改命名、调整结构，一律先改这里再动手，顺带更新已建 topic 的 `manifest.json` 的 `slots`。

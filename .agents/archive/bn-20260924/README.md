# bn skill 族群归档（2026-09-24，第二代）

## 为什么归档

第一代（`bn-20260914/`）太重：8 个 skill、一堆模板，写得太细，跑起来像在填表。9 月中旬推翻重建，只留骨架，靠「黄金」这个主题一个阶段一个阶段地试，试出来什么写什么。

试到 9 月 24 日，第二代也停了。原因：

1. **skill 一写就机械。** 9 月 23 日把一次顺手的动作（阶段总结汇总回槽位文件）固化成五条规范，豆哥："太机械了。" 删了。同样的坑 9 月 19 日犯过一次——替他给问题分类、给答案排优先级、替大纲定结构、替他挑反转。共同点是 agent 忍不住做取舍。
2. **边界还是没守住。** 9 月 21 日写的"选题目录不建 process/，槽位文件够了"是替他排除，9 月 23 日被纠正：process 每个 topic 都要有。
3. **内容线不是流水线这件事，用 skill 框不住。** 每步要停下等一句话、质量判定权在用户手上，写进 skill 就变成流程，一变成流程就开始替他决策。

所以第二代也归档。现在 `.agents/skills/` 下没有 bn 了。

## 第二代留下的东西

这几条是在第二代里试出来的，不管下一代怎么建都成立：

- **三层分工**：`source/` 放第三方原文，`process/` 放自己的思考轨迹（纵向按阶段、只增不改、留被推翻的判断），槽位文件放当下这版结论（横向按题号、会被覆盖）。
- **process 是 topic 维度的**，工作台 task 目录和选题目录两边都建。
- **`bn-0000-init-flow` 是目录骨架的唯一定义处**，改槽位先改它。
- **规则用正面表述**（要做什么，不是不要做什么）；走偏信号写成"在做的事 / 回到哪"对照表。
- **写进 skill 的门槛是"不写就会反复做错"**，不是"这次做对了值得记"。手感的事留在手上。
- agent 的边界：**查到什么记什么，不排序、不推荐、不评价**。归类、筛选、选方向、评价哪个有意思，都是用户的事。

# 软件产品视频制作

工具 skill，不占 dev-flow 阶段号。视频需求可以出现在方案、发布或运营阶段；先用 `wb-router` 定位业务仓与已有任务目录，再按本 skill 制作。原始制作能力来自工作台保存的[上游视频 skill](../../vendor/product-video/SKILL.md)，当前版本和许可见[第三方来源说明](../../vendor/README.md)。实际制作时读取上游 `SKILL.md`，再按需读取它的 `references/`；不要把所有参考资料一次性加载。

## 在工作台中的用法

1. **定内容范围。** 从用户已有要求确定产品、要讲的功能或版本、观众、渠道、时长和画幅。缺少会改变影片主张的信息时再问。普通样片可从已实现的一个功能入手，明确它只是样片。
2. **核对产品事实。** 阅读目标仓 `AGENTS.md`、相关页面、组件、样式、资产与版本记录。每个功能主张都能回指源码或发布说明；演示数据可以固定，但不能把未实现的功能拍成已可用。
3. **定方向与交付目录。** 优先沿用产品自己的设计语言，视频工程放在既有任务目录或明确指定的独立目录，保留分镜、来源、渲染代码、声音和成片。视频工程不得为接入方便改动产品代码；业务仓改动仍按 dev-flow 方案门禁走。
4. **制作与审片。** 按上游流程接通组件、逐镜头渲染、配乐音效、检查关键帧与完整成片。环境依赖先检查再补装，避免无谓的全局安装。交付 MP4、可复现工程，并说明哪些画面和声音实际审过。

## 框架适配

- Web / React 组件可优先使用上游起步工程的直接接入方式。
- Vue、uni-app、微信小程序等无法直接挂载到其 React 浏览器管线时，先评估能否用现有页面的 Web 构建或真实录屏；需要还原展示层时，逐项对照源码和端上状态，记录哪些是重建画面，不把它称为原组件实拍。
- 不要把上游 CodePilot 默认视觉套到已有品牌产品上。若确需使用默认或混合样式，先查对应 BSL 文件与素材来源；品牌 Logo、字体、音乐、音效分别核对来源和许可。

## 来源与维护

- 上游源码保存在 `.agents/vendor/product-video/`，由工作台 Git 固定版本；不直接在 `~/.agents/skills/` 克隆上游仓库。
- 上游更新时先比对版本、许可与本地适配，再整体更新 vendor 快照及[来源说明](../../vendor/README.md)。本入口保持中性命名；不要把上游目录的 `name` 当作工作台 skill 名。
- `task/dev-flow/261015_gknow-product-video/promo-sample/` 是首个样片案例：微信小程序界面按源码还原，适合参考边界说明，不作为所有产品的模板。

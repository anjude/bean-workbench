# 总体大纲模板（选题 + 讨论合一，落笔前的生产闸门）

一份文档三段：先主题分析（确认想表达什么），再立选题，最后压实讨论结论。字段顺序固定，方便一眼判断走没走偏。不要在字段间加解释段落。**主题分析未确认前不许展开写法**；**骨架**字段每节须同时带「写法方向」，写法服务于主判断，不倒推主题。

```markdown
# 大纲｜<选题名>

## 主题分析（讨论第一步，先于写法）
**拆题**：（这个主题由哪几层构成，分别是什么）
**最容易写歪成**：（跑偏清单，2-4 条：如语录汇编 / 只讲定义的概念科普 / 过度否定变成劝短线 / 荐标的）
**想表达什么（主判断，一句）**：（这篇要让读者看到什么；是「看到」不是「改变看法」，不强行灌输，这句未立住不许谈写法）
**脉络（推导链）**：（主判断凭什么被接受——读者被一步步带到哪。写法见下方「脉络怎么写」）

## 选题判断
**写给谁**：（一句话，别写"所有人"）
**一句话结论（中性）**：（选题阶段中性；态度版最狠句留到下方结论）
**核心问题**：
- 
**标题草案**：
1. 
2. 
3. 
> 备选：

## 核心内容摘要（生产闸门）
**定位**：写给谁（与上方选题判断一致，一句话）
**结论**：强判断 = 本文最狠那句、有态度；事实流 = 事实陈述 / 核心机制
**反差**：最反直觉的一点（事实流可弱化为"事实本身的张力"）
**骨架**：
1. <小节主题> — 事实：…；写法：用哪个例子 / 手法 / 避什么坑
2. …
3. …
**锚点**：用哪些熟悉标的替代抽象（茅台 / 腾讯 / 英伟达 …）
**边界**：不点名 / 只机制观察 / 留免责声明
**核实**：发布前必须查的最新事实（数据 / 案例）与版本标注

> 模式说明：默认强判断模式（结论须最狠、有态度）。若选题走「事实流模式」（用户要求少判断、给事实、让时间证明），结论字段改为「事实陈述 / 核心机制」；「结论含糊没态度」「骨架只是资料罗列」两项降级为可选，其余走偏信号仍生效。模式确认后写进该篇 `manifest.yaml` 的 `mode` 字段。

**走偏信号**（命中任一项先改大纲再确认）
- 强判断模式专属：结论含糊、和稀泥、没态度（如「值得关注」「未来可期」）
- 反差缺失或落入俗套（如「到了年纪要注意这些坑」三段式）
- 强判断模式专属：骨架只是资料罗列、没有判断维度
- 边界写不清（点名具体公司 / 没提免责声明）
```

## 脉络怎么写（大纲里最容易被跳过、也最不能跳过的一段）

**骨架写的是"每节讲什么"，脉络写的是"读者怎么被带过去"。** 骨架对了文章可能仍是并列的几块；脉络对了，读者才会觉得"这篇文章是有内在逻辑的"。

格式：编号 6-8 步，每步一行，写三件事（压缩成一句）：

1. **读者此刻在哪**（他手里已有的认知 / 已经发生的现象 / 上一步刚给出的结论）
2. **这一步抛出或解决什么疑问**（必须是上一步自然长出来的问号，不是另起一头）
3. **推出什么，交棒给下一步**

写法要求：

- **单向推进**：每一步只能从上一步的答案里长出来（因果 / 递进 / 检验 / 反过来问）。并列堆砌不算脉络。
- **不许序号式衔接**："还有一个问题""最后一个""再看一个"说明两步之间没有推导关系，要么补上桥，要么删掉其中一步。
- **写出读者状态**：脉络是读者视角，不是素材清单。每步开头应是"读者此刻手里有什么／已经看到什么"，不是"介绍 X 概念"。
- **现象不许写成"读者以为"**：起点是已发生的现象就写现象（"多数人进场时的打算是捞一笔就走"），不写成"读者以为自己会捞一笔就走"。后者把事实降级成认知偏差，还替读者下了定义——"读者此刻在哪"指的是他手里已有的信息和已经发生的现象，不是他哪里想错了。
- **一步 ≈ 一节**：脉络的步数与骨架节数应对得上，对不上说明有一节是塞进去的，或有一跳没接住。

自检（写完必做）：

- 抽掉中间任一步，后一步会不会悬空？会悬空说明链是假的，只是排了个顺序。
- 顺着只读脉络，能不能不靠正文也把主判断推出来？不能，说明中间缺环。
- 有没有哪一步其实是在重复上一步（换个说法再说一遍）？有就合并。

## 固定检查顺序

主题没拆开、主判断没立住 → 先回到主题分析，不许谈写法。**脉络接不上 → 先修脉络，不许动骨架顺序蒙混。** 其后：定位错、结论飘、反差无、骨架散、边界糊，任一项不对就是走偏，先改大纲再确认。

# 审稿（02 阶段）

## 这一步在做什么

| | |
|---|---|
| 用户在这一步说什么 | "这段太 AI"、"这里不够狠"、"结尾收不住"、"可以发" |
| agent 做什么 | 先改不辩解、判一次性还是规则盲区、沉淀规则、跑检查清单逐项附证据、每轮只收敛一个量级的问题 |
| 产物 | `05_检查清单.md` + `manifest.yaml` 槽位更新 |
| 停下等什么 | 用户说"可以发" |

上游交接物：`bn-0101-draft-flow` 的成稿

**改稿默认不落盘**（见 `bn-tools-content-context` 通用交互规则第 8 条）：反馈轮次先在对话里给，用户明确说「写入 / 保存」才改文件。
**只给全文，不给片段**（同规则第 9 条）：对话里贴出的一律是完整正文（标题到免责声明，含配套块），禁止只给改动片段、diff 或"改法＋改后段落"；"相对上一版的变化"放在全文之后做附注。
下游指向：`bn-0301-publish-flow`

通用交互规则（一次最多问 3 个问题、每步结束必须停、先给判断再解释、不辩解）见 `bn-tools-content-context`。

## 发布检查

生成 `05_检查清单.md`，必须包含：

- 合规红线
- 文风检查
- 受众检查（以人为本：易接受、有收获感，禁止强行灌输，见 `references/正文质检清单.md`「受众检查」段）
- 信息密度检查（自述/观察/判断篇幅比例、每段是否有新增信息量）
- 是否有 AI 味表达
- 标题、封面、事实源发布前确认项

---

## 合规红线

投资理财内容，只守以下硬红线：

- 不承诺保本保收益、不写"稳赚""保本""无风险"
- 不直接喊人买/卖具体标的（"买入X""上车X""赶紧卖Y"）
- 不诱导开户或交易
- 必须保留免责声明：

```text
内容仅供参考，不构成投资建议。投资有风险，决策需谨慎。
```

红线以外的都可以写：

- 可以聊具体公司、具体产品，给出自己的观察和判断
- 可以提历史收益率、回撤数据，作为事实引用
- 可以讨论名人动作和逻辑，只是不能写成"跟着他买"
- 可以说"我觉得有意思""值得关注""我在关注"，这是观点不是指令
- 可以分析投资框架、商业模式、风险收益比

判断标准：**读者看完之后，是多了理解，还是多了冲动？** 多了理解就写，多了冲动就改。

## 交付前硬检查

每次交付前必须检查：

### 操作真实性检查

- [ ] 已实际读取 `business-repo/beannote/docs/content-playbook.md`
- [ ] 已实际读取 `references/创作准则.md`
- [ ] 已实际读取 `references/正文质检清单.md`
- [ ] `05_检查清单.md` 不是空模板，含具体检查证据
- [ ] 最终回复只描述已经真实完成的动作，不把计划说成结果

### 文件检查

- [ ] 目录是否是 `{状态前缀}YYYY-MM-DD_主题简述`，且在正确的月份层级
- [ ] 公众号是否有 `01`（大纲）、`04`（含大纲选题段 + 正文）、`05`（`06` 仅在有反馈/沉淀时生成）
- [ ] 小红书图文是否有 `01`、`02`、`03`、`05`（`06` 同上）
- [ ] `manifest.yaml` 的 `slots` / `next` 是否与实际文件一致，索引是否已重跑
- [ ] 额外脚本、跨平台正文是否只在需要时生成

### 正文检查

- [ ] 正文无第二人称"你"（互动问题可例外）
- [ ] 无中文破折号、英文 em dash
- [ ] 无角引号
- [ ] 无滥用引号包裹关键词
- [ ] 无保本保收益承诺、"稳赚""无风险"等绝对表述
- [ ] 已保留免责声明
- [ ] 每一段都有新增信息量
- [ ] 没有强行升华
- [ ] 没有主持人口吻强行转场
- [ ] 没有复述前文判断当结尾
- [ ] 粗体 3-5 处，不泛滥
- [ ] 正文末尾附有精彩引言和封面 prompt

### 反馈后处理

用户指出问题时：

1. 先改当前稿，不辩解
2. 判断是一次性问题还是规则盲区
3. 规则盲区要同步更新：
   - 当前主题 `06_复盘.md`
   - `business-repo/beannote/docs/content-playbook.md`
   - 本 skill 或 `references/` 中对应规则
4. 更新后再次检查当前稿，确认同类问题已清掉
5. 最终回复要明确说明：改了当前稿；如有规则沉淀，说明沉淀到了哪个文件

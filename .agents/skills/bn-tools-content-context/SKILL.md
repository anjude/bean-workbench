# beannote 项目上下文

操作 beannote 任何内容前先读本文件。目录、命名、状态、规则该落哪，都以这里为准。

---

## 顶层结构

仓库根 `business-repo/beannote/`：

| 目录 | 用途 |
|---|---|
| `topics/` | 唯一生产区。一篇选题一个目录，从选题到复盘都在里面 |
| `knowledge-base/` | 跨选题素材，长期可复用的理财知识 |
| `data/` | 发布记录总表、高频问题记录 |
| `docs/` | 项目说明、账号定位、内容手册 |

状态不再用目录层级表达。一篇选题的路径建立后不再变化。

## 选题目录

路径：`topics/[YYYY-MM/]{状态前缀}{日期}_{主题}/`

- 日期：选题记录日，不是发布日
- 主题：中文简述
- 状态前缀：无（在制）／`done-`（已发布）／`drop-`（已归档，不进数据统计）

## 月份归档

月份目录按月归档，让 `topics/` 根只留当前月在做的东西。

| 情况 | 落在哪 |
|---|---|
| 选题记录日属于当前月 | `topics/` 根，不加月份目录 |
| 选题记录日属于往月 | `topics/YYYY-MM/` |
| 跨月后仍未收尾的旧选题 | 下月首次开题时整体搬进对应 `YYYY-MM/` |

规则：

1. 月份按**选题记录日**算，不按发布日、不按最后修改时间。
2. **当前月新开题直接建在根**。只有跨月之后才搬，不预判。
3. 归档只换所在目录，**不改目录名**，状态前缀照旧。
4. 一篇目录建立后，路径在其生命周期里只变两次：跨月归档、发布/废弃改名。
5. 触发归档时顺手更新 `topics/索引.md` 的目录列（要带 `YYYY-MM/`）。

示例：

```text
topics/2026-09-08_价值投资和长期投资的关系/          # 当前月，在根
topics/2026-05/done-2026-05-10_段永平泡泡玛特恋爱梗/  # 往月，已发布
topics/2026-05/drop-2026-05-07_预测涨跌的时间才是最大亏损/
```

## 槽内文件

| 槽位 | 文件 | 内容 |
|---|---|---|
| 01 | `01_大纲.md` | 主题分析（含脉络）+ 选题判断 + 核心内容摘要（七字段）+ 写法方向，落笔前生产闸门 |
| 02 | `02_脚本.md` | 读者推进节奏、图文分页结构 |
| 03 | `03_正文.md` | 跨平台纯享长文 |
| 04 | `04_发布稿.md` | 公众号终版 |
| 05 | `05_检查清单.md` | 发布前自检，逐项附证据 |
| 06 | `06_复盘.md` | 读者收获感评估、原因分析、规则沉淀（发布数据只记录不评分） |

配图、封面放该篇的 `assets/`，不建全局素材库。

数字前缀即流程顺序：缺哪号就是卡在哪步，不需要额外记录进度。

**槽内文件只装内容，不装状态。** 状态、结论、卡点一律写 `manifest.yaml`。

## manifest

每篇一个 `manifest.yaml`，是这篇的唯一状态源。模板见 `references/manifest模板.yaml`。

| 字段 | 含义 | 谁改 |
|---|---|---|
| `topic` | 主题中文简述 | 开题时定，之后不改 |
| `status` | 在制 / 已发布 / 已归档 | 发布时改「已发布」，废弃时改「已归档」 |
| `platform` | 公众号 / 小红书 / 跨平台 | 开题时定，可改 |
| `form` | 文章 / 图文 / 视频 | 同上 |
| `mode` | 强判断 / 事实流 | 大纲确认核心内容时定，决定结论要不要有态度 |
| `delivery_mode` | 落盘 / 正文。**由用户切换**，agent 不擅自改 | 见下方「交付模式」 |
| `created` | 选题记录日 | 不改 |
| `published` | 发布日，未发为 `null` | 发布时填 |
| `slots` | 已有槽位编号数组 | 每次落文件更新 |
| `next` | 下一步动作，一句话 | 每步结束更新 |
| `conclusion` | 本篇最狠那句主张 | 开题填中性版，大纲确认后换态度版 |
| `decisions` | 时间 + 定了什么，被否掉的切口也记 | 有决策就追加 |
| `blockers` | 卡点 | 出现就写，解决就删 |
| `metrics` | 曝光/点赞/收藏/评论/涨粉 | 发布后填，分析留在 `06_复盘.md` |
| `links` | 知识库条目、事实源、参考篇目 | 随时补 |

维护规则：

1. **manifest 是权威，`topics/索引.md` 由它派生。** 不要两处各写一半，改完 manifest 重跑索引。
2. **`status` 与目录名前缀必须一致**：无前缀↔在制、`done-`↔已发布、`drop-`↔已归档。不一致就是漏改。
3. **抽不出来的字段留 `null` / `[]`，不臆造。** 尤其是 `published` 和 `metrics`。
4. **只记判断，不复制正文。** 结论和决策是给下一轮续写的指针，细节留在槽位文件。
5. **被否掉的切口必须进 `decisions`。** 内容创作最容易重复踩的就是忘了自己放弃过什么。
6. **改名或归档不动 manifest 内容**，只核对 `status` 是否还匹配新目录名。

## 交付模式（`delivery_mode`）

正文类改动怎么交付，由用户定，agent 不擅自切换。切换后写回本篇 `manifest.yaml` 的 `delivery_mode`。

| 值 | 行为 |
|---|---|
| `落盘` | 改完直接写文件（默认）。改动生效即落盘，用户看文件。 |
| `正文` | **不写文件**，每轮把完整正文贴在对话里（见通用交互规则第 9 条），等用户明确说"写入"才落盘。 |

用户切换的措辞：

- 切 `正文`：先给我看 / 在对话里贴 / 先不落库 / 别写文件 / 我要在对话里看
- 切 `落盘`：写入 / 保存 / 落库 / 改上去 / 直接写

拿不准时按当前 `delivery_mode` 走，并在回复末尾注明当前是哪一种。

## 最小充分原则

需要什么生成什么，不为空流程造空文件。

| 平台 | 默认槽位 |
|---|---|
| 公众号 | 01、04、05（06 有反馈或沉淀才写） |
| 小红书图文 | 01、02、03、05（06 同上） |
| 跨平台 | 在公众号基础上加 03 |

图文页数按内容自然决定，不强行凑页数。

## 索引

`topics/索引.md` 是全局看板，按状态分组列出全部选题：日期、主题、平台、已完成槽位、下一步、目录。

它由各篇 `manifest.yaml` 派生，**不手改**。改了 manifest 就重跑 `business-repo/beannote/script/gen_index.py`；脚本会顺带校验 `status` 与目录前缀是否一致。

目录列写相对 `topics/` 的路径，往月的带 `YYYY-MM/`，例如 `2026-05/done-2026-05-10_段永平泡泡玛特恋爱梗/`。

进入项目先读索引看全局，进单篇先读 `manifest.yaml` 看状态，不靠翻目录猜。

## 通用交互规则

内容创作里质量判定权在用户手上，agent 无法自己判定好坏。所有阶段遵守：

1. **一次最多问 3 个问题**。内容创作不是填表，问完就该给判断，不发问卷。
2. **每步结束必须停**。默认逐回合推进，用户没接话就等着，不自动往下跑。
3. **全自动模式**：用户说「直接做」「一路写完」时一次走到审稿结束，但发布仍需显式确认。
4. **先给判断再解释**。用户抛想法时，先说"这题能写 / 不能写，理由"，再展开。
5. **不辩解**。用户说某段不行，先改；改完再判断是否规则盲区。
6. **摊稿时点出拿不准处**。成稿交付要主动说"这两处我不确定，你先看这两处"，不甩一篇全文。
7. **每轮只收敛一个量级的问题**。审稿不一次改十处让用户重看全文。
8. **改稿默认不落盘，先给用户看**。「看稿」「先不落库」「这样改行不行」类回合，以及任何改动方案，一律先在对话里给，用户明确说「写入 / 保存 / 落库 / 改上去」才动文件。改稿阶段唯一例外是**阶段产物的首次生成**（如 `04_发布稿.md` 初次成稿），那属于交付，不算改稿落盘。
9. **正文只有两种形态：对话里贴完整全文，或全文落库。不存在"只给一部分"**。凡涉及正文的回合（成稿、看稿、改稿、改后确认），交付物必须是**从标题到免责声明的完整全文**，含精彩引言、封面 prompt、留言引导等配套块。
   禁止：只给改动片段 / 只给 diff / 只写"改法说明＋改后段落" / 用"其余不变"代替原文 / 只丢一个文件路径。用户读不到全貌，判断不了改动跟整体协不协调。
   执行：
   - 未落盘的每一轮改稿，重贴整篇正文，不贴"改了哪几处"。
   - "相对上一版的变化"放在**全文之后**做附注，不能放在全文之前替代全文。
   - 用户说"贴一遍""把全文给我"时，直接贴全文，不复述改动清单。
   - 局部推演（主题分析、大纲某一节的几种写法）不受此限，那时还没有正文。

## 废弃处理

选题废掉或热点过期：目录名加 `drop-`，同步 `topics/索引.md`。不删文件，不进数据统计。每 3 个月可清理一次。

## 归档时机自查

每次进入 topics 操作前扫一眼根目录：有不属于当前月的目录，先搬进 `YYYY-MM/` 再干活。这一步不做，根目录会越堆越乱。

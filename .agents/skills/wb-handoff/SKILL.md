# 任务交接与过程记录

两个目录，两层记录，互不替代：

| | `handoff/` | `process/` |
| --- | --- | --- |
| 回答的问题 | 下一步干什么 | 这一步发生了什么 |
| 读者 | 下一个会话的 agent，拿来就能开工 | 事后回溯的人，想知道怎么走到这一步 |
| 粒度 | 高层，一屏读完 | 细节，可以长 |
| 时间维度 | 横切面，每份是此刻全貌 | 纵切面，逐阶段累积 |
| 更新方式 | 每次交接一份时间戳文件，最后一份即最新 | 一个阶段一份，同一阶段多轮就追加，不新建 |

一句话记法：**handoff 是「我从哪接着干」，process 是「这件事是怎么被想清楚的」。**

## 一、定位任务目录

1. 读 `task/registry.md`，从热任务里找目标任务目录；命中不了再扫 `task/` 下的 `YYMMDD_*`。
2. 没有对应目录就新建 `task/YYMMDD_{主题}/`，README 用 `wb-router` 的 `references/task-readme.md`，并顺手登记进 `task/registry.md` 热任务。
3. 目录里必须有 `handoff/` 和 `process/`：没有就建；已有就直接写。

> `process/` 在两个地方出现：工作台任务目录（`task/YYMMDD_{主题}/`）和 beannote 选题目录（`business-repo/beannote/topics/{topic}/`）。命名和写法一致，差别只在"阶段号"跟着谁的流水线。选题目录那边的 process/ 由 `bn-0000-init-flow` 建，内容依据 `bn-0100-discuss-flow`。

## 二、process：每个阶段一份过程结论

一个阶段做完、或这一步要停下换方向，就把这个阶段的经过落成 `process/{阶段号}-{环节名}.md`。

**命名规则：**

- 阶段号两位，跟随所用流水线的阶段号：`process/00-方案设计.md`、`process/01-后端开发.md`、内容线 `process/01-讨论.md`。
- 任务不跑流水线，用两位流水序号：`process/01-{环节名}.md`、`process/02-{环节名}.md`。
- 同一阶段改了几轮，追加到同一份文件里，用 `## {日期} 第 N 轮` 分次，不新建文件。

**写什么：**

- 这一步做了什么，按动作顺序记
- 得出什么结论，每条带出处或产物路径
- 哪些判断被推翻了——当时为什么那么想，后来被什么数据或事实打掉
- 没答上来、还没核的，单列出来
- 引用 `source/`、方案文档、commit，指向即可

**红线：**

- 不复述产物内容，一律路径引用。
- 不写下一步计划，那是 handoff 的事。两份重复就会出现两份都不准。
- 不写密钥、口令、token、个人隐私信息。

## 三、handoff：什么时候写

| 情况 | 动作 |
| --- | --- |
| 用户明确说 handoff / 交接 / 收工 / 记进度 | 写 |
| 一个阶段做完、要停下等用户确认 | 写，同时在 `process/` 补该阶段的过程结论 |
| 会话上下文快满、或任务要中断 | 写 |
| 同一次会话内又触发、但没有实质新进展 | 更新已有的那份，不新建 |
| 纯闲聊、没有任务上下文 | 不写，先问清归属哪个任务 |

## 四、handoff 文件命名

`handoff/YYMMDD-HHMM_{slug}.md`，时间取当前本地时间，slug 是一句话概括（中文即可）。按文件名排序，最后一份就是最新状态。

## 五、handoff 写什么

按 `references/handoff-template.md` 的骨架填，八段缺哪段就写「无」，不要留空标题充数。

硬规则：

- **不复制已有产物的内容。** 方案、文档、diff、commit、清单、过程结论，一律写路径或 URL 引用。handoff 是索引，不是快照。
- **过程结论指向 process。** 「某阶段做了什么」在 handoff 里写一句带路径的引用，正文留在 `process/{文件名}`。
- **下一步要可执行。** 每条写清「做什么 + 在哪 + 怎么算做完」，不写「继续推进」「完善一下」这种。
- **决策要带原因。** 只写结论等于没写；被否掉的方案要记，否则下一轮会再试一遍。
- **脱敏。** 密钥、口令、token、个人隐私信息不进文档，写「见环境变量 X」。
- **建议调用的 skill 要具体。** 直接点名 skill 编号，让下一个 agent 进来就能调。

## 六、接手侧怎么用

下一个会话进来：先走 `wb-router` 建上下文 → 读任务 `README.md` → 读 `handoff/` 里**最后一份** → 按「未完成 / 下一步」开工。要问「这是怎么定的」才去翻 `process/`。读完先跟用户对一句确认方向，再动手。

## 七、配套 references

| 文件 | 用途 | 何时读 |
| --- | --- | --- |
| `references/handoff-template.md` | handoff 文档骨架与字段说明 | 每次写 handoff 前 |

## 八、process 文件骨架

```markdown
# {环节名} · 过程记录

- 任务目录：`task/YYMMDD_{主题}/`
- 阶段：{阶段号} {阶段名}
- 时间：YYYY-MM-DD

## 做了什么

- {动作} → 结果 / 产物路径

## 得到的结论

- {结论}：`出处或路径`

## 被推翻的判断

- {当时的判断} → 被 {数据/事实} 打掉：`出处`

## 待核 / 没答上来

- {问题}：卡在哪
```

## 输出要求

- 回报写入路径 + 一句话摘要（这次到哪了）。
- 写了 process 就顺带说一句阶段结论落在哪份文件。
- 新建了任务目录时，提示已登记 `task/registry.md`。
- 任务收口后，最后一份 handoff 就是归档，不要删；`handoff/` 和 `process/` 跟着任务目录整体走。

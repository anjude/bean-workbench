# 会话续接：自动与手动入口

## 触发条件

- 自动：当前会话第一次触发 `PreCompact` 时，后台从该会话第一轮结束位置分叉。手动、自动压缩均适用；钩子返回 `continue: true`，旧会话继续压缩、继续回答。
- 手动：用户明确说「切新会话」「换个新会话继续」或要求创建续接会话时，立即执行下方手动流程。
- 每个旧会话共用一份续接状态；自动与手动重复触发时复用已经创建的新会话，避免重复分叉。新会话以自己的 ID 独立计算触发状态。
- 首轮尚未结束时，后台只等待首轮结束；已有结束的首轮时立即分叉，不等旧会话当前轮结束。

## handoff 与注入内容

手动切换前先按当前任务实际进展更新 handoff；自动触发依赖任务已有的最新 handoff，旧会话仍应在阶段完成或上下文将满时按需维护。脚本不代写 handoff；写入或更新 handoff 时按模板记下来源会话 ID，便于仅凭旧 ID 定位任务。

新会话保留旧会话第一轮，追加消息只包含老会话 ID 和读取 handoff、按本规则接手的指令。近期用户请求、旧会话答复、进展摘要等不再拼入消息。工作目录作为分叉运行参数沿用，Git 分支沿用；旧会话保留。

## 新会话接手规则

收到「老会话 ID + 读取 handoff」的续接消息后：

1. 读取本规则；从运行环境 `CODEX_THREAD_ID` 确认自己的新会话 ID，必须与消息里的老 ID 不同。不要把旧会话 ID 当成置顶目标。
2. 使用应用工具 `move_thread_to_sidebar_section` 将**新会话**放入 `sectionId="pinned"`，再用 `list_threads` 核对它已在 `pinnedThreads`。工具不可用或失败时报告具体情况，不把创建成功当成置顶成功；不直接写桌面应用的内部数据。
3. 使用 `navigate_to_codex_page` 打开新会话。旧会话继续运行，不归档、不取消旧会话置顶、不停止旧轮。
4. 优先按老会话 ID 匹配 handoff 的「来源会话 ID」；旧记录没有该字段时结合首轮保留的任务线索与任务登记定位对应任务，读取 README 和 `handoff/` 最新一份；只有必要时再查其索引所指文件。无法确定任务或没有 handoff 时，说明缺少的文件或归属并等待，不自行补造旧进展。
5. 保留脚本已经设置的新会话名，不因自动任务绑定再次覆盖它。
6. 若任务正式记录已有用户对续接会话与特定定时任务迁移的明确授权，读取记录后核对原始字段与旧绑定，用应用自动化工具只迁移已授权、仍绑定老会话的 ID，并核验。已经绑定新会话则跳过；绑定第三个会话或更新失败时不覆盖、不宣布成功。不得直接写自动化配置文件，不迁移未授权任务。
7. 简短报告 handoff 读取、置顶和已授权迁移的实际结果，然后等待用户下一条输入。不要自行重做日报、交易或扩大任务。

## 手动切新会话

在旧会话中收到明确切换要求时：

1. 更新当前任务 handoff。
2. 执行 `python3 script/codex-hooks/continue-session.py --manual`；从工作台外调用时使用该脚本的绝对路径。默认从 `CODEX_THREAD_ID` 取旧会话 ID，也可显式使用 `--session-id`；工作目录默认当前目录，可用 `--cwd` 指定。
3. 若返回 `pending`，用 `--status` 查询相同旧 ID 的状态，给后台创建留出时间；首轮仍在运行时让当前轮正常结束，后台会继续处理。不要因暂时未返回 ID 而另行分叉。
4. 返回 `ready` 后使用 `forked_thread_id` 核对新会话已置顶，并打开它；新会话启动消息已由脚本发送，不重复发消息。尚未置顶时可直接调用上述应用工具完成置顶和核验。
5. 返回 `failed` 或 `needs_review` 时检查状态和已有子会话。特别是续接消息提交结果未知时，先读已有新会话核对，不直接重试 `turn/start`。

## 命名、状态与故障

- 命名沿用 `任务名-短阶段总结-02`；当前实现取旧会话标题和最近用户请求，各最多 24 个字符，仅用于命名，同前缀编号递增。
- 状态与日志位于 `~/.codex/state/session-continuation/`，按旧会话 ID 隔离；本机 hook 配置在 `~/.codex/hooks.json`，只注册 `PreCompact`。
- 连接优先使用已有共享 app-server；共享控制套接字不存在时，启动独立 stdio app-server，沿用本机配置和账户，待新会话接手轮结束后关闭，不安装或重启常驻服务。
- 后台失败不阻断旧会话。尚未创建子会话或仅改名失败时，下次触发可继续处理；消息提交结果未知则标记待核，避免重复注入。
- `script/codex-hooks/fork-before-third-compact.py` 仅为已加载旧路径的会话保留兼容入口，转调新脚本；不再执行第三次压缩阻断逻辑。
- 配置已写入不等于桌面端真实事件链路已验收；如应用要求重新审阅 hook，在 `/hooks` 中审阅并信任后才会执行。

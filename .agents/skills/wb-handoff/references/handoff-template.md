# handoff 文档模板

文件名：`handoff/YYMMDD-HHMM_{slug}.md`

```markdown
# {任务名} · 交接

- 任务目录：`task/YYMMDD_{主题}/`
- 时间：YYYY-MM-DD HH:MM
- 状态：进行中 / 待确认 / 已完成
- 上一份：`handoff/{上一份文件名}`（首份写「无」）

## 这次到哪了

一句话：目标是 X，现在做到了 Y。

## 已完成

- {做了什么} —— `路径`
- {做了什么} —— `路径`

## 未完成 / 下一步

1. {做什么}，在 `路径`，做完的判断标准：{标准}
2. {做什么}，在 `路径`，做完的判断标准：{标准}

## 关键决策与原因

- {决策}：因为 {原因}；否掉了 {备选}，因为 {原因}

## 卡点与待确认

- {阻塞点}：等 {谁} 拍板 / 需要 {什么}

## 环境与坑

- {命令 / 路径 / 权限 / 平台差异}：{坑与绕法}

## 关联产物

| 产物 | 路径 |
| --- | --- |
| 方案文档 | `task/YYMMDD_{主题}/README.md` |
| 改动 | {commit / diff / 分支} |

## 下次建议调用的 skill

- `wb-router`：建上下文、确认归属
- `{具体 skill}`：{为什么}
```

## 字段说明

| 段 | 要点 |
| --- | --- |
| 这次到哪了 | 只一句，给接手的人定坐标 |
| 已完成 | 每条带路径，方便直接跳过去看，不复述内容 |
| 未完成 / 下一步 | 可执行动作 + 验收标准，编号排列，接手的人按序做 |
| 关键决策与原因 | 记「为什么」和被否方案，避免下一轮重复试错 |
| 卡点与待确认 | 需要用户或其他人介入的，单独列出 |
| 环境与坑 | 本次踩到的命令、路径、权限、平台差异，值钱的部分 |
| 关联产物 | 只列路径，不复制内容 |
| 下次建议调用的 skill | 点名 skill 编号，写清为什么调 |

## 红线

- 不复述已有文档的内容，一律路径引用。
- 不写密钥、口令、token、个人隐私信息。
- 不写「继续推进」「完善一下」这类没有落点的下一步。
- 段为空就写「无」，不留空标题。

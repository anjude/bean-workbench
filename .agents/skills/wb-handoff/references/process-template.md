# 过程记录规则与模板

`process/` 记录任务每个阶段的推进过程，`handoff/` 记录跨会话的当前状态；两者互不替代。

## 命名规则

- 开发流程沿用阶段号：`process/00-任务初始化.md`、`process/01-需求沟通.md` 等。
- 不走固定流水线的任务使用两位序号：`process/01-{环节名}.md`、`process/02-{环节名}.md`。
- 同一阶段多轮修改追加到同一文件，以 `## YYYY-MM-DD 第 N 轮` 分隔，不重复新建。

## 记录内容

记录本阶段做了什么、得出哪些结论及其出处、被事实推翻的判断、待核问题。引用方案、代码、来源、命令结果和提交时写路径或链接，不复述已有产物。

过程记录不写下一步计划（下一步属于 handoff），也不写密钥、口令、token 或个人隐私信息。

## 代码提交前

准备提交代码时检查本次改动是否已被 `process/` 覆盖；缺少时自动补记改动范围、关键取舍、影响面和实际验证结果，并与代码一并提交。同一阶段已有记录则追加新轮次。若最新 handoff 的已完成状态或下一步因改动而过时，同步更新；普通提交不额外新建 handoff。

## 模板

```markdown
# {环节名} · 过程记录

- 任务目录：`task/YYMMDD_{主题}/`
- 阶段：{阶段号} {阶段名}
- 时间：YYYY-MM-DD

## 做了什么

- {动作} → 结果 / 产物路径

## 得到的结论

- {结论}：`出处或路径`

## 被推翻的判断

- {当时的判断} → 被 {数据/事实} 打掉：`出处`

## 待核 / 没答上来

- {问题}：卡在哪
```

没有对应内容的栏目写「无」，不留空标题充数。

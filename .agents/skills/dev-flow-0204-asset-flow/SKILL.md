# SVG 与品牌图标资产

阶段 02 前端开发，执行顺序第 4 步。阶段编排见 `dev-flow-0000-plan-flow`，项目上下文见 `dev-flow-tools-repo`。

本 skill 把图标、空状态图和轻量图形收归项目内，不把关键视觉资产交给外部平台。

## 适用范围

业务图标、空状态图形、组合图形或轻插画、图标替换、SVG 组件封装。

## 一、通用策略

1. 默认产出 `SVG`，不是 `PNG`。
2. 默认放到项目静态资源目录，例如 `src/static/icons/`。
3. 默认补薄组件或复用现有组件，不在页面里散落硬编码路径。
4. 默认至少接到一个真实页面验收。

### 资产主权检查

判断这次需求是否过度依赖外部条件：

- 是否依赖 iconfont 或外部图标平台
- 是否依赖重 UI 框架才能成立
- 是否依赖外部插画、图片、纹理才能成立
- 是否能改为项目内 `SVG`、CSS、轻组件、自有样式实现

首屏关键体验如果依赖外部资源，且项目内可以实现，优先改成项目内实现。

### 资产主权规则

优先使用项目内实现：品牌型业务图标、高复用入口图标、关键空状态图、能明显影响产品气质的小资产。

仅在以下情况允许复用外部方案：系统级通用图标（`uni-icons` 已足够）、品牌无要求且生命周期很短、项目明确要求兼容现有 iconfont 体系。

### 目录与命名

- 文件名统一短横线：`ic-{name}.svg`
- 目录：`src/static/icons/common/`、`src/static/icons/{domain}/`
- carbon 业务图标默认落 `src/static/icons/carbon/`

### 工作流程

1. 先判断是否必须新增 SVG，而不是先画。
2. 检查项目是否已有图标组件、目录和命名规则。
3. 需要新增时优先成批补齐同风格资产，不单点插入异类图标。
4. 同批超过 3 个图标时，优先补预览区或集中使用点。
5. 接入后检查真实页面，而不是只检查资源文件。

### 画法约束

- 默认统一 `viewBox`，例如 `96x96`
- 同批资产描边粗细、留白比例、圆角倾向一致
- 缩到 `18-28px` 仍要清晰
- 尽量减少碎细装饰
- 默认不引入多色插画风格；除非明确是空状态或场景图

## 二、carbon 品牌特化

命中 carbon 需求时，在通用流程之上叠加品牌约束。品牌基调与治理边界见 `dev-flow-0205-space-ui`。

- 默认气质：像夜里的小信号，不是白天的大图标
- 默认风格：圆角线性 + 少量面填充 + 克制暖色
- 默认落到 `src/static/icons/carbon/`，优先复用 `src/components/cu-biz-icon.vue` 或等价薄封装
- 不做游戏化卡通，不做企业后台线框感，不把图标做成多色插画主视觉

## 接入约束

- 页面不要大量直写资源路径，优先走组件映射。
- 图标组件只负责 `name`、`src`、尺寸和轻量展示。
- 替换已有入口图标时，尽量同步同类入口，避免半套风格。

## 验收

- 小尺寸是否清晰
- 深浅主题下是否可见
- 真实页面节奏是否协调
- 至少运行一次 `npm run type-check`

## 与其他 skill 协作

- 接入页面、组件、样式时同时使用 `dev-flow-0203-page-flow`
- 命中品牌项目时叠加 `dev-flow-0205-space-ui`

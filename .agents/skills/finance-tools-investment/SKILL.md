# 理财分析

把用户的投资规则、真实仓位和市场事实组织成可判断的方案。报告区分决策信息与阅读依据；真实数据以当前任务记录为准，不在 skill 或定时提示词里复制动态仓位和周进度。

## 入口与数据依据

- 当前工作台投资上下文：从工作台根目录读取 `task/daily/health-sleep-sell-put/README.md`、最新 handoff 和 `plans/投资授权与账户规则卡.md`；其他任务使用其明确绑定的投资记录，不串用账户。
- 当前私有输入在 `.agents/local-config/investment-analysis/`：必读 `strategy-policy.md`、`portfolio.json`、`weekly-income.json`；按需读 `market.json`、`events.json`、已有决定流水。人工核对入口为任务 `logs/美股期权仓位.md` 和 `logs/每周权利金记录.md`。
- 最新用户明确报送优先，其次正式台账/快照，旧报告和缓存只作历史资料。数据冲突时定位差异，不从记忆重建；未知仓位不补零。
- 金额、持仓、目标和阈值从上述记录加载；用户已确认的账户总价值包含股票市值，不再追问同一含义。当前用户不要求历史成本与手续费，勿把它们列为日常必补项。
- 计算复用 [投资分析工具](../../../tools/investment-analysis/README.md)。需要行情/事件更新时在内存构造输入，再调用既有聚合、情景或报告函数；不为一份日报开发新接入。

## 分析原则

### 决策状态与长期资格

- 真正进入交易决定前检查用户当次清醒与情绪状态；睡眠不足、精神疲惫或情绪不稳则暂缓决定。报告和到期风险提醒继续；只读报告不反复要求自评，不从聊天时段推断睡眠。
- 选股首先检查是否有证据支持十年后经营大概率更好：需求与竞争优势、盈利和现金创造、债务与再融资、资本开支、稀释、集中依赖、监管及治理。列支持证据、反向证据和判断失效条件。
- 分开判断公司长期资格、当前接股估值和可接受总股数。未研究标记待证实，不能因已持仓默认合格；不保证十年结果，不编造精确成功概率。
- 基金另评长期适合度，不能把行业增长直接当成基金长期价值；产品内部杠杆是否计融资额度以用户规则为准，波动和路径风险仍独立分析。

### 资金、仓位与周目标

- 当前用户资金安排口径：已知正股参考市值＋全部未到期 Put 的行权价毛接股义务，与用户账户总价值允许的融资后上限比较；超出总价值部分为该情景下潜在融资需求。每次随股价重算，不沿用旧余量。
- 不把该口径冒充真实券商融资/保证金；日常预算分析不因缺单独现金金额而停下或反复索取，精确交割核算仅在对应需求出现时另核。
- 覆盖全部存续 Put，不能漏远期；分列未来七天到期金额、潜在新增股数与全部指派后持股量。Call 校验现有股票和已占用股数，未知覆盖不默认满足。
- 集中度和共同风险以可核数据解释，未确认的阈值不自行设置；市值加接股承诺比例不能标成当前持仓市值权重。
- 周目标按已确认的账户总市值与目标比例计算，读取本周净收入和剩余目标；不把部分股票市值当账户总价值。先核记录所属周，跨周不可沿用旧剩余目标，不因期权到期重复记已收权利金。
- 净权利金现金流＝新卖出收入－旧仓买回支出，当前用户不扣手续费。它和账户整体投资收益分开；roll 的两条腿只合计一次，净滚仓价不是新腿开仓价。
- 目标用于寻找合适机会，不是必须凑满的额度；没有合格机会应直说，不能为达标提高行权价、增加张数或延长期限而省略新增风险。

### 事件、报价与候选

- 先核未来十四天、尤其下一次操作/到期前的全局与标的事件：官方日历、公司 IR、SEC、发行人资料优先，列上海时间、来源和核验时间。事实与影响推断分开，未核全不写无事件。
- 比较候选前确认是否新增跨越财报、利率/就业数据、除息或公司行动。无法确认的公司事件保留待核，不用往年日期填补。
- 优先使用已连接工具只读查行情。股票成交价、期权最后成交价与 bid/ask 的时间分别核对；最后成交时间不等于买卖价时间。不同来源/交易时段的涨跌保持同口径。
- 买回用 ask、卖出用 bid；中间价只能明示为争取成交的条件，不标已可成交。冻结、延迟、无买卖价时间或旧成交只能给参考计算/观察条件，不能升级为实时可执行结论。
- IV 须有效且说明单位、期限；无效负值/占位值不用。无有效历史分布不声称 IV 处于高分位，短期限年化 IV 较高不直接证明更贵。不同步的股票/期权不混算剩余时间价值。
- 当前用户优先研究到期周接近平值、滚至下一周；同时保留继续持有、接股、降价 roll 和平仓。平值不自动最优，净收 credit 不自动降低后续风险。
- 用户指定固定报告时刻时按其要求执行，按交易所时区/夏冬令时检查是否已开盘；固定上海22:00在美东冬令时仍是盘前，不因时刻到达就假定有盘中报价或有效IV。
- 分析每个候选时核对准确合约、张数/乘数、双腿报价、净现金流、目标贡献、资金变化、期限、跨越事件及适用条件；日报默认展示决定所需的精简结果，双腿报价与完整计算在用户追问时展开。对旧报价或无独立时点的结果标“参考”，不得标为确定可成交收入。
- 组合候选合并算资金，互斥/共用旧仓的方案明确标注，不能重复收入或重复使用同一余量。新开仓还需通过长期资格、接股价与持股量要求；否则只列观察池。

### 滚仓净收入：模型与报价并列

- 本周到期重点持仓表固定展示“模型净收”和“报价净收区间”两列，单位均为美元整笔金额：价差乘实际张数及合约乘数。报价区间的上下限放同一单元格，例 `+$35～+$160`。其他持仓若无本轮滚仓比较方案，用简表保留仓位，不铺满“未比较”。正值净收、负值净付，不标成已实现盈利。
- 两列比较完全相同的旧仓与目标新仓；表中注明目标合约，默认优先比较同价向后展期一周。不同当前到期日分别确定其下一周目标，不把远月仓位倒滚至近期；无本轮比较方案写“未比较”，不能填0。表头或行内必须能识别新到期日/行权价，不能只有滚仓金额。
- 模型净收＝（新仓理论价值－旧仓理论价值）×张数×乘数。使用同一估值时点和标的价格，分别输入两腿有效IV、准确剩余时间、无风险利率、分红和行权方式。美式股票/ETF期权优先使用支持提前行权的二叉树模型；仅用Black–Scholes时须在末尾标“欧式近似”。模型名称、参数来源与假设放末尾数据说明；参考[模型适用性](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/valuation-contingent-claims)。
- 报价净收区间下限＝（新仓bid－旧仓ask）×张数×乘数；上限＝（新仓ask－旧仓bid）×张数×乘数。上下限必须来自同一目标方案、尽量同步的四个报价。它们是单腿买卖价组合出的参考边界，不是保证成交的最低/最高收益；上限需要两腿均取得有利价格。中间价不冒充出价，不默认用上限补足周目标。
- 两列可独立缺项：缺有效IV/利率等必要参数则模型列写“待数据”；区间某端缺报价则该端写“待报价”，仅有一个端点不补造完整区间。交叉报价、无效或不同时点导致的倒置区间先核对，不自动排序掩盖异常。不得拿报价相减冒充模型结果，也不编参数凑满表格。
- 行情商的IV通常由市场价格反推，模型结果不构成独立的可成交报价；不能因模型数值更高就认定可多收权利金。过期/无时点数据对应列标“参考”，数据质量与模型假设集中在末尾解释。

## 日报格式：先速读，再查持仓

- 默认整份报告控制在约一屏半至两屏；分层必须减少阅读量，不能把长文拆成两个标题后仍全部铺开。日期/更新时间只写一次，全文在会话展示。
- 日报顺序：①“今天看这三件事”：事件窗口、最需处理的仓位、周目标，各一句，财报紧邻事件压成一行；②“本周到期”：重点持仓表含模型净收与报价区间；③“其他持仓”：简表覆盖全部其余合约；④资金一行结论；⑤末尾数据说明。优先结论不在后续重复展开，同一滚仓金额只出现在重点持仓表；确有必要时表后补一句取舍。没有合适机会直说，不凑候选；超限或其他期限的紧急仓位也必须前置。
- 第一层只写算出的结果、值得关注的仓位及改变操作选择的具体条件；不展开双腿、完整日历、规则复述、健康检查过程或泛化投资教育。报价不足时给有明确价格门槛的观察条件，不在正文反复插入“成交前需重核”等套话。
- 合约统一使用 `CRWV 261030 75P` 格式，张数、距到期分别单列，不同到期或行权价各一行。本周到期重点表采用“合约｜张数｜距到期｜模型净收｜报价净收区间”；同价滚至日期统一写在表头附近，例“同价滚至261106”，目标不同的行再注明差异。其他持仓简表采用“合约｜张数｜距到期”，发生重要风险时补一句，避免未比较占位。
- 股价与涨跌按标的只展示一次，可用四行窄表放在重点表附近，股价和涨跌仍分列，不重复到每份期权合约。正股数量只概括一次。距到期按报告上海日期与合约美东到期日期之差算日历日，到期当天为0；口径放末尾，临近到期的实际截止时刻另行注明，不能把日历日当剩余交易小时。未知持股不补零。
- 用户偏好直接用文字颜色表示涨跌，但当前会话的 HTML `span` 及内联颜色未能渲染。使用带正负号的百分比，例如 `+6.41%`、`−0.33%`；不要输出原始 HTML 标签或用圆点图标代替文字颜色。仅在当前展示环境实际支持且已确认文字颜色渲染时直接着色；颜色表达价格方向，不表示仓位盈亏。
- 财报在关键事件之后、持仓表和操作明细之前展示，优先用一行紧凑列各标的日期及确认/预估状态，不强制表格，也不在每份合约行重复。优先官方确认；未官宣可用行情商/日历预估，保存来源和核验日；注明已知盘前/盘后、统一时区；未核到可靠估计写“待定”，基金写“不适用”。来源冲突标范围或冲突，不用预估日期保证某笔到期前无财报；影响 roll 窗口的冲突是需关注的事实，仍须前置。
- 操作比较默认展示净收入、接股义务变化、延长期限、新增事件及适用条件；互斥候选和组合资金合并关系要说清。IV 只在有效且影响选择时展示；无合格机会或有效报价则给观察条件，不为达标扩大风险。
- 资金结论尽量一行给全部 Put 接股义务、情景潜在融资和距用户融资上限余量；金额覆盖远期仓位，未知不能当零。仍须检查本周到期及价内风险、长期资格、集中度、期限和完整性，异常或改变决定的结论明确展示；新仓须先过长期持有资格。
- 双腿报价表、完整事件日历、长期资格证据与逐项健康检查，用户追问对应部分时再展开；不以“全文展示”为由默认堆齐全部核对过程，也不把当前结论藏到文件链接。
- 同一事实只出现一次；不凑待补问题，不反复索取已记录的张数/资金。用户简写报送成交时先对照已有仓位解释字段。
- 所有免责声明、报价来源/快照时点、时区/乘数约定、延迟/冻结/接口失败、未核范围等说明统一放全文末尾的“数据说明”，通常一至三行；正文直接给结果和关注点。金额涉及旧报价时在候选名保留“参考/观察”标记，避免误标实时可执行。已确认超限、临近指派和具体事件冲突属于重要事实，不因说明后置而隐藏。引用贴近对应事实，避免重复免责声明；只加粗结论、金额、日期和触发条件。
- 图标统一：🟢 已检项目在限额内；🟡 待核/观察；🔴 已确认超限。用户只问单笔时直接回答，不强套日报。

## 记录与权限

- **报告正文默认只在会话展示，用户要求才落盘。** 不默认保存原始行情响应，不为每份日报写 process 或 handoff。
- **重要规则、目标、操作习惯和用户确认成交持续记账**：更新对应日常任务入口/台账和私有结构化输入，不能只修改定时提示词。真实金额/交易保留 Git 忽略目录，跟踪文档主要放规则和入口。
- 用户明确报送已成交再更新仓位，保留旧快照；同时记周净现金流，不把建议当成交。净滚仓价、单腿价格、用户报送日期、精确成交时刻分别存，缺项不伪造。
- 记录使用唯一事件 ID 防重复；存量仓位更新复用 `save-snapshot`。只有净滚仓价而没有精确成交时刻/双腿价时，沿用 `weekly-income.json` 与人工流水，不为迎合 `record-decision` 的严格成交字段制造数据。
- 私有目录 700、文件 600；`logs/` 被 Git 忽略，直接检查路径，不能因 `rg --files` 未列出就覆盖台账。
- 本 skill 只做分析、报告与用户报送记账；当前没有读取券商账户余额/仓位/流水及下单、改单的授权。不得据使用 skill 推导交易权限。
- 自动化读取本 skill 与任务最新记录；调度提示只保留入口、时间和权限边界，不堆叠动态金额与旧规则。用户要改频率时更新既有定时任务，避免重复新建。
- 当前投资任务已获用户明确授权，在轻量新会话/压缩续接时迁移日报 automation-2。先核对正式记录，再用应用自动化工具读取配置：只有目标仍是本次交接的旧会话才改到当前新会话，保留时间、状态、提示词及其他字段，随后读取核验；已是新会话则跳过，指向第三个会话或失败时不覆盖、不宣布迁移完成，不自动归档旧会话。授权不扩大到其他自动化，不直接改 automation.toml。

## 持续迭代

- 用户对信息顺序、图标、决策依据或流程的稳定偏好，改本 skill；个人风险规则和资金口径改规则卡/私有策略；成交与周进度改台账/快照。避免在三处重复维护同一份事实。
- 日常投资分析直接使用本 skill；计算器新增功能走 `dev-flow`，修改 skill 本身用 `skill-creator`，跨会话续接按 `wb-handoff`。
- 本轮重点反馈落实后检查相关入口和自动化是否一致；没有新脚本/算法时不另造测试，金额复用现有 Decimal 计算核对。

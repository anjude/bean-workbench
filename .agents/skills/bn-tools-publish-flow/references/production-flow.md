# 生产发布流程与二次开发边界

## 模式

这些是 Agent 当前可执行的工作方式，尚无统一的 mode 参数或编排程序。

| 模式 | 输入 | 执行范围 | 结束产物 |
| --- | --- | --- | --- |
| 讨论编辑 | 问题、观点、材料 | 讨论、核算、查证、修订 | 讨论结论或草稿 |
| 直接起草 | 主题和写作要求 | 起草并按反馈修订 | 待确认草稿 |
| 已有稿加工 | 原稿和修改要求 | 核查、改稿 | 修订稿或确认发布稿 |
| 仅排版 | 选定正文 | 格式转换、图片处理、预览检查 | 本地 HTML 与附件 |
| 入草稿箱 | 确认稿件和排版 | 上传素材、检查 payload、创建草稿 | 草稿 ID 和回执 |
| 后台定时发布 | 已验收的公众号草稿 | 在公众号后台核对稿件版本并设置计划时间 | 计划时间/任务标识及排期记录；实际结果待执行后核验 |
| 完整发布 | 确认稿件与明确发布授权 | 排版、上传、草稿、发布提交及查询 | 最终文章链接和记录 |
| 排障续跑 | 产物、回执和错误 | 核对远端结果，定位失败步骤后继续 | 恢复后的状态或明确阻塞 |

模式可组合，已有用户授权持续有效；内容质量判断由用户决定，不自动把草稿升级为发布稿。

## 生产步骤与交接

1. 查重并定位主题：在 `task/beannote/topics/YYMMDD_主题/` 建立或续写 README、process/、handoff/；绑定会话遵循 wb-handoff。
2. 确定本轮方式与终点：讨论、起草、改稿、仅排版、入草稿或发布；按用户要求执行，不默认公开发布。
3. 整理材料：保留来源、采集日期，区分事实、作者观点和待核问题。材料存 source/，判断过程存 process/。
4. 查证与计算：按需查原始出处或脚本复算，保存采用的假设及未核事项；投资演算区分本金、追加投入和收益。
5. 起草与修订：使用 `bn-tools-edit-flow`，按需读取其写作规则 reference，保留原稿及重要取舍依据，主题唯一正文存 `发布稿.md`，草稿/定稿阶段写入 README 与 process，不另复制文件。
6. 确认对外版本：更新同一份 `发布稿.md`；确认前后用 README 标记稿件状态，未经确认不能标记为定稿。
7. 提取排版输入：将对外标题与正文写入 publish/body.md，排除内部讨论、封面提示词等元信息。当前由 Agent 提取。
8. 选择样式：使用 `bn-tools-format-flow`，支持 Markdown 或 JSON blocks 输入、六套模板或自定义 JSON 覆盖。纯文本和任意 HTML 先转换；公式与复杂嵌套需单独核查。
9. 生成初版：输出 article.md、article_wechat.html、preview.html 和可选 article_seo.md；固定文件名会覆盖上次排版产物。
10. 核对内容与展示：检查文字遗漏、标题重复、表格宽度、图片和出处。SEO/词表只是本地提示，不自动替用户修改内容。
11. 准备封面与正文图片：已有图或生图工具生成，保留原图与必要的来源/AI 标识；裁切适配展示位。
12. 上传并回填：核对目标账号和凭证，封面上传取得 media_id，正文图上传取得微信 URL；Agent 回填正文图片 URL 后重排版，形成最终 HTML。
13. 检查入库数据：draft --dry-run 展示标题、作者、导读摘要、HTML、封面 ID 和评论权限；默认作者为「豆小匠」、开启评论并允许非粉丝评论。摘要由 Agent 写成有吸引力的导读，不要求复述正文；不请求远端草稿接口、不创建回执。
14. 创建草稿：已有入草稿授权后执行 draft，写请求前创建 pending 回执，响应成功后保存草稿 ID 和返回依据。平台保存的是提交时的稿件快照。
15. 后台验收：公众号后台或手机核对实际展示，并与本地最新正文/HTML核对；本地浏览器预览不能代替。重新排版不会更新已有草稿；当前脚本没有草稿读取/更新命令，存在版本差异时在后台同步并复核。
16. 设置定时发布：若用户选择后台排期，先完成草稿版本核验，再记录计划时间及可获得的任务标识。排期状态不等于已发布；当前没有自动排期命令。
17. 提交即时发布：用户明确授权公开发布后执行 publish，保存 publish_id；状态此时为已提交发布。
18. 查询结果：执行 status 查询平台最终状态；成功后记录实际文章链接及时间，接口无权限时转后台完成。
19. 回写记录：发布记录.md 记录账号、稿件和图片路径、素材 ID、草稿 ID、稿件版本核验状态、计划时间、发布任务 ID、链接、实际时间与结果；当前由 Agent 整理，回执为平台返回依据。

图片有一个回路：初步排版 → 确定图片 → 上传正文图 → 回填 URL → 最终排版。

## 当前实现的状态与恢复

- 内容及人工验收状态由 README、process 和 Agent 维护，没有统一状态机。
- 发布写请求回执有 pending、accepted 两种状态；accepted 仅代表对应接口已返回成功，不自动等于文章已公开。
- dry-run 不写回执、不发请求。同一路径已有回执会阻止再次提交；超时或中断后先查后台，不自动重试。
- 防重复以回执路径为边界，指纹尚未接入全局去重索引；更换回执文件名不能证明提交安全。
- 素材上传尚无自动持久化回执和内容去重缓存，Agent 需保存返回值并在重试前核对。
- status 是单次查询，结果只打印到终端，尚无自动轮询、最终回执和发布记录生成。
- 本地排版文件与远端草稿没有版本绑定；排版文件更新不会改变已创建草稿或平台定时安排，当前需人工核对后台版本。
- 后台定时发布不由当前脚本创建或查询；用户可提供计划信息，实际完成状态需在计划执行后核对。

## 二次开发缺口

| 能力 | 当前情况 | 可开发方向 |
| --- | --- | --- |
| 统一配置与账号选择 | 参数散落在命令和文档中 | 结构化账号、标题、作者、摘要、模板、目标终点 |
| 编排入口 | Agent 串联各脚本 | 显式模式、步骤执行、状态保存、断点恢复 |
| 版本关联 | 排版文件覆盖，内容靠约定保存 | 发布稿与生成物快照，回执关联具体版本 |
| 素材管理 | 手工保存上传返回值和回填 URL | 图片清单、哈希、远端 ID/URL 缓存及自动回填 |
| 草稿维护 | 只有新增 | 读取、更新、核对已有草稿 |
| 发布跟踪 | 单次查询 | 有限轮询、最终结果保存、自动回写链接 |
| 状态记录 | 人工文档与回执并存 | 明确的状态和失败分类、统一运行记录 |

统一编排、版本管理、自动状态机及上述扩展尚未实现，不将它们计为现有功能。当前源码与规则已内化；真实上传、后台展示及公开发布仍需新主题实测。

## 配置位置

工作台本机配置统一在 `.agents/local-config/`，公众号子目录为 wechat/：credentials 保存两行凭证，token-cache/ 按账号缓存 token。目录被 Git 忽略，敏感文件权限 600、目录权限 700。旧凭证与缓存已迁入，默认执行不再读取 home 密钥或 /tmp。环境变量和 WECHAT_KEY_FILE 显式覆盖继续可用。

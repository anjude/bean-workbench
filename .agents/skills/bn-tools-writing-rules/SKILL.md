# 写作硬规则

成稿和审稿前先读。完整的句式禁区与文风判断在 `references/创作准则.md`，本文件放账号级表达规则。

---

## 账号表达写法

适用于所有公众号文章、小红书图文、选题拆解和内容改稿。

豆小匠的内容不能只是"正确"，还要有辨识度。默认写法是：先给一个能站住的判断，再用场景、数字、案例、框架把它托起来。

- 不做资料搬运：信息要被整理成判断。
- 不做温吞科普：知识点要落到真实问题。
- 不做情绪喊单：情绪要被事实、方法或边界托住。
- 不做万能鸡汤：每个结论都要有具体对象、具体场景或具体后果。

### 推荐结构

1. 人设开场或直接进入事件/问题
2. 抛出主判断或强反差
3. 展开事实、场景、案例或数据
4. 给出判断框架或观察路径
5. 说清边界，尤其是投资合规边界
6. 用轻观察、调侃或开放问题收住

### 具体判断维度要写出来

不要只写：

```text
普通人要提升认知。
```

要写成：

```text
很多人以为提升认知是多看几篇文章。
真到亏钱的时候，问题往往不是不知道道理，而是仓位、现金流和情绪承受力没对齐。
所以这篇不聊大道理，只聊一个动作：买之前先写下最坏情况。
```

### 避免重复

如果正文中已经讲过“持续做 IP 的能力”，结尾就不要再复述“到底有没有持续做 IP 的能力”。

结尾可以换成新的轻观察：

```text
不过，谁知道大道这次到底是不是在喊单呢哈哈哈

话说回来，一个头像能让投资圈聊这么久，本身就挺泡泡玛特的。
```

## 公众号一次可发布标准

公众号文章不要写成“小红书短句合集”，也不要写成“标准评论文”。核心是：像一个真的人在认真聊这件事。

### 语气

- 可以轻松，可以调侃，但不要油。
- 允许有一点生硬转折，比如“不过，谁知道...”，这比过度顺滑更像真人。
- 不要把所有转场都磨平。过度自然，反而像 AI。
- 不要解释笑点，直接写反应。
  - 不好：这个梗好笑，是因为反差足够大。
  - 更好：哈哈哈，这反差也太大了。

### 读者位置

- 不要预设读者想错了。
- 不要用纠偏式表达：
  - 别把这个理解成...
  - 不要以为...
  - 很多人会误以为...
- 不要替读者规定重点：
  - 真正值得看的...
  - 这比讨论 X 重要得多
  - 这才是...
- 改法：顺着语境自然往下聊。

### 信息密度

每一段都要提供新东西，至少满足一个：

- 新事实
- 新观察
- 新判断
- 新例子
- 新情绪
- 新问题

删除没有新增信息量的垫话：

- 不好量化，不代表不重要。
- 这套框架当然重要。
- 它要求投资者理解的东西变多了。
- 表面看...往深一点看...
- 当然是好事。
- 这本身没问题。
- 并不是坏事。

如果一句话只是“解释前一句为什么对”，优先删除或换成具体细节。

不要用无意义的价值平衡句软化观点。如果一句话只是为了显得客观、稳妥、两边都照顾，但没有提供新观察或新判断，直接删掉。

### 结构

- 开头可以用梗，但不要一直围着梗打转。
- 中段要给出具体判断维度，不要只说“情绪价值很重要”。
- 结尾不要复述前文判断。
- 结尾可以用轻微调侃收住，也可以留一个有余味的小观察。

### 重点标注

- 可以少量使用粗体。
- 每篇 3-5 处即可。
- 只加粗真正值得停一下的句子。
- 不要满屏加粗，不要把粗体当情绪放大器。

# Superone MCP

通过已连接的 Superone MCP 工具操作用户自己的近期任务、清单和 Skill。用户可用 `so` 作为唤起词；单独说 `so` 时先简短确认本次要查任务、处理清单还是管理 Skill，不猜测并执行写操作。

## 近期任务

- 查询使用 `list_recent_tasks`。默认只展示置顶任务：读取返回项的 `top` 字段，筛出 `top` 非零的任务；接口不支持置顶筛选时，在结果中本地过滤，并继续分页查找，直到确认当前筛选结果或到达列表末尾。
- 用户明确要求查看全部任务，或给出关键词、状态、优先级、数量等筛选条件时，按其要求查询；若未明确要求忽略置顶限制，仍只展示置顶任务。
- 状态值：`1` 待处理、`2` 进行中、`3` 已完成、`4` 已取消；优先级的显示含义若工具结果或产品资料未说明，不自行推断。
- 用户要求查看某项详情时，用列表中的 ID 调用 `get_recent_task`。任务工具当前只读，不声称可以通过 MCP 新建或修改近期任务。

## 清单

- 按标题查找或浏览用 `list_checklists`；查看具体内容用 `get_checklist`。
- 用户明确要求创建时，依据其提供的标题和步骤调用 `create_checklist`。若关键内容缺失，先用已有上下文补足；无法合理确定标题或步骤时只询问缺失项。
- 编辑时先读取现有清单，保留未要求变更的标题与步骤，再调用 `update_checklist`。该接口传入项目列表会按原接口语义更新；不要只传局部步骤，以免覆盖其余项目。
- 目前没有删除清单本身的 MCP 工具。不要把删除执行记录误当作删除清单。
- 创建执行记录前读取清单，按用户选择的模式和实际进度记录。`mode=1` 为正常执行，`mode=2` 为分步执行；`status=1` 为进行中，`status=2` 为已完成。`start_time`、`finish_time`、步骤确认时间使用 Unix 秒。
- 步骤执行记录以清单项目 ID 对应。只有实际完成或明确跳过的步骤才写相应总结、确认时间和跳过标记；不要虚构执行结果。未完成时使用进行中状态；全部步骤实际完成后再记为已完成。
- 查历史使用 `list_checklist_executions`，按 ID 读取用 `get_checklist_execution`。更新记录前先读取并保留无关字段。删除执行记录会移除历史，只有用户明确要求删除指定记录时才调用 `delete_checklist_execution`。

## Skill 管理

- 浏览指定分类使用 `list_skills`；查看文件包用 `get_skill`。不确定分类时先查看当前会话中 Superone MCP 安装说明或工具约定，不猜测分类名。
- 用户明确要求上传/创建 Skill 时，上传用户选定目录中的 Skill 文件，按相对路径映射为 Base64 后调用 `save_skill`；不包含凭证、机器配置、缓存和临时文件。保存后核对返回的名称、ID、分类、摘要与版本。
- 上传前在目标分类按名称检查是否已有同名 Skill。若同名，读取现有完整文件包并比较；只有用户明确授权更新时才以对应 `skill_id`、当前 `revision` 和完整文件包更新。未经授权不得覆盖或删除远端 Skill。
- 更新使用 `save_skill` 提交完整文件包及当前版本号；新增时省略 `skill_id` 和 `revision`。组织 Skill 还需使用用户指定或已查明的 `organization_id`。
- 删除 Skill 会移除远端资源，必须有用户明确指向该 Skill 的删除要求，并先按 ID 和当前版本核实；不得通过同名猜 ID。
- 本地 Skill 的创建、修改与远端上传是不同操作。用户只要求整理或创建本地 Skill 时，不自动上传。

## 工具边界

- 只调用完成当前要求所需的 Superone MCP 工具；成功或失败都依据工具返回如实说明。
- 写入操作必须由用户当前明确要求支持。查询和详情读取可直接进行；含糊的 `so` 唤起仅用于澄清操作意图。
- 时间戳按 Unix 秒传递；向用户展示时转为其本地时区的可读时间。
- 不在回复、日志或上传文件中暴露认证令牌、账号内部标识等无关敏感值。

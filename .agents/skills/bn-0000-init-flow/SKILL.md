# 选题初始化（00 阶段）

## 这一步解决什么

开题时把舞台一次搭齐。之后各阶段只往里填内容，不再操心文件叫什么、放哪。

| | |
|---|---|
| 输入 | 主题名 |
| 输出 | 一个选题目录 + 五个槽位文件 + `manifest.json` |
| 停下等什么 | 建完报路径，不问别的 |

## 触发

用户开新选题（"开个 topic""起个主题"之类）并给出主题名。主题名没给就问一句，问完直接建，不再确认。

## 做什么

1. 建目录：`business-repo/beannote/topics/{YYYY-MM-DD}_{主题}/`，含一个空的 `source/`
2. 建五个槽位文件，`md`，各写一行 H1 `{槽位名} - {主题}`：

   | 文件 | 用途 |
   |---|---|
   | `01-1-问答录-{主题}.md` | 讨论的结论：问了什么、答了什么、哪些没答上来。只留结论，不放原文 |
   | `01-2-素材-{主题}.md` | 选题素材：有意思的知识点、故事、数字，带出处和可用在哪 |
   | `01-3-大纲-{主题}.md` | 用途待定，用户没说之前不填 |
   | `02-1-公众号-{主题}.md` | 公众号正文 |
   | `02-2-小红书-{主题}.md` | 小红书正文 |

   编号规则：`{阶段号}-{阶段内序号}-{槽位名}-{主题}`。阶段号固定两位，不动；同阶段多个文件靠中间那一位序号排，**序号即流程顺序**，新增文件插在中间时要重排序号并同步已建 topic 的文件名。

   `source/` 放原始素材：查到的原文摘录、数据表格、网络内容快照。命名 `{序号}-{来源}-{内容}.md`，文件头写来源 URL、数据口径、抓取时间。**槽位文件只放结论，`source/` 放原始件**——这样问答录不膨胀，事实也能追溯。

3. 写 `manifest.json`

## manifest.json

```json
{
  "topic": "黄金",
  "status": "draft",
  "created": "2026-09-14",
  "slots": ["01-1-问答录", "01-2-素材", "01-3-大纲", "02-1-公众号", "02-2-小红书"]
}
```

| 字段 | 含义 |
|---|---|
| `topic` | 主题名，建题后不改 |
| `status` | `draft` / `published` / `archived` |
| `created` | 建题日期 |
| `slots` | 已建的槽位 |

## 规矩

- 只建骨架，不写内容。
- 不预先建用户没要的文件，不为将来可能的需要留位。
- 目录建好就停，把路径报给用户。
- **本 skill 是目录骨架的唯一定义处。** 新增槽位、改命名、调整结构，一律先改这里再动手，顺带更新已建 topic 的 `manifest.json` 的 `slots`。

# AI 辅助编辑

主题入口是 `task/beannote/topics/YYMMDD_主题/`，目录约定见 `task/beannote/README.md`。先查同题目录，新建时按 `wb-handoff` 绑定会话，建立 README、process/ 和 handoff/。

## 按请求推进

- 用户给问题：围绕问题展开讨论，保留尚未确定的判断；不要仅凭主题名称自动产出完整文章。
- 用户提出新主题或灵感时，先把它当作内容引子：优先寻找能让读者代入、想点进来聊两句的情绪、经历或争议点。不要自动把轻主题扩成研究报告，不要求先做完整行业比较、数据论证或穷尽背景；只有用户明确要分析、核查或写成深度稿时，再按需补充。
- 讨论选题时可以给出简短、有画面感的切口或标题方向，重点是引发共鸣和讨论，不把标题里的情绪表达自动当作待证明的事实，也不因此强行定文章结构。
- 标题不必概括全文，也可以只是一个引子或讨论问题；标题的作用可以是把读者带进来参与讨论、分享经历。不要为了让标题完整复述文章论点而牺牲它的吸引力，具体取舍由用户决定。
- 用户给观点、材料或草稿：按这次要求查证、改写或提出可比较的表达。标题、结构、风格、留删服从用户的选择；不要用固定反转、金句数量或 CTA 套住内容。
- 用户要求直接起草：可以交付完整草稿，标出假设和待核事实；不能把自己的版本写成用户已经确认的发布稿。
- 修改稿件时保留原稿和讨论依据。重要判断落 `process/`，当前状态落 README；已被否掉的稿件不自动复用。

## 事实与计算

需要查证的资料保留来源、日期和适用范围；引用数据与作者推断分开。无法访问的资料标记待核，不编造出处或搜索热度。

投资题材的计算记录本金、收益率、期限、追加投入、复投频率、费用和通胀等实际采用的假设；示例收益率不写成承诺。用脚本复算关键数值，区分本金增长、追加投入与投资收益。用户所说的「感受到」应在讨论中具体化，不先替用户设一个金额门槛。

## 写作规则应用与维护

起草、改稿和内容检查时按需读取 [写作规则](references/writing-rules.md)；需要免责声明或公共模块时读取 [文章公共模块](references/article-modules.md)。排版也直接引用这份公共模块。

用户明确提出「以后统一」「以后都这样」，或要求新增、修订、撤销长期规则时，更新对应 reference，并把变更依据记入任务 process/。单篇临时调整只记在该主题；Agent 自己提出的建议和待确认草稿不自动成为全局规则。更新时同步检查排版和发布的引用，避免复制维护多份规则。

## 交给排版与发布

每个主题只维护一份正文，统一存为 `发布稿.md`；草稿和定稿是 README 中的内容状态，不复制两份正文。排版调用 `bn-tools-format-flow`；上传素材、入草稿箱和发布调用 `bn-tools-publish-flow`。同一次用户授权已覆盖的操作继续执行，不为机械步骤反复确认；尚未确认的内容版本不要标为定稿。

编辑阶段可单独使用，不因研究文章而自动发布。记录实际稿件状态，不把本地预览、公众号草稿和公开发布混为一谈。

整条链路的模式、输入输出与二次开发缺口见 [生产发布流程](../bn-tools-publish-flow/references/production-flow.md)，理解或改造跨环节流程时读取。

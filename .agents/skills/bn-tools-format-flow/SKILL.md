# 公众号排版

执行代码随本 skill 落盘，不依赖用户级安装或外部排版网站。下列命令在工作台根目录执行；从其他目录调用时按本 skill 的实际位置解析 scripts/。

## 排版

从选题的发布稿单独提取标题与正文：只将正文写入 `publish/body.md`，标题作为元数据通过 `--title` 传入；内部说明、封面提示词、讨论记录不进入正文。微信草稿接口有独立标题字段，因此 `article_wechat.html` 只包含正文，不在 HTML 中重复放标题；本地预览可单独显示标题以模拟阅读页；预览页复制按钮只复制正文 HTML，与接口使用的正文内容一致。仅当留言引导本身属于用户确认的正文时保留。每篇文章都必须有独立的 `置顶留言.md`，包含通用免责声明和题材风险提示；排版前确认该文件存在。免责声明不放进文章 HTML；正文只排版对读者有用的内容。置顶留言单独保存为可直接复制的文案。模块约定见 [文章公共模块](../bn-tools-edit-flow/references/article-modules.md)。

```bash
ARTICLE_TITLE="文章标题"
python3 .agents/skills/bn-tools-format-flow/scripts/formatter.py "$TOPIC/publish/body.md" \
  --title "$ARTICLE_TITLE" -t 微信绿 -o "$TOPIC/publish" --seo -k 复利
```

`TOPIC` 为当前选题目录。输出固定为 `article.md`、`article_wechat.html`、`preview.html` 和可选的 `article_seo.md`，再次执行会覆盖这些排版产物。原始发布稿不改。重新排版只更新本地文件，不会修改已入草稿箱或已设置定时发布的远端稿件；如远端已有稿件，生成新版本后交由 `bn-tools-publish-flow` 核对并同步。

- 默认在微信正文 HTML 和本地预览中注入账号固定头尾：`templates/beannote-header.html` 与 `templates/beannote-footer.html`。头部包含关注引导、公众号名片和单线菱形分隔装饰；中间点缀使用可保留的文字图形 `◇ ● ◇`，不依赖 flex 或空元素。尾部默认包含「鹅懂个啥」微信小程序卡片、`—— E N D ——` 与点赞提示；`article.md` 保留纯文章内容，不混入头尾。
- 特殊文章需要关闭或替换时，使用 `--no-header`、`--no-footer`，或通过 `--header-template`、`--footer-template` 指定其他 HTML 片段。头尾属于账号包装，不写入 `发布稿.md`。
- 本地浏览器无法渲染微信自定义公众号名片 `<mp-common-profile>`；它能保留在生成的 HTML 中，但最终须在公众号编辑器或草稿预览里核对名片显示。
- 固定尾部小程序内容可用 `--mini-program-link`、`--mini-program-title`、`--mini-program-copy` 覆盖链接、显示文案和尾部提示；`--mini-program-path` 与 `--mini-program-image` 可同步覆盖备用页面路径和封面。参数未提供时沿用 formatter 中固定的账号默认值。要在公众号显示真正的小程序卡片，使用 `--mini-program-mode card` 输出 `<mp-common-miniprogram>`，并以公众号草稿预览的实际显示作为验收标准；本地浏览器不显示此卡片不影响公众号稿件。`text` 模式仅用于明确需要文字链接的场景。接口对 `draft/add` 曾返回 45166，但本篇通过 `draft/update` 成功保存卡片标记；不要据一次接口报错推断所有接口或更新场景均不支持。新的全局默认值通过 `templates/beannote-footer.html` 与 formatter 常量维护。
- 模板：微信绿、经典红、商务蓝、清新绿、优雅紫、温暖橙；beannote 默认使用微信绿，其他主题沿用用户指定或账号已有模板。
- 自定义样式用 `-c config.json`；可覆盖配色、font、spacing、image、card、heading_numbering 等，字段见 [排版参数与检查边界](references/layout.md)。
- 输入支持 Markdown 或 JSON blocks。纯文本和 HTML 先核对内容并转成 Markdown/blocks；脚本不直接解析任意 HTML。微信端列表若出现空圆点，使用普通段落加显式圆点/序号排版，避免原生 `<ul>/<ol>`；列表效果以公众号草稿预览为准。本地预览不能替代平台核验。表格、列表、公式、图片和出处在预览中逐项核对，特别检查移动端宽度与文字丢失。
- SEO 分数与词表命中仅为本地提示，不作为自动改标题、加图、改观点或通过审核的依据。详见上述 reference。
- 需要更明显的互动时，参考[公众号互动排版武器库](references/wechat-interactions.md)。优先选无脚本、带普通文字兜底的静态 SVG/SMIL 片段；网页专用手势不作为公众号正文能力承诺。

## 图片

### 公众号封面风格

- 先想清这篇文章写给谁、读者带着什么问题点开，以及封面要传达的判断或情绪。封面要让目标读者觉得内容值得认真读，维护公众号可信、成熟的专业感；不能只因画面“有趣”或“有冲击力”就采用。
- 封面不必复述全文。可以从文章里选一个具体细节、真实矛盾或关键关系做视觉切口；抽象主题也可以用编辑插画或克制的概念表达。画面与文章的联系应能一眼理解，不依赖作者额外解释。
- 创意服务于内容和受众。避免幼稚小清新、廉价搞笑、故作荒诞、惊悚压迫、套路化金融符号，以及表情或动作诡异的人物画面；也不要把“专业、深刻”简单画成冷黑、阴郁或堆砌抽象符号。人物、隐喻、戏剧性都按主题和账号气质判断，不套固定禁用清单。
- 不因担心画坏而默认退回纯文字封面。只有用户明确要求，或文字本身就是本篇最合适的视觉表达时，才采用纯文字；其他情况继续寻找合适的图像方向。
- 构图保持清楚，缩略图下先看到一个主视觉和标题层级。人物、物件与环境应自然可信，细节不互相打架；对生成结果检查人物表情、肢体、物件结构、文化暗示、裁切和标题可读性。出现违和、幼稚或廉价感时先重做，不把它包装成可发布成品。
- 投资、理财等主题不直接出现钱币、钞票、K 线、走势图、金融终端等理财符号；从文章真正要表达的感受或逻辑出发，选择含蓄的视觉隐喻。
- 视觉方向以有表现力、完成度高的编辑插画或绘画为主，不限定画派、材质和色彩；根据文章与受众选择明度、冷暖和抽象程度，不默认温暖治愈或暗黑沉重。避免模仿某位在世艺术家的具体风格。
- 每篇封面都根据目标读者、文章内核和当篇切口单独构思，不套固定模板或固定视觉母题。不要为了系列一致牺牲内容表达；账号专业感由准确的内容切口、成熟的视觉判断和完成度建立。
- 默认不在图上主动添加标题、文字、数字、Logo 或水印；用户另有要求时再添加。素材自带的必要来源或 AI 标识按图片工具规则保留。
- 生图前用一两句话说明目标读者、画面切口和预期气质；生成后先按这些标准筛图，再检查裁切和小尺寸表现。不能只因图片已生成或技术上能上传，就认定封面适合发布。以上是账号的质量原则，不要求所有题材使用同一种画风、色板或构图；同时遵守图片工具的 skill。
- 可参考 [外部封面样本的可读性原则](references/cover-visual-reference.md)：学习如何从文章切出具体、有趣、带情绪或戏剧感的画面，不复用原图或套用对方的具体素材。

```bash
python3 .agents/skills/bn-tools-format-flow/scripts/image_enhance.py 原图.png 封面.jpg --cover-crop --ratio 2.35
```

图片工具需要 Pillow；排版和检查仅需 Python 标准库。当前系统 Python 缺 Pillow，可用桌面依赖工具返回的 Python 运行时（本轮已验证），不要把该运行时的机器绝对路径写死到脚本。macOS 无 Pillow 时可用 `sips --cropToHeightWidth 高 宽 原图 --out 输出图` 和 `sips -s format jpeg -s formatOptions 85 输出图 --out 封面.jpg`。先按原图尺寸计算居中裁切范围，2.35:1 是当前工作台封面默认值，可按实际展示位调整。保留原图和必要的来源、AI 标识信息，不把去除标识作为裁切目标。

正文图片先用 `bn-tools-publish-flow` 上传取得微信 URL，再回填排版输入并重跑；本地路径或占位符不能作为最终入库图片。需要生成新图时使用当前环境的生图工具，遵循该工具的 skill。

## 交付

报告发布稿、HTML、预览和检查报告的位置，说明排版中无法保真的元素。用户已授权入草稿箱时接 `bn-tools-publish-flow`，并将实际结果写回选题。

整条链路的模式、输入输出与二次开发缺口见 [生产发布流程](../bn-tools-publish-flow/references/production-flow.md)，理解或改造跨环节流程时读取。

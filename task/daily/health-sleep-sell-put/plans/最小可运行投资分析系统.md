# 最小可运行投资分析系统

- 日期：2026-10-26
- 使用入口：用户已选择当前聊天生成报告，本地保存仓位与记录。
- 范围：单账户、USD 正股与卖出 Put / covered call 的只读分析。
- 任务归属：继续当前 daily 任务；代码放工作台 `tools/investment-analysis/`，业务仓和网页不改动。
- 2026-10-27 新入口：`finance-tools-investment` 统一处理分析、报告与记账。报告为事件前置的“决策层＋阅读层”，默认只在会话展示；历史设计中每份报告自动保存、健康明细总在首部的约定已被覆盖。

## 需求理解

输入用户确认的仓位、带时点的市场快照与事件资料，在聊天中给出当前仓位分析、标的与全局事件，以及持有、新开、roll、平仓的可选情景。计算部分可重复执行，研究结论保留来源；缺失数据限制对应结论，不阻止整个报告生成。

## MVP 功能

| 功能 | 最小交付 |
| --- | --- |
| 当前仓位分析（第一功能：仓位健康检查） | 先给总体结论、风险/待核项与处理优先级，再分别检查长期持有资格、资金与融资边界、集中度/相关性、到期及接股义务、事件风险和数据完整性；分开统计正股与期权。缺少成本不阻止前瞻分析，缺少现金不判定实际融资或现金覆盖。具体规则见下节。 |
| 标的信息 | 报价时点、来源、状态、相对前收变动；未来 14 天全局/标的事件及来源。没有查证事件时标记“未检查”，不写“无事件”。 |
| 操作可能性 | 每个持仓先列继续持有，再列平仓和 roll 的待补条件；按输入报价比较候选新仓/平仓/roll 的现金流、资金变化、期限和覆盖约束。卖出用 bid、买回用 ask；roll 净收入与旧仓盈亏分别计算。 |
| 仓位输入与留存 | JSON 快照录入/校验/备份；真实仓位只存 Git 忽略的私有目录，保留用户报送时间和来源；以本次找回的原会话记录恢复初始仓位。 |
| 分析与决定记录 | 每份报告保存分析时间、数据时点、缺项；用户做出决定后以 JSONL 记录，不把“建议”写成“已成交”，不自动改变仓位。 |

## 实施方案

### 第一功能：当前仓位健康检查

- 前置检查用户决策状态：当次自评适合 / 暂缓 / 未知；记录来源和时点，不默认通过，不从聊天时间推断睡眠。睡眠不足、精神疲惫或情绪不稳定时只提供研究、待复核候选与风险提醒，暂缓交易决定；恢复后用最新报价和事件重新复核。没有自行设定睡眠时长阈值，也没有券商端拦截能力。
- 入口：用户要求“检查当前仓位”或每日生成报告时使用；健康明细位于阅读层，紧急告警放决策层，关键事件在候选之前；它是原“当前仓位分析”的完善，不另建独立系统。
- 输出：总体状态（发现超限 / 需关注 / 待核 / 未发现已检项目异常）、已核依据、待核范围、优先事项。没有完整证据时不把整体标为健康，不设置伪精确健康分数。
- 长期持有资格：逐家公司给“符合 / 待证实 / 不符合”，附支持和反向证据、判断失效条件；现有仓位不默认合格。基金单独检查适合度，不能套用公司长期经营结论。
- 资金边界：按用户当前规则，账户融资不超过本金参考的 10%，产品内部杠杆不计入。已知股票参考市值与全部 Put 毛接股义务合并作粗筛；分母、价格时点、未知其他持仓必须标明。粗筛在上限内不等于实际现金足够，也不把余量变成新开仓预算。
- 集中度：至少列每只标的已知股票参考市值、全部 Put 接股义务和全部接股后股数；统计到期聚集，研究行业及共同风险。用户未设置集中度阈值时仅披露，不编造合格线；未知相关系数不填写数值。
- 到期/接股：检查未来 7 天和全部存续义务、标准乘数假设、准确到期日、接股意愿/数量；不因远期未到期就漏算资金。
- 事件：未来 14 天宏观/公司事件、候选 roll 是否跨越新事件；事件覆盖 partial/not_checked 时结论待核，不能当作无风险。
- 数据：仓位完整性、合约身份、行情时效、IV 是否有效；缺失仅限制对应判断，不阻止报告生成，历史成本不再作为必填项。
- 优先事项从可确认事实给出，关联继续持有、接股、roll、平仓比较，不将健康告警自动转为交易指令。
- 实现边界：当前采用现有计算器聚合 + 聊天研究解释，依据私有策略文件生成报告；没有新增自动评分算法或自动风控引擎。
- 验收：现有冻结快照下能列出资金粗筛、全部/近期义务、各标的敞口、长期门槛待核和数据缺项；未知项不显示通过。金额使用现有 Decimal 聚合并复核。

- `tools/investment-analysis/investment.py`：Python 标准库实现，Decimal 金额计算；`report`、`save-snapshot`、`record-decision` 子命令。
- `tools/investment-analysis/examples/`：虚构数据、事件与候选操作样例，可无外部服务跑通。
- `tools/investment-analysis/test_investment.py`：核验聚合、盈亏/roll 口径、持股覆盖、失效/缺失报价和输入拒绝行为。
- `tools/investment-analysis/README.md`：聊天使用方法、输入字段、报告口径和命令。
- `.agents/local-config/investment-analysis/`：真实组合、市场快照、事件、决定和报告；目录 700、文件 600。市场快照沿用本轮 IBKR 已返回数据并明确冻结状态；不开展行情自动接入。
- `logs/美股期权仓位.md`：恢复原用户逐笔快照，保持人工入口。`rg --files` 默认忽略 logs，不能据其输出判断文件不存在。

事件由聊天中的公开来源研究或用户输入维护；v0.1 的事件文件读取与报告展示可以离线运行，未查证的覆盖范围明确标记。行情/事件的自动抓取不作为首次可运行的前置条件。

## 计算与状态约定

- 空值为未知，数量/金额不可用零补齐；分组股票不因同一标的多张期权重复计数。
- 合约乘数单独存储并标明是否由用户/合约确认；初始仓位沿用每张 100 股的标准合约情景，实际合约身份待核。
- 报价状态与时间总是展示；冻结、未来时间、过期或延迟数据只能作为历史/条件情景，不作为当前可执行建议。
- 默认报价时效提示窗口为 15 分钟，仅用于数据质量提示，可配置；这不是用户投资风险阈值，也不证明行情订阅实时性。
- 卖 Put 毛行权资金 = strike × multiplier × contracts；它不是券商保证金。
- roll 现金流 = 新仓 bid × 新数量 × 新乘数 − 旧仓 ask × 旧数量 × 旧乘数 − 已知费用；旧仓盈亏需要原始权利金和费用，未知时留空。
- CC 候选校验已知持股与已有 short call 覆盖；持股未报送时覆盖状态未知。
- “适合开仓/roll”等结论还需用户资金规则、接股/交股意愿及新鲜报价；MVP 可以输出条件和数字比较，不替用户补这些偏好。

## 验收标准

1. 使用虚构样例，一条命令输出三项核心内容及缺项，不访问网络、账户或交易接口。
2. 恢复的用户快照独立记录 CRWV 300 股、PDD 400 股和 8 张 Put；标准乘数情景下毛行权资金 76,500 美元，本周到期 6 张、58,500 美元。
3. 缺权利金/成本/现金时，对应净盈亏/覆盖率显示未知；冻结报价和未查事件不能显示为新鲜数据或无事件。
4. roll 例子同时给出旧仓平仓成本、新仓收入、净现金流和资金/期限变化，不把 net credit 当作利润。
5. 非法数量、重复仓位 ID、不合法日期、NaN/Infinity、ask 小于 bid、无来源事件/报价、不可覆盖 call 均可辨识；snapshot 留存保留旧版本。
6. 手工报告与未来 API 输入使用同一字段口径，无网页、生产数据库、部署或自动订单变更。

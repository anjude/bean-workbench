# 美股交易数据与新闻采集方案

- 日期：2026-10-26
- 状态：本地能力与官方数据源已盘点；实现前待确认接入源与凭证/行情权限

## 需求理解

为 covered call / sell put 组合分析建立只读数据入口，拿到有时间戳、能追溯来源的正股行情、期权合约/期权报价、财报/公司公告和必要新闻；自动标出延迟、缺字段、权限不足与数据冲突。优先复用现有 LongPort 股票行情能力，但不把 LongPort 或任何单一来源假定为完整。

## 本地盘点结果

### 工作台和业务仓现状

- 工作台根目录已有 `cmd/stock.go`（`hr stock <ticker>`）：访问 `https://stockanalysis.com/api/quotes/s/{ticker}` 获取报价，`-v` 另访问 `/symbol/s/{ticker}/overview` 获取基本面、分析师、公司简介和财报日期。报价模型含 `UpdatedAt`、market status、常规/盘前盘后价格；没有期权字段。
- 这个命令走的是 StockAnalysis 网站内部 endpoint，而非供应商开放 API。StockAnalysis 官方 FAQ 表示不提供 API/MCP/程序化访问；当前 Terms of Use 明确禁止 bot、script、scraper 等自动访问和采集。因此不能把该 endpoint 复用到新投资采集器，也不应把当前 CLI 输出当作有 API SLA/授权保证的交易数据源。网站说明其 Nasdaq/NYSE 网页报价对免费用户约每 5 秒刷新、付费用户实时流，但这不等于授权脚本调用其内部 API。
- `tools/` 目前有来源采集器，没有合规授权的美股行情或期权采集工具；来源采集器面向网页/视频资料，不应承担实时行情抓取。
- StockAnalysis 来源说明：[API access FAQ](https://stockanalysis.com/help/faq/api-access/)、[Terms of Use](https://stockanalysis.com/terms-of-use/)、[股票报价更新频率](https://stockanalysis.com/help/faq/stock-price-data/)。
- `business-repo/backend-superone/third_party/longport/longport.go` 的 `IStockInfoSource` 目前只封装股票 Quote、批量 Quote 和美股证券列表，没有期权方法。
- `business-repo/backend-superone/go.mod` 使用 `github.com/longportapp/openapi-go v0.16.1`。本机该 SDK 版本已有 `OptionQuote`、`OptionChainExpiryDateList`、`OptionChainInfoByDate`，说明 LongPort 期权链/报价能力可从 SDK 接入，但现有封装尚未接入。
- `business-repo/frontend-investment-platform` 当前是 Vue 工具网站基座，代码中未发现行情 API 接入。

### LongPort 官方能力与缺口

- LongPort 官方文档提供美股期权实时报价、到期日列表、按到期日查询期权链。调用需要账户具备相应行情权限，未确认本账户权限是否开通。
- 官方期权报价 schema 包括最新成交价、前收、开高低、成交量/额、行情时间、IV、OI、到期日、行权价、合约乘数/类型、Call/Put 方向、历史波动率和标的代码。
- 当前公开报价 schema 未列出 bid/ask、Greeks；本机 SDK `OptionQuote` 类型同样没有这些字段。因此 LongPort 适合作为合约发现、最新成交及 IV/OI 的来源，暂不能单独满足可执行买卖价和 Greek 风险分析。
- 官方资料：[期权实时报价](https://open.longportapp.com/docs/quote/pull/option-quote)、[期权到期日列表](https://open.longportapp.com/docs/quote/pull/optionchain-date)、[按日期查询期权链](https://open.longportapp.com/docs/quote/pull/optionchain-date-strike)。

### 可补充的数据源

- IBKR 插件已通过只读请求验证可搜索 CRWV、ORCL、PDD、SOXL 的美股合约，查到期权到期日/行权价/合约 ID，并返回期权快照。实测结果和限制见下方“IBKR 插件实测”。本次未读取账户数据，也未创建交易指令。
- 插件响应为 `FROZEN` / `FROZEN_DELAYED`，未证明当前可获得实时行情；股票快照没有返回所请求的 bid/ask，期权快照虽返回 bid/ask、部分 Greeks 和 OI，但 IV 字段无效、期权成交量字段缺失。因此在正常交易时段复测并确认行情订阅之前，IBKR 插件只能作为合约发现与行情字段可用性探测，不能作为实时执行报价或完整波动率分析来源。
- 若后续确认 IBKR 的 Web/TWS API 许可和相应市场数据订阅，可将其作为 bid/ask、Greeks 和期权链的优先候选；官方文档说明市场数据需已授权 session、brokerage session 和相应行情订阅。账户数据不属于本只读行情采集器范围。
- SEC EDGAR `data.sec.gov` 提供公司 filings submissions 与 XBRL company facts 的公开 JSON API，不需 API key；适合 8-K、10-Q/10-K、6-K/20-F 等正式披露的事件触发与财务事实核对，不是媒体新闻流。来源：[SEC EDGAR APIs](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)。
- 公司新闻稿/财报发布以发行人 Investor Relations 页面为一手源，并记录发布时间和原文链接。若之后要聚合媒体 headlines，再选有明确 API、授权范围、延迟说明和费用的新闻供应商；当前工作台没有找到已接入的财经新闻 API。

### IBKR 插件实测（2026-10-26）

- 请求窗口：2026-10-25 18:26–18:27 UTC（上海时间 2026-10-26 02:26–02:27）；当时美国市场为周日休市。工具响应未提供独立的抓取完成时间字段，记录的抓取时点为发起请求时间。
- 合约搜索均成功，并按美国主上市及完全匹配 ticker 选中：CRWV `771759702`（NASDAQ）、ORCL `272800`（NYSE）、PDD `326398585`（NASDAQ）、SOXL `73340487`（ARCA）。四者均返回 `OPT` section。
- 四者均返回到期日列表；最近到期日为 2026-10-30。按现价附近抽取该到期日的 call/put 后，均能返回合约 ID、到期日描述、行权价及 `SMART` exchange。
- 股票快照请求字段 `bid_ask`、`last`、`prior_close`、`volume`、`open`、`high`、`low`、`top_status`。四只均返回 `last`（含 `price`、`ts`、`halted`、`is_close`）、前收、成交量、开高低及状态；四只都未返回所请求的 `bid_ask`，状态均为 `FROZEN`。`ts` 是 Unix 秒时间戳；响应例值对应 2026-10-23 UTC。CRWV 返回的 `last=53.95` 低于同一响应的 `low=54.01`，该字段组合存在内部不一致，需复测。
- 期权快照请求字段 `bid_ask`、`last`、`option_volume`、`option_open_interest`、`option_midpoint_iv`、`option_greeks`、`top_status`。所抽取的 8 个合约快照状态均为 `FROZEN_DELAYED`，返回 `last` 与 Unix 秒 `ts`、bid/ask 及数量、`option_open_interest`（同时含 call/put interest）、IV 对象和 Greeks 对象。多数样本有 delta/gamma/theta/vega/option_price；PDD call 的 Greeks 对象为空。所有样本的 IV `isValid=false`，`dailyIv=-1`、`annualIv=-15.8745`，应视作无效值。8 个响应都没有 `option_volume` 字段。
- CRWV call 首次快照调用返回内部错误，单次重试成功。请求均为行情/合约读取；未调用账户余额、持仓、账户摘要或任何交易指令工具。
- 结论：插件连通性、合约发现和部分期权报价字段已验证；当前休市时返回冻结/延迟状态，未验证实时性、市场数据权限、盘中延迟或行情连续性。下一次应在美国正常交易时段对相同标的复测，并核对状态、报价时间戳、bid/ask、IV/Greeks 完整性及 option volume。

## 数据源充分性结论（阶段 1）

**结论：目前可支持标的研究和候选合约发现，尚不足以支撑有新鲜报价依据的周度交易评估或自动生成完整快照。** SEC/IR 可以支撑正式披露核对；主要短板是当前没有经过盘中验证的单一行情源能稳定提供正股报价和期权执行/风险字段，组合资金与实际持仓数据也尚未进入数据输入。

| 分析需要 | 当前来源 | 充分性 |
| --- | --- | --- |
| 标的识别、期权到期日和行权价 | IBKR 插件；LongPort 期权链 API（尚未接入） | 合约发现已验证；IBKR 的完整链可按到期日与行权价查询。 |
| 新鲜正股报价 | IBKR 插件快照；LongPort 股票 Quote | 当前不足：IBKR 实测为冻结行情且股票 bid/ask 缺失；LongPort 账户权限和实时状态未核。 |
| 期权买卖价、IV、Greeks、成交量、OI | IBKR 插件快照；LongPort 期权 Quote | 当前不足：IBKR 样本有 bid/ask 与多数 Greeks/OI，但 IV 无效、成交量缺失；LongPort 文档字段有成交量/IV/OI，但没有 bid/ask/Greeks。 |
| 财务与正式公司披露 | SEC EDGAR；发行人 IR | 足以作为第一阶段的一手事实来源；SEC 提供 filings/XBRL，IR 补充公司公告和财报发布材料。 |
| 财报、除息、宏观日历和广泛新闻 | 发行人 IR；LongPort 文档所列日历/新闻 API | 目前仅能按需查证；LongPort API 尚未接入或验证，没有统一新闻聚合源。付费媒体源不是首阶段必要条件。 |
| 组合资金、持仓、成交及保证金覆盖 | 用户提供的台账/券商导出 | 市场行情源无法替代；现有分析框架仍需用户补充相关记录与投资约束。 |

### 阶段 1 的最小充分条件

1. 在美国正常交易时段复测 IBKR 插件；记录请求时间、响应 `ts`、市场数据状态和报价字段。只有确认状态为实时或已明确标注延迟、且时间戳新鲜后，才把该源用于当周价格判断。IBKR 官方状态代码区分实时、15–20 分钟延迟、冻结、延迟冻结和无订阅，必须将其写入数据质量标记。
2. 对四只标的至少抽样一个近价 call 和 put：需有 bid/ask、有效 IV、可用 Greeks、OI 和期权成交量。缺失字段应标为缺失，不能用 last 替代 bid/ask，也不能用本地计算值伪装供应商 Greeks。
3. SEC/IR 继续作为公司事件核验来源；行情快照旁记录来源、抓取时间、市场时段和延迟状态。
4. 组合级保证金/现金覆盖率与仓位集中度，等用户提供持仓、现金和风险约束后再算；本阶段不读取账户数据。

上述条件满足后，数据源足以支持只读的周度候选分析与情景比较；若 IBKR 盘中仍缺字段，则需再评估能否通过已授权的 IBKR Web/TWS API 获取，或另选能提供完整期权报价的合规供应商。完整媒体新闻流、自动交易和交易后券商同步不属于阶段 1 的必要范围。

## 建议实施方案

在工作台新建只读 CLI：`tools/investment-data/`，不改业务仓 API，也不接交易下单能力。

1. **Source adapters**：LongPort（现有股票报价 + 期权到期日/链/期权 quote）；SEC EDGAR（公司 submissions/XBRL）；IR 页面以官方 RSS/可稳定读取页面为准。IBKR 官方 Web/TWS adapter 仍作为可选第二阶段，须单独具备 API 许可和行情订阅；本次验证的是 Codex 插件能力，不能据此推定本地 CLI 已具备 IBKR API 接入条件。
2. **统一快照模型**：symbol、asset/option identifiers、contract multiplier、strike、expiry、bid/ask/last/IV/OI/Greeks（源有提供才填）、source timestamp、retrieved timestamp、market session、real-time/delayed/frozen、source URI、entitlement/error 状态。缺字段保持 null 并标明来源不支持，绝不以 last 冒充 bid/ask 或本地模型 Greek 冒充供应商值。
3. **组合驱动采集**：从本地私有的结构化组合文件读取 CRWV/ORCL/PDD/SOXL 及正股数量；本地报告 MVP 已生成 `.agents/local-config/investment-analysis/portfolio.json`，人工台账保留为可读入口。自动行情接入仍暂停；后续只查询持仓到期合约和用户请求的近月候选链，限制请求数与调用频率。
4. **输出和缓存**：本地生成 JSON 原始快照与 Markdown 周报；缓存/凭证放 `.agents/local-config/investment-data/`（Git 忽略），仓库只保存代码、脱敏样例和字段说明。所有报价带来源和时点。
5. **新闻与事件**：先收集 SEC filings、官方 IR 新闻稿、财报/除息日历；每条保留 source URL、published_at、collected_at、headline、内容摘要/事实片段。AI 总结必须链接回原始披露，不把摘要当事实源。
6. **安全边界**：LongPort / IBKR 凭证只通过 `.agents/local-config` 或环境变量读入，不复用业务仓常量、不输出日志、不提交；CLI 首阶段只读，不申请交易权限、不发订单。

## 阶段 1 验收标准

- 一条命令可为已登记持仓生成快照和周报。
- 每条实时数据有数据时间与抓取时间；延迟/无权限/空数据清晰标识。
- LongPort 报价字段缺 bid/ask/Greeks 时准确显示缺项，不生成虚假的执行价/风险数字。
- 期权合约身份、到期日、行权价、类型、合约乘数与 broker 链对得上。
- SEC/IR 事件保留原始链接与发布时间，可逐条回源。
- 凭证和用户本地持仓缓存不进入 Git；无任何交易写入/下单路径。
- 对无权限、限频、行情停牌、错误符号、行情过期和单一来源失败有可辨识输出。

## 需要确认的外部条件

4. 现有 `hr stock` 如何处理：迁移到有程序化授权的数据源，或停止维护；在确认前新采集器不复用其 StockAnalysis 内部 API。

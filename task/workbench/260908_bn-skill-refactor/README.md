# bn skill 族群交互化重构

## 背景

bn 族当前 3 个 skill：`bn-0001-knowledge-base`（189 行）、`bn-0101-creation-flow`（511 行总控）、`bn-0201-article-review`（74 行）。

2026-08-29 工作台完成 dev-flow 三阶段重构后，bn 族未同步：一个 511 行总控扛下整条链路，素材整理占着 `0001` 编号，步骤之间没有停下等用户的约定。

## 设计原则：内容线不是流水线

dev-flow 的阶段语义是「需求从方案到验证的生产阶段」，门禁靠命令和测试判定，可以全自动跑完。内容创作不是这个形态：

| | dev-flow | bn |
| --- | --- | --- |
| 阶段切分依据 | 技术分工（后端 / 前端） | 用户交互回合（选题 / 讨论 / 审稿 / 发布） |
| 门禁 | 命令跑通、测试通过 | 用户确认 + 检查项清零 |
| 默认模式 | 出方案后等确认，确认后可全自动 | 逐回合停，每步都要用户一句话 |
| 失败处理 | 报错回退，改代码重跑 | 用户说"这段不行"，改稿再来一轮 |
| 产物判定 | 文件存在且能编译 | 用户说"可以发" |

内容创作里 agent 无法自己判定好坏，质量判定权在用户手上。所以 bn 族按「用户在这一步说什么、agent 怎么接」组织，不是按「这一步生成哪个文件」组织。

## 阶段定义

| 阶段 | 交互动作 | 用户说 | agent 做 | 产物 | 停下等什么 |
| --- | --- | --- | --- | --- | --- |
| `00` | 选题 | "想写 XX"、"这个热点能不能写" | 读 playbook、查知识库、反问 1-3 个关键问题、选题排雷、定平台 | `02_topic_pool/TODO_YYYY-MM-DD_主题.md`；确认后建 `01_in_production/YYYY-MM-DD_主题/` | 用户认可这个选题和角度 |
| `01` | 讨论 | 聊角度、给反馈、说"这个点不够狠" | 出核心内容摘要七字段、走偏自查；确认后一次成稿，摊稿时点出拿不准的 1-2 处 | 核心内容摘要（写入正文选题判断区）+ `公众号文章.md` / `图文脚本.md` + `纯享正文.md` | 用户说"核心内容 ok" |
| `02` | 审稿 | "这段太 AI"、"这里不够狠"、"结尾收不住" | 先改不辩解、判一次性还是规则盲区、跑发布检查清单逐项附证据、每轮收敛不一次改十处 | `发布检查清单.md` | 用户说"可以发" |
| `03` | 发布 | "发吧" | 正文转微信 HTML、封面、调草稿接口、登记发布记录、目录移到 `07_published`；有反馈则复盘 | `media_id` + `03_data_review/发布记录总表.csv` + `复盘.md`（条件触发） | 推送前确认（不群发） |

阶段内动作顺序：

- `00`：接需求 → 查素材 → 反问 → 排雷 → 出选题卡 → 等确认
- `01`：定模式（强判断 / 事实流）→ 出摘要 → 走偏自查 → 等确认 → 一次成稿 → 摊稿
- `02`：接反馈 → 改稿 → 判是否规则盲区 → 沉淀规则 → 跑检查清单 → 等"可以发"
- `03`：确认 → 推草稿 → 登记 → 移目录 → 有反馈则复盘

## 交互规则（写进每个阶段 skill）

1. **一次最多问 3 个问题**。内容创作不是填表，问完就该给判断，不发问卷。
2. **每步结束必须停**。默认逐回合推进，用户没接话就等着，不自动往下跑。
3. **全自动模式**：用户说「直接做」「一路写完」时一次走完 `00`→`02`，但 `03` 发布仍需显式确认（类比 dev-flow 的 live 授权）。
4. **先给判断再解释**。用户抛想法时，agent 先说"这题能写 / 不能写，理由"，再展开。
5. **不辩解**。用户说某段不行，先改；改完再判断是否规则盲区。
6. **摊稿时点出拿不准处**。成稿交付要主动说"这两处我不确定，你先看这两处"，不甩一篇全文。
7. **每轮只收敛一个量级的问题**。审稿不一次改十处让用户重看全文。

## 职责边界

| 边界 | 规则 |
| --- | --- |
| 讨论 vs 成稿 | `bn-0101` 只对齐不落笔；没拿到"核心内容 ok"不得成稿 |
| 成稿 vs 审稿 | `bn-0102` 生成，`bn-0201` 判定与改稿；审稿不重写全篇，只改被点和被清单命中的地方 |
| 只整理 vs 生产 | `bn-tools-knowledge-base` 只输出知识库条目，不顺手产出文章或选题卡 |
| 只进草稿 vs 群发 | `bn-0301` 只调草稿接口，群发必须用户手动操作 |

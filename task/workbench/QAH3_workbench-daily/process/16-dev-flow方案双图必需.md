# dev-flow 方案双图要求 · 过程记录

- 时间：2026-11-08

## 做了什么

- 按用户要求，将业务泳道图与系统时序图设为所有开发方案的必需产物，并同步更新方案模板、设计细则及工作台日常任务索引。
- 2026-11-09，根据用户对实际方案图的反馈，进一步规定业务泳道图必须使用“纵向角色列 + 横向阶段行”的连续表格布局：每列对应一个实际角色/系统，列之间紧邻相接、共享边界、不留空隙；节点按责任归列，跨列箭头表达交接；补充失败分支、同角色节点和阶段行的布置规则。此次在大转盘方案中按该标准重画并目视检查。

## 得到的结论

- 图示必须覆盖本次真实角色、系统边界和交互；简单需求可以缩小图的规模，但不省略两张图，也不虚构参与方。业务泳道图采用纵向角色列、横向阶段行，列之间连续相接且无空隙，不再使用自由布局网络：`.agents/skills/dev-flow/references/00-plan/solution-template.md`、`.agents/skills/dev-flow/references/00-plan/design.md`。

## 被推翻的判断

- 简单 MVP 与局部改动可以不画图 → 用户明确要求两类图都改为必画，原模板的按需规则已移除：同上。
- 泳道只需按责任方分区、列间可以分离且布局可自由组织 → 用户指出泳道应是角色分列且连续的多列表格；已明确列间无缝、共边界及跨列交接规则。

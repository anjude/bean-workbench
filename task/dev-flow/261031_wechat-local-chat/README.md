# 261031 本机微信聊天读取与总结

## 背景

用户希望直接使用本机微信数据，按群聊、联系人、关键词和时间范围查找消息或做总结；明确不使用窗口操作或 MCP。此前定位到微信 4.x 消息分片，但数据库加密，且 shell 中尚无可用读取 CLI。

## 需求理解

沉淀一套可重复执行的本机读取与总结流程。查询应只覆盖用户点名的会话/时间；总结能回溯到发送者和时间；无法读取或分片缺失时如实报告，不把部分数据说成完整结果。

## 目标

建立可复用的本机微信聊天查询流程，让用户按群聊、联系人、关键词和时间范围请求查找或总结，并让结果可追溯到实际消息。

## 范围

- 工作台 skill：`.agents/skills/wb-wechat-local/SKILL.md`。
- 本机查询包装器：`.agents/skills/wb-wechat-local/scripts/query.sh`。
- 工作台路由与清单：`.agents/README.md`、`AGENTS.md`、`.agents/skills/wb-router/SKILL.md`、`task/registry.md`、`task/dev-flow/README.md`。
- 本机数据源探测：微信 4.x `db_storage` 消息分片；仅按请求做只读定向查询。

## 边界

- 不操作微信窗口，不使用 MCP 或第三方聊天导出服务。
- 不自动安装解码器，不自动提取密钥，不更改微信签名或系统权限。
- 不把聊天正文写入工作台或持久明文导出文件；查询结果仅供当前请求使用。
- 不改动微信应用或业务仓。

## 实施方案

1. 由 `wb-wechat-local` 承接后续查询，总结前先解析用户给定的会话和时间条件。
2. 本机准备可用的只读读取工具后，先确认工具版本、账号数据目录与分片覆盖，再用其会话/联系人索引解析目标。
3. 使用工具自身支持的只读查询按会话与时间过滤；数据量大时分页，保留发件人、时间、消息数和覆盖范围等证据。
4. 在当前对话输出结论和必要的短引文，不另存明文副本，不把原始正文交给其他服务。
5. 若初始化需要特权访问、读取进程内存或修改系统权限，先明确说明具体动作；本 skill 不自动运行初始化。

当前读取器基于公开 `wx-cli` 源码构建，版本 `0.6.3`、源码提交 `077a54cbfe679bda963cd038d8440422907fc797`；二进制和私有配置保存在 `.agents/local-config/wechat-reader/`，不进入 Git。`query.sh` 限制为只读查询命令，并在查询后停止 daemon、清除解密缓存。

## 验收标准

- 用户说出群名/联系人、关键词或时间范围时，自动路由到 `wb-wechat-local`。
- 查询只覆盖点名的会话和时间；“最近七天”报告实际起止日期。
- 每份总结都说明消息覆盖范围；关键结论可追溯到发送者/时间或短引文。
- 无读取器、目标重名、分片缺失或解码失败时，说明具体缺口，不编造总结。
- 不调用窗口操作、MCP、第三方聊天服务，不在工作台持久化明文聊天内容或密钥。

## 验证与交付

- 尝试运行 skill-creator 的 `quick_validate.py`，因系统 Python 缺少 PyYAML 未能启动；已手动检查 frontmatter、skill 名称、路径引用和占位符。
- 本机数据库只检查了路径、文件名和文件头，没有读取消息正文。
- 首次读取器与密钥准备仍未完成，故本任务当前可交付的是流程规则；下一次实际总结需先完成本机读取准备。

流程、CLI 和清理包装器已配置；本机微信 4.x 有 27 个加密数据库分片。首次非提权 LLDB 捕获未获得密钥；当前执行环境没有免交互 sudo，需用户在本机 Terminal 执行一次密钥扫描后，才能验证分片覆盖并查询群消息。

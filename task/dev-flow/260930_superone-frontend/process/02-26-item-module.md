## 本轮实现

- 首页物品面板接入 Superone rail/swiper 和底部「添加物品」主操作。
- 实现分页列表、下拉刷新、空态/错误态、单选分类与状态筛选；列表请求使用空 `keyword`，不增加搜索框。
- 实现物品新建/编辑页：名称、分类、状态、价格、图片上传、开始日期、Markdown 描述。
- 实现物品详情：基础属性、编辑/置顶/删除、提醒设置与清除、Topic log 的新增/分页/回看/删除。
- 日志使用既有 `TopicType.Item` 和 `topicApi`；提醒日期在小程序端请求订阅消息授权，失败时仍保存提醒设置。
- 拒绝/无法获得订阅授权时仍保存提醒字段，并提示“提醒已保存，未授权通知”。模板 ID 与 backup、后端同步逻辑一致。
- 修正后端 Item 提醒消息默认进入路径为 `/pages/item-detail/index?id={itemID}`，并修正通用 Item 提醒处理器未传 `enterPage` 时的默认路径；提醒消息因此能打开新物品详情而非已下线的 backup 页面。
- 复用 `--so-*` 令牌、`so-page`、`so-custom`、`so-card`、`so-timeline` 与现有 Markdown/上传工具；未复制 backup 或 Carbon 样式。

## 取舍

- 无关键词搜索框；分类与状态各为单选筛选。
- 不做列表“提醒临近”装饰、不做标签编辑、不迁移 demo 数据初始化与单独的“移至最前”操作。
- Item 的新建/更新/删除、分类、日志与订阅均复用当前已有契约；没有扩展接口字段或 OpenAPI schema。仅调整后端提醒跳转目标。

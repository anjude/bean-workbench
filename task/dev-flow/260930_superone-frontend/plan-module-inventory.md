# 计划模块功能清单与设计提案

> 状态：待豆哥决策。本文件只梳理 backup 能力并提出设计方向，不代表迁移范围已确认。
> 输入：`business-repo/uni-superone-backup` 的 plan 页面、组件、store 与 composable；Superone 当前首页和 plan 契约；Carbon 首页及功能页结构。

## 1. 当前基线

- Superone 首页已经有「计划」模块位和「新建任务」底部主操作，但该模块仍由占位组件承接。
- Superone 前端已经消费生成的 plan 契约：近期任务与目标（Goal/OKR）各有列表、详情、新建、更新、删除接口；不需要为已覆盖的 CRUD 另造一套请求。
- backup 的计划页有两个子页签：**近期任务**、**OKR 管理**。近期任务按状态筛选，OKR 按年份和年度/季度筛选。
- backup 的任务与目标详情都挂有日志时间轴。日志复用 topic log 能力，迁移时应确认 Superone 已有 topic log API 能否按对象类型和 ID 直接复用，不把它误当成 plan CRUD 的一部分。
- Carbon 可借鉴的是首页模块切换、内容滚动区、状态组件、令牌化样式和克制的信息层级；Superone 保持自身 `--so-*` 主题、品牌色、`so-page` 页面门禁与现有字体/组件体系。

## 3. 页面与交互方向

### 计划首页模块（仅近期任务）

- 延续 Superone 首页既有形态：左侧 rail 选择「计划」，计划内容放在当前 swiper 模块内；保留首页底部栏的「新建任务」主 CTA，由模块 `open()` 接收并打开任务编辑流程。
- 计划模块直接呈现近期任务列表，不再设置「任务 / OKR」子切换。
- 列表顶部放状态筛选；不要把筛选控件堆进首页全局导航。
- 任务采用易扫读的列表行或轻卡片，优先标题、状态、优先级与截止日期等决策信息。置顶只用小标记；不把每条记录做成信息密集的大卡片。
- 空、加载、错误、刷新中、加载更多各自沿用 Superone 三态组件与分页约定；无数据时提供对应的「新建任务」或「新建 OKR」入口。

### 任务详情

- 采用 Superone `so-page` 详情页骨架：任务标题与元信息在上，描述为主体，进展日志（若采纳）作为后续区块；页面只保留一项明确的主操作。
- 任务详情主操作建议为状态推进或编辑二选一，底部/标题操作不同时争抢视觉重心；优先级、截止日期与逾期状态以小型标签/属性行呈现。
- 进展日志若纳入，复用 topic 已有日志编辑/展示能力与 `so-timeline` 方向（确认组件已存在或在相邻任务中落地），统一线性时间顺序和分页/失败反馈。
- 新建与编辑复用一套任务表单页，字段保持精简。

## 4. Carbon 参考边界与 Superone 视觉落法

| 借鉴 Carbon 的产品/工程做法 | 在 Superone 的落点 | 不直接照搬 |
|---|---|---|
| 首页 rail + swiper + 懒挂载模块 | 已有 Superone 首页骨架，计划作为 rail 模块内容接入 | Carbon 的空间语义、暖色品牌、消息红点 |
| 每个模块有自己的滚动区、刷新和分页状态 | 计划列表内维护状态，刷新/分页协议沿用当前 Superone 模块约定 | backup 两套分页状态、页面级与 scroll-view 混用刷新 |
| 页面职责清楚、详情围绕单对象组织 | 任务/OKR 详情各自承载对象信息和后续动作 | Carbon 落地页式 hero、eyebrow、大标题装饰层 |
| 空/加载态沿用共享状态组件；CSS 变量控制主题 | 使用 Superone 现有 `so-loading-state`、`so-empty-state`（若已可用）及 `--so-*` 令牌 | Carbon `cu-*` 组件名、`--cs-*` 令牌或复制整套样式 |
| 克制布局与一致间距 | 列表行、清晰分组、轻量边界；颜色服务状态识别 | backup 的硬编码颜色、堆叠阴影和重复卡片壳 |

## 5. 实施拆分建议（待功能决策后细化）

1. **P0 模块入口与读取**：计划 tab 内近期任务列表、状态筛选与空态；依赖已有 recent task list/detail 契约。
2. **P0 核心写入闭环**：任务新建/编辑/删除；所有异步操作具备提交态和失败回退。

4. **P1 进展记录**：任务日志按 topic log 能力接入；先核对对象类型约定与跨模块删除行为。
5. **P2 扩展**：无；任务复制不迁移，快照按 backup 原义记为任务日志。

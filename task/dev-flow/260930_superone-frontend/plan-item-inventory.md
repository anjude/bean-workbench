# 物品模块功能清单与设计提案

> 状态：本轮范围已按 2026-10-06 的指示落地；type-check、构建与真机验收尚未执行。
> 输入：`business-repo/uni-superone-backup` 的物品列表、详情、编辑页与数据逻辑；当前 `uni-superone` 首页和 Item 契约；`uni-carbon-space` 的首页模块、详情页与 UI 规范。

## 1. 当前基线

- Superone 首页已经预留「物品」面板和「添加物品」底部主操作，当前页面仍是占位内容。
- `uni-superone/src/contracts/` 已有 Item 的列表、详情、新建、更新、删除、分类列表契约；契约字段包含分类、状态、标签、开始时间、描述、图片、价格、提醒信息和置顶值。
- backup 的物品能力由列表、详情和编辑三个页面组成。详情还包含提醒编辑、使用日志；物品日志通过通用 topic log 体系读取和写入。
- 需要特别核实日志 `topicType` 对 item 的支持、订阅消息能力与提醒触发链路；当前只凭前端 backup 不能认定这些在新前端可直接复用。
- Superone 的页面骨架和 `--so-*` 主题是本次落地基线。Carbon 只提供模块组织、层级与组件交互的参考，不直接复制其空间品牌样式。

### backup 的数据语义

- 分类：默认、电子产品、服饰、图书、家居、运动、美妆、食品、工具、其他（最终以共享契约/后端枚举为准）。
- 状态：使用中、闲置、损坏、丢失、已出售、已赠送、已回收。
- 列表排序：置顶项优先，再按创建时间；长按“移至最前”与置顶不是同一个交互含义，需决策是否保留两种操作。
- 价格在当前 Superone 契约以字符串表达，适配后端 decimal；前端展示和表单校验不应假设为整数。
- 提醒和日志虽出现在 backup UI 中，但实现依赖系统订阅消息与通用日志类型，不能仅根据 item CRUD 契约推断其已完整接通。独立的订阅消息列表/配置页面不迁移；物品提醒所需的微信订阅授权、Item 更新后的服务端订阅同步和提醒消息跳转属于物品功能范围。

## 3. 页面原型与结构建议

### 原型判断

- 首页物品面板是轻量 **dashboard/list**：用于浏览和快速定位资产，不在面板内承担复杂编辑。
- 物品详情是 **detail**：围绕单件物品展示属性和后续操作。
- 新建/编辑是 **config/form**：以字段输入和明确保存为主。

### 首页「物品」面板

- 沿用 Superone 首页 rail + swiper 模块、模块独立滚动区和底部主 CTA；`open()` 打开新建表单。
- 列表建议用紧凑行/轻卡片：小图或分类图标、名称、分类与状态、可选价格；提醒仅在采纳 IT-11/12 时以低干扰次级信息显示。
- 分类/状态/搜索控制最多选一到两种作为列表顶部工具，避免同时堆满筛选条。它们需按决策范围启用，不从接口支持反推产品必须有入口。
- 置顶小标记即可；行操作优先通过长按 actionSheet 或详情页完成，避免每行常驻多个按钮。
- 支持首次加载、空列表、列表刷新、失败重试、分页/无更多（如确认后端列表分页语义）、图片失效等状态。

### 详情页

- 使用 Superone `so-page` / `so-custom` 页面骨架：顶部标题与图片，接着名称和少量核心属性，再按区块展示描述及（若采纳）提醒、使用日志。
- 首屏突出名称、状态、分类；价格、开始时间、创建/更新时间作为次级属性，不做一张塞满所有字段的大卡片。
- 操作收敛为编辑与更多菜单；置顶/删除等次级操作放在更多菜单或短操作行，删除需二次确认。
- 若有日志，日志时间轴单独成区；输入放在明确的新增入口，不让编辑器长期占据详情首屏。

### 新建/编辑表单

- 新建和编辑共用一页，必填字段优先为名称、分类、状态；价格、图片、开始时间、描述作为可选字段。
- 将低频字段分组或折叠，底部固定一个保存主操作；提交中禁用重复提交，失败保留用户输入。
- 图片上传、Markdown 编辑、日期选择器只有确认纳入对应功能后才加入，避免首版表单变成配置面板。

## 4. Carbon 与 Superone 的设计取舍

| 参考原则 | Superone 落法 | 不直接照搬 |
|---|---|---|
| 首页模块切换与内容区域边界清楚 | 接入已有 rail/swiper，模块内独立滚动与刷新 | Carbon 的关系空间语义、暖色品牌与提示红点 |
| 信息分层靠留白、轻表面和一致间距 | 使用 `--so-*` 令牌、状态小标签、分隔线/轻边界，按物品浏览效率组织信息 | Carbon 的 `--cs-*` 变量、`cu-*` 组件及整套样式 |
| 详情页围绕一个对象组织内容 | 单件物品头部、属性、描述、可选提醒/日志分区 | 装饰性 hero、eyebrow 大标题与关系叙事 |
| 空态友好、操作克制 | 空列表提供单一「添加物品」主 CTA，详情避免多个同权按钮 | 低照度光斑、磨砂层、呼吸动画等 Carbon 品牌表达 |
| 组件和状态反馈一致 | 沿用 Superone 已有三态组件、错误重试与请求反馈 | 不复制 Carbon 中已有实现细节或类名 |

## 5. 最小状态矩阵

| 场景 | 界面表现建议 | 回退/动作 |
|---|---|---|
| 首次进入且正在加载 | 轻量 loading，不先闪空态 | 保持页面结构 |
| 服务端无物品 | 空态说明 + 添加入口 | 可直接进入新建 |
| 有物品 | 列表按选定排序展示 | 点行进入详情 |
| 刷新/筛选/分页请求中 | 保留已有内容，局部显示进度 | 防止重复请求 |
| 列表或详情请求失败 | 错误提示与重试 | 已有数据时保留旧内容 |
| 新建/编辑提交中 | 保存按钮显示提交态并禁用 | 避免重复提交 |
| 保存失败 | 保留表单内容并展示可理解错误 | 用户可修正或重试 |
| 删除确认/删除失败 | 二次确认；失败不移除本地记录 | 取消或重试 |
| 图片缺失/加载失败 | 显示分类默认图标 | 其余信息照常展示 |
| 提醒或日志部分不可用 | 对应区块提示不可用，不阻塞物品详情 | 需结合最终迁移范围确定 |

## 6. 已知接口与待核实依赖

- 当前 Item 前端契约已有 list/detail/create/update/delete/category list。是否需修正分类枚举、分页参数默认值或当前契约与 backup 期望的差异，开发前需与 `backend-superone` DTO 对照。
- 提醒字段已在 ItemDetail/Create/Update 契约中；Item 更新会由后端同步订阅记录，并由现有消息任务触发。物品提醒默认进入路径必须使用当前 Superone 详情路由并携带 item id。
- 物品日志复用 topic log：需确认 `topicType` 枚举有 item 类型、读写/编辑/删除所需 API 在当前契约齐全，且物品删除时日志如何处理。
- 图片上传服务需确认当前 Superone 可用的上传 API 与权限；不应直接搬运 backup 的上传工具或硬编码身份数据。
- 开发落点预计在 `business-repo/uni-superone/src/pages/index/index.vue`、`src/components/business/`、`src/pages/`、`src/composables/`、`src/contracts/`；待你确认功能后再细化文件级方案。

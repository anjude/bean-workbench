# 261009 鹅懂个啥小程序初始化

## 目标

建立「鹅懂个啥」独立小程序的开发上下文，先完成产品定位、初始化方案与品牌图片归档，再开展项目初始化。

## 产品定位

- 名称：鹅懂个啥。
- 体验：开心玩，顺便认识自己。
- 内容方向：趣味测试（包括类似 MBTI 的性格玩法）、小游戏，以及解决日常选择和多人活动需求的实用小工具。
- 品牌形象：一只好奇、爱玩、也不装懂的鹅；产品表达保持轻松，不使用沉重的自我定义叙事。
- 长线愿景：借有趣的测试与互动，让人更理解自己和他人的相处方式，愿意走近彼此、互相接受；爱情是其中一个方向，不将产品限定为恋爱测试。

## 小程序介绍

> 鹅懂个啥？和一只好奇的鹅测测性格、玩玩小游戏，顺手解决日常小纠结。先开心起来，再发现一点新鲜的自己。

## 体验设定

- 核心顺序是先玩得开心，再从测试或游戏结果里得到一点关于自己的新发现。
- 2026-10-10 鹅BTI 首次实际体验反馈：用户认为「小现场 + 凭第一反应选择」有代入感；后续测试可沿用这种场景化表达，但应设计各自的情境主题、节奏与结果，不把不同测试做成同一题库的换皮。
- 趣味测试、小游戏和实用小工具是并列产品模块；品牌名称与主视觉不绑定单一玩法。
- 工具模块强调轻量、即开即用，解决个人选择或多人活动中的小需求，不包装成测试结果，也不要求每个工具都具备游戏化流程。初步候选包括大转盘、今天吃什么、深圳去哪玩、团建摇骰子、麻将记分；仅为候选，不代表首发顺序或已确认范围。
- 当前对外只使用「趣味测试」等表述；原计划的抽签类玩法暂不纳入当前产品范围，后续若恢复须按实际功能重新评估平台规则和类目。
- 「帮助全人类认清自我」「SI 时代迷失、找不到意义」是讨论产品时的玩笑式背景，不作为严肃的产品使命或对用户的承诺。
- 面向用户的文字保持轻巧、好奇、有幽默感；吉祥物以「懂个啥」的自嘲口吻陪用户探索。

## 产品模块扩展（2026-10-10）

- 后续产品结构由「趣味测试 + 小游戏」扩展为「趣味测试 + 小游戏 + 实用小工具」三个并列模块；首页应能承载三类内容入口与持续扩展。
- 实用工具按「功能」与「主题」两层规划：功能是可复用的工具能力（例如大转盘、摇骰子、麻将记分）；主题是某个功能承载的具体场景与选项内容（例如大转盘的今天吃什么、深圳去哪玩）。大转盘首期范围与实施记录见本文末。
- 工具模块的品牌表达保持鹅懂个啥的轻松调性，价值以快速解决问题为主；与测试的自我探索、游戏的娱乐挑战保持清晰区分。
- 首发功能为「大转盘」，第一期上线三个主题：「今天吃什么」「深圳周末去哪逛」和「周末玩点啥」。前者覆盖日常饮食决策；第二个提供深圳周末去处；第三个从 100 件低门槛小事里给个人或朋友提供周末灵感。
- 「今天吃什么？鹅转一圈就知道。」作为首发主题的主文案候选，直接点明吃饭决策；「别再说随便，鹅来拍板」可作为副文案。产品传播重点可围绕多人共同决策、转动反馈、鹅式结果文案和结果分享设计。
- 只有「深圳周末去哪逛」绑定深圳；「今天吃什么」与「周末玩点啥」使用大众通用内容，不读取城市或定位。吃覆盖日常正餐、地方菜系和小吃甜品；玩覆盖轻松独处、朋友同乐、在家动手、出门体验四类。
- 后续若接入后端，可向候选接口传入用户选择的地点，由接口返回该地点的特色美食/活动；当前首版仍用通用静态候选，不提前绑定城市。
- 传播判断目前是产品假设，不是已验证的趋势结论。公开搜索可见「今天吃什么」已有不少转盘/决策工具，通用转盘本身同质化较高；差异应来自多人“都行”场景、鹅的品牌表达和可转发结果。小红书官方热点榜说明其热点根据站内真实搜索和互动变化，运营选题应在发布前看实时榜单，而不是预设某主题必然热门（[官方热点榜说明](https://fe.xiaohongshu.com/ditto/vincent/c45978d1a53d4dec963167ebd6f1802e?fullscreen=true&naviHidden=yes)）。
- 当前小程序的注册主体和服务类目仍需结合实际功能整体评估。新增工具不自动解除现有测试/游戏的类目准入问题，申报范围必须与实际功能一致。

- 「鹅懂个啥」以趣味测试、结果展示和内容导航为主体，技术上拟复用 uni-app 页面框架，优先按普通小程序规划。

- 注册形态建议不解除个人主体类目的准入卡点：当前不应为了上线测试功能而选择不匹配的服务类目。

### 页面与状态

- 原型：沉浸式单页游戏，首页小游戏卡片是唯一入口。

## 应用启动数据门禁

- 需求：gknow 与 uni-superone 一样，在应用启动时取得用户数据和系统数据；两项数据都成功后才展示任何页面内容。现有页面统一由 `gk-page` 包裹，它作为本产品对应 `cu-page` / `so-page` 的门禁容器，等待态和失败重试也由容器呈现。
- 请求顺序：先确保微信登录并取得可用 token，再并发请求 `userApi.getUser()` 与 `commonApi.getSystemInfo()`；任一失败则保持页面门禁关闭。遇到登录过期，清理 token、重新登录并重试一次。
- 数据归属：在 `src/stores/app.ts` 保存 `userInfo`、`systemInfo`、`ready` 与错误状态；`App.vue` 负责启动时初始化，`gk-page` 为页面挂载提供幂等兜底。不给页面各自重复请求用户和系统数据。
- 影响文件：`src/utils/adapt/login.ts`、`src/utils/auth.ts`、`src/utils/request.ts`、`src/stores/app.ts`、`src/App.vue`、`src/components/gk-page.vue`、`AGENTS.md`、`README.md`。
- 验收：`ready` 只有在用户与系统数据均有值时才变为真；加载中和失败时不渲染页面 header/主体；失败页可以重试；运行 `npm run type-check` 与 `npm run build:mp-weixin`。

## 管理员专用品牌内容海报与贴图生产工具（方案待确认）

### 背景与需求理解

- 目标是给「鹅懂个啥」官方运营者提供内部内容生产工具：管理员输入虚拟情景、对话文字并提供/选择图片，按品牌视觉生成可发布的内容海报，再使用微信小程序当前可用的图片转贴图能力生成贴图内容，用于贴图号起号；同一内容可导出小红书笔记图片与配文，供官方账号人工发布。
- 这是官方内容生产能力，不向普通用户开放，不做用户截图编辑器、公开投稿、用户内容社区或真实聊天记录仿制器。
- 方向以「虚拟情景演绎」为前提；内容按创作作品呈现，不包装成真实恋爱经历或真实私聊证据。

### 本期目标与边界

#### 本期目标

- 管理员从设置页进入单一内容创作页，填写主题/标题、情境引子、对话内容、角色图片与发布文案。
- 使用「鹅懂个啥」自有色彩、字体层级、角色元素和版式生成海报预览；图片支持从项目品牌素材选择或从本机相册选取。
- 一次创作提供贴图号用图片与小红书用竖版图片两个导出选项；可复制小红书标题/正文/话题，手动发布。
- 贴图导出调用用户已确认可用的微信图片转贴图能力；同时保留保存到相册作为失败或后续人工处理的回退。
- 首版内容在本机编辑和生成，不上传内容、不存用户数据、不增加后端、数据库或共享契约。

#### 本期不做

- 不给普通用户开放创作入口，不允许用户公开投稿或浏览其他用户作品。
- 不调用小红书发布接口、不自动登录或代发笔记；不将小程序码、站外联系方式或诱导话术强行塞入小红书图片/文案。
- 不做聊天截图仿真，不伪造聊天软件 UI、时间戳、头像身份或真实经历。
- 不做云端内容库、多人协作、发布排期、审核后台、数据分析看板和生成式 AI 写文案。
- 首版不承诺自动批量发布或批量生成；以单条内容的快速生产和人工校对为准。

### 产品原型与操作流程

- 原型：单内容的沉浸式编辑页（detail/editor）。管理员围绕一条内容完成编辑、预览、导出，不在同一页叠加内容看板或内容流。
- 入口：现有设置页「管理员工具」增加「内容海报与贴图」入口；非管理员不显示入口，直接访问目标路由时也显示无权限回退并返回设置页。
- 编辑字段：内容标题、情境说明（可选）、对话段落（至少 1 段，首版最多 6 段）、角色/场景图片、品牌署名、贴图号发布短文案、小红书标题/正文/话题。
- 主要 CTA：`生成预览` → `转为贴图`。次要 CTA：`保存贴图图片`、`生成小红书版`、`复制小红书文案`、`重新编辑`。
- 生成前有“虚拟情景演绎”标识预览，可见品牌署名与内容审核提示；不把虚构内容伪装成截图。
- 生成后预览目标版式，管理员确认后再调用微信贴图能力；小红书版本为独立构图，不直接拉伸贴图图像。两种图片尺寸/格式应在开发前按账号实际贴图入口和小红书当前发布要求确认，避免在方案阶段臆定平台规格。

## 大转盘首期方案（方案已确认，阶段 02/03 已完成；后续交互调整见落地记录）

### 需求理解

实用工具模块首发一个可复用的「大转盘」功能，内置三个并列主题：①「今天吃什么」；②「深圳周末去哪逛」；③「周末玩点啥」。选项由官方预置并允许用户编辑，不面向管理员内容运营后台。核心价值是让个人快速做小决定，或让朋友/同事把结果发到群里共同决定。

### 目标与边界

- 本期从首页「实用工具」进入大转盘主题选择页；用户先选择具体意图，再进入对应转盘详情。
- 吃什么提供日常正餐、地方菜系、小吃甜品等通用内容池；周末去哪逛固定提供深圳各区地点，并按片区、室内/户外、轻松散步/徒步、公共空间/需购票等条件筛选。
- 三个主题首次进入都默认全选官方候选；周末玩点啥提供 100 件小事，按轻松独处、朋友同乐、在家动手、出门体验筛选，每项附耗时、花费和适合人数参考。此后以本地缓存为准，不覆盖用户自己的勾选和自定义项。
- 结果卡展示主题/选项、片区或分类标签、成本/预约注意提示，支持再转一次、编辑选项和分享结果。
- 地点池、食物选项及标签见[《大转盘·首期主题与候选选项》](大转盘-首期选项清单.md)。地点营业状态、票价、预约名额、交通和活动均可变化，首版只给核验提示，不硬编码当天状态。
- 候选数据维持主题通用字段；未来按地点取特色内容时可在后端请求传 `location` 并返回对应候选，不要求当前前端写死深圳食物或玩乐池。
- 首版本地运行，不新增后端、数据库、共享契约、定位权限、地图导航、点评/订位或小红书自动发布。
- 小程序当前账号及类目准入仍要按实际产品和平台要求评估；新增工具不自动解决已有测试/游戏准入问题。

### 产品原型与交互

- 原型：工具主题选择（dashboard）进入单主题决策页（detail）。先选“今天吃什么”“深圳周末去哪逛”或“周末玩点啥”，详情页只呈现当前主题，不放多个主题切换控件；未来新增骰子、麻将记分等工具时，从工具入口增加对应意图。
- 首页「实用工具」卡片进入大转盘主题选择页；主题卡直接进入对应大转盘详情。设置页不增加工具入口。
- 主题选择页主 CTA 为具体主题卡；转盘页主要 CTA 为 `开始转`，结果出来后为 `再转一次`。编辑候选、筛选、全选和分享为次要操作。
- 候选项数量较多时，通过类别/片区/室内外等条件收窄编辑列表；已选候选跨筛选保留并共同参与转盘。用户自定义选项与勾选状态写入当前设备本地缓存，不写入服务端；“清空已选”只清勾选，不删除自定义选项。
- 首次进入时使用随版本发布的官方候选与默认勾选；此后以当前设备缓存的用户选择与自定义项为准，不提供恢复默认操作。
- 深圳地点结果卡展示行政区、出游类型、粗略时长标签和预约/购票核验提示；不使用设备定位推断用户位置。远郊地点标出“远郊/需规划交通”，市区与远郊可手动筛选。

- 不请求定位权限、不上传个人数据、不新增 API/表/契约；原有鹅BTI、游戏、设置页功能不受影响。

## 2026-10-15 鹅图鉴海报切换修复

- 背景：用户反馈鹅图鉴中只有第一个项目能生成海报，其余项目失败。
- 需求理解：图鉴复用同一个 `gk-result-poster` 实例；海报首次成功后 `posterPath` 一直缓存，后续项目打开时因缓存短路而不会按新项目重新绘制，导致各项目不能生成自己的海报。
- 目标与边界：项目切换后失效旧海报缓存并依据当前项目数据重新绘制；不修改图鉴记录、二维码接口和其他分享入口。
- 改动范围：`business-repo/uni-gknow/src/components/gk-result-poster.vue`（监听海报内容变化并清除预览缓存）；必要时仅调整 `src/pages/collection/index.vue` 的海报内容绑定；无数据库、接口或契约变更。
- 页面状态：首次打开生成中/成功/失败可重试；切换项目后显示新项目内容并重新生成；关闭后再次打开同一项目可复用已生成图；生成过程中的重复点击不重复绘制。
- 验收：先后从至少两个不同已解锁项目打开海报，标题、指标和小程序码均对应当前项目；重开同一项目不重复请求；类型检查与微信小程序构建通过。

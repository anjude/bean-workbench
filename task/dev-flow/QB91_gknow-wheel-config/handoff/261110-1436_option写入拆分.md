## 关键决策与原因

- option 写接口独立于 wheel update：因为几千项时服务端不应为单个修改读取整盘，且 wheel 元数据与 option 写入职责不同。
- 单条和批量共用 `MutateOptions` 事务：保证锁 wheel、版本校验、选项写入和版本递增只有一份实现。
- 批量接口只递增一次版本：避免一次导入触发数百次版本变化。
- `filter_first` 与 `direct` 并存：因为小转盘全量加载更简单，大规模地点必须先筛选再查询。

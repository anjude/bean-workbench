### 做了什么

- 在侧会话澄清用户核心目标为 BV 号输入、字幕输出，实现形式不限；只读检查本机硬件，查询 MLX 与 OpenAI 官方能力和费用资料。

- 具体方案与来源记录于 `../本地信息源工具方案.md`。

### 得到的结论与修正

- 从插件优先转为本地工具核心，原因是核心需求不依赖浏览器界面，原生 MLX 更值得在这台 Apple Silicon 机器上评估；已有插件作为历史实现与可复用素材保留。
- 不把旧浏览器 GPU 测试结果外推到原生 MLX；本地模型是否更快、更准确仍待实际测量。
- 平台采集、采集通道、内容处理与导出分层，避免每接一个平台重复实现转写与存储。

### 待核

- MLX 本机实际速度、峰值内存、准确度、时间轴和取消后的资源释放均未验证；未来平台的可获取范围也未验证。
- 本轮只新增交接与方案文档，未安装依赖、运行模型或修改实现。

## 2026-10-24 第 3 轮：本地工具与开源方案比较

### 做了什么

- 阅读最新 handoff 和已确认本地工具方案；按用户要求保持原 Chrome 插件交付并独立比较本地方案。
- 检查 yt-dlp B 站 extractor、MLX Whisper、whisper.cpp、faster-whisper、SenseVoice 与 VideoToNo 的公开实现和文档。
- 汇总判断与建议边界至 `../handoff方案调研.md`。

### 得到的结论

- 本地程序更适合作为长期批量来源库，插件适合作为并存的快速采集入口；插件源码与交付不应因此删除或重构。
- Python + SQLite + 本地文件 + CLI/网页共享核心方向合理；首版应只兑现 B 站、持久化队列和统一导出，避免先做宽泛的平台插件框架。
- yt-dlp 的 B 站字幕映射包含弹幕项，且明确处理登录可见字幕；适配层必须过滤弹幕并区分字幕缺失与权限不可见。
- MLX Whisper 是 Apple Silicon 上的优先实验候选，但公开仓库不能证明本机速度和准确率优于浏览器扩展；需要同一音频实测 MLX 与 whisper.cpp Metal。

### 待验证

- 本机 MLX large-v3-turbo 和 whisper.cpp Metal 的真实速度、内存、中文专名准确率与取消行为。
- yt-dlp 当前版本对目标公开视频和平台字幕的实际行为；需要单视频纵向闭环验证。

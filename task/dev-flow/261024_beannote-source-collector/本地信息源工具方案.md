## 目标与首版边界

建设可扩展的本地信息源收集工具。首版输入 BV 号或 B 站链接，获取字幕和来源信息；后续逐个平台接入其他视频、公众号文章、小红书图文与评论。未来平台和评论能力属于扩展方向，不承诺首版实现或已验证可获取。

首版顺序：获取元信息 → 优先提取已有字幕 → 无字幕时获取音频并在本地转写 → 保存原始素材和处理结果 → 导出 TXT、SRT、JSON。支持批量输入、去重、进度、失败重试与取消。

## 实现形式与技术选择

- Python 核心程序，命令行先完成闭环，简单本地网页作为日常入口；两种入口共用业务逻辑。
- 本地网页服务使用 FastAPI，只监听本机；暂不开发原生 Mac 应用。
- SQLite 保存任务、内容索引、处理记录；本地文件目录保存原始响应、媒体和处理产物。
- 转写默认 MLX Whisper large-v3-turbo；首次下载权重，任务需要时加载模型，无需训练或常驻模型服务。
- 云端语音转写采用可替换引擎接口，首版保留扩展位置，不要求接入付费服务；默认不上传音频，后续云端调用须显式选择。
- 转写置于独立工作进程，首版一次执行一个本地转写任务；采集与下载由任务队列调度。
- 浏览器扩展保留为未来的页面采集与登录态辅助入口，不作为核心转写运行环境。已有扩展代码不在本次交接中删除或改造。

## 分层与扩展边界

```text
命令行 / 本地网页 / 未来浏览器入口
                 ↓
任务管理（排队、进度、重试、取消）
                 ↓
平台适配器（链接识别、平台 ID、元信息、正文、媒体、评论）
                 ↓
采集通道（网络请求 / 浏览器辅助 / 用户导入）
                 ↓
原始素材存储
                 ↓
通用处理器（字幕转换 / 语音转写 / 正文清理 / 图片 OCR）
                 ↓
统一索引与导出
```

- 平台适配器声明能力，例如正文、图片、音频、字幕、评论；不要求每个平台全部实现，界面根据能力展示操作。
- 平台获取与内容处理解耦：新增视频平台后可复用转写和字幕导出；新增图文平台后可复用正文清理和 OCR。
- 不为未来平台预先实现复杂插件框架；先通过 B 站闭环证明接口边界。

## 数据约定

- 来源：平台、原始 URL、平台内容 ID、标题、作者、发布时间、采集时间。
- 内容：正文、带时间轴的字幕片段、图片及说明、音视频附件；保留平台特有元数据。
- 评论：独立记录评论 ID、内容归属、回复关系、分页进度与采集范围。
- 处理记录：引擎、模型、处理时间、状态、错误与输出路径。
- 原始数据与处理结果分开；平台字幕、机器转写、人工修订分别保存，避免覆盖来源。
- 用平台与内容 ID 去重；重试复用已保存素材，支持更换模型后重新处理。
- 完整性显式记录为完整、部分、无权限、平台未提供等状态，不能把部分评论当成全部评论。

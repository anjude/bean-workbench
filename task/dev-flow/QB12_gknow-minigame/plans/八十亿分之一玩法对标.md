# 疯狂大鹅人生模拟对标方案

## 需求与范围

1. **补齐人生起点差异。** 出生地点按各国出生人数估算加权抽取；把统计资料用于抽取，不在玩家主流程展示数据来源或模拟免责声明。人物和家庭以具体、可玩的原创故事呈现。
2. **增加贯穿一生的内容。** 按年龄阶段出现年度故事和关键选择，选择能够改变后续机会、资源、关系或结局。
3. **支持完整人生体验。** 玩家可以逐年、快进或自动推进；决定出现时自动暂停；结尾回看一生与可重玩的起点。
4. **对齐 1in8B 的主要体验面。** 参照其随机出生、真实统计背景、年度事件、关键年龄停顿、自动推进、人生年表、结局回顾和重玩。多人同局、在线房间与响应其他玩家属于需要独立端到端设计的下一阶段。

**当前状态**　现有 Cocos Demo 有 4 个虚构国内家庭、13 个固定抉择、6 条通用随机事件、4 项属性、自动推进和结局。事件分布稀疏，起点没有出生概率依据；记录只展示最近 5 条，人生结局只列选择。

**已确定**　保留 Cocos Creator 微信小游戏工程和单人逐年模拟入口；游戏文案与人物原创，不复用参照游戏的文案、人物或素材。统计数据提供背景概率，不能呈现成个体预测。

## Cocos 玩法可行性验证（2026-11-09）

用户要求实玩 1in8b 并验证 Cocos 能否承载其核心循环。本轮只验证单人人生时间与抉择节奏，不复制原作人物、文字、图像或页面。

- 官方页面说明：玩家可暂停或倍速；约 30 分钟的人生对应每年约 20–30 秒，遇到选择可自动停下，也可开启自动抉择。[官方游戏说明](https://1in8b.life/zh-hans/)
- 实玩观察：出生登记先给出家庭与身份起点；开始后年龄、家人、人生记录同步变化。2 岁选择如何回应来客，5 岁形成“贴心”气质并在年表中回扣；6 岁出现“想养小狗”的选择。5 岁时另有可跳过的反思停顿。选择后能看到当场结果，决定不会只停留在按钮反馈。
- 当前 Cocos 实现沿用 `LifeDemo`、种子随机引擎和本机存档；人生从开始后以 1× 自动前进（每年 20 秒），支持暂停、1×/4×/8×/16×、跳到下个决定。重大决定出现时暂停，若玩家此前正在自动推进，选择后恢复原速度；手动暂停后做决定则保持暂停。
- 这是玩法节奏与 Cocos 调度能力验证，不代表已完成原作全量复刻。全球统计口径、地区对应内容、人物家庭、反思停顿、终局纪念馆等仍需分别设计；不以生成说明替代具体故事。

## 整体方案

1. **加入可追溯的国家统计基线。** 将世界银行 2023 年国家人口、粗出生率、预期寿命、PPP 人均 GDP 与城镇人口比例固化到客户端数据模块；按人口 × 粗出生率估算各地出生数并加权抽样。来源与估算方法保留在项目资料中，作为抽样依据，不直接灌入开局叙事。
2. **沿用确定性种子推进人生。** 年度事件、出生处境、人生长度都从同一局种子按稳定步骤取样；玩家的决定不会让无关年份重新抽签。
3. **扩充原创年度内容和分龄决策。** 事件表按年龄范围筛选，增加数量、题材和状态条件；重大选择保留分支结果和里程碑，后续事件读取这些结果。
4. **复用现有 Cocos 运行时 UI。** 继续使用 `LifeDemo` 与本地存档，不引入新框架；把玩家注意力放在角色处境、场景和决定上，数据说明留在项目资料，年表/结局复用当前 `entries`。
5. **分阶段完成完整对标。** 当前实现国家起点、内容密度和结局回看；下一阶段再做人生档案、多局比较、图卡分享、同场多人节点与在线房间。实时多人需按 `backend-superone` 的真实能力与授权另行设计，不能用本地假联机冒充。

## 使用流程

玩家点击抽取人生，系统按出生人数权重选起点，以具体人物和家庭处境开场；开始后进入有目标、有代价、有后续的故事，玩家的决定改变机会、关系或资源。普通过场可以快进，关键场景停下来选择。人生结束后回看决定如何改变经历，再用相同起点重玩或抽取新人生。年龄推进、状态数值和完整事件表是系统能力，不能代替玩家目标与故事因果。

本轮不涉及后端接口、数据库和权限；数据随游戏包发布，存档留在本机。统计来源及估算方法留在项目 README 和开发资料中，不在玩家主流程打断故事。

## 功能模块设计

### 1. 出生抽样与个人起点

1. **过滤统计记录。** 加载国家/地区资料，排除 World Bank 区域及收入组聚合项；没有出生率或人口的记录不参与抽样。
2. **估算抽样权重。** 使用人口乘以每千人粗出生率得到估算出生数，再按总和抽取一个起点。数据标示参考年 2023，不宣称是实时人口或完整人口普查。
3. **写好人物起点。** 统计基线只决定起点抽样权重。玩家看到的是有姓名、关系、眼前难题和行动目标的人物场景；不能把国家平均值套成某个家庭的生活，也不展示种子或生成规则。
4. **保留旧存档。** 保留原 4 个虚构起点的数据定义供旧版存档读取；新局不再从旧起点池抽取。

### 2. 年度内容与决定

1. **按年龄过滤事件。** 每条年度事件提供适用年龄段、文案、属性变化和可选里程碑；候选集为空时只推进年份，不制造空事件。
2. **按人生上下文出现选择。** 关键决定可读取路线、资源与里程碑；选择写入年表，并至少改变一处后续机会、代价或结局表述。
3. **固定随机流。** 使用当前种子与年龄生成结果，确保同一起点复玩能够比较选择带来的差异。

### 3. 人生记录与结局

1. **保留全过程事件。** 本地存档继续保留完整 `entries`，生活页面突出最近记录，结局页呈现整个人生与关键选择。
2. **呈现游戏结果。** 年龄与状态用玩家能理解的语言表达；数据来源、抽样方法和寿命计算规则留在项目资料，不插入人生叙事。
3. **允许重新体验。** 同种子重开相同起点；新人生使用新种子。
4. **保存完成记录。** 完成人生会进入本机档案，最多保留最近 12 局；玩家可打开旧人生完整回顾。正在经历的人生可收藏最近事件。
5. **记录年度状态。** 每年和关键选择后保存状态快照；结局地图依据健康与心情的平均值着色，旧版存档不伪造缺失的年度数值。
6. **明确区分继续与重开。** 首页有进行中人生时，提供“继续人生”和“重新开始”；重开直接进入新身份抽取，不增加危险操作式确认页。

## 接口、数据、改动范围

- **接口与契约：不涉及。** 本轮不请求后端。
- **数据库：不涉及。** 现有进行中人生继续由 `sys.localStorage` 保存。

- `business-repo/crazy-goose/assets/scripts/life-demo.ts`：出生说明、全程事件与结局回顾；沿用现有 Cocos 组件入口和滚动布局。

## 验收与风险

| 场景 | 操作 | 预期结果 | 环境 |
| --- | --- | --- | --- |
| 新人生抽样 | 连续开始不同种子的人生 | 人物处境和可选行动明确；抽样权重由出生人数估算决定，数据解释留在项目资料 | Cocos Browser / 微信小游戏 |
| 同起点复玩 | 使用相同种子完成相同年份 | 出生背景和年度随机事件一致，选择产生的后续差异可辨认 | Cocos Browser |
| 关键决定 | 自动推进到关键年龄 | 出现有效选项，做出选择后记录并恢复推进；相同选择不重复触发 | Cocos Browser |
| 旧存档 | 使用版本 1 的旧起点数据恢复 | 原进行中人生仍可继续 | 本地 Cocos 存储 |
| 结局 | 推进到模拟寿命终点 | 显示人生摘要、关键选择和完整记录；可以重开或开始新人生 | Cocos Browser |
| 微信真机 | 微信开发者工具预览并扫码 | 微信运行环境中可操作、滚动和恢复进度 | 微信小游戏 |

统计基线跨年份不会自动更新，重新生成数据时需核对指标年份并更新来源元信息。玩家反馈指出，开局展示“家庭细节由游戏种子生成，不代表当地每个家庭”会把技术说明塞进游戏，破坏代入感；该类说明移出玩家流程。发生构建或微信预览失败时，回退本轮代码改动即可；静态数据没有数据库迁移。

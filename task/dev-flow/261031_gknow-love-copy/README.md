# 261031 鹅懂个啥恋爱副本

## 背景

鹅懂个啥已有「人生副本」，在探索 tab 进入副本目录，再选择剧本阅读并在关键场景互动。现计划增加「恋爱副本」，让用户体验多种恋爱题材剧本；首个方向参考用户提供的小红书视频所称的「恋爱速通版」。

## 需求理解

- 在探索 tab 增加「恋爱副本」入口，后续可以扩展多种恋爱题材剧本。
- 首发只做一个副本「恋爱速通版」，面向没有恋爱经历的用户，用轻松、好懂的故事讲清恋爱中常见的过程。
- 交互选择不改变关系主线或结局；可用来让用户参与并看到当下反馈，随后回到同一段主线。
- 用户提供的小红书视频标题为「今天又又又带你谈一段恋爱（崩溃版）」，时长约 5 分 16 秒。使用 XHS-Downloader 下载、提取音频，并以本机 Qwen 和 Whisper 转写；用户确认有权处理完整转写，已交付两套带时间轴的机器字幕与文字稿。

## 目标与边界

### 本期目标

- 在探索 tab 增加「恋爱副本」入口，进入剧本目录；首期目录只有一个可体验的「恋爱速通版」，数据结构允许后续增加其他剧本。
- 提供完整的单次体验：开场、恋爱过程中的关键阶段、少量回应互动、结束回顾和重玩/返回目录。
- 以轻松剧情和阶段推进解释常见恋爱过程，给用户留有个体差异空间，不把该过程表述为人人必须遵循的固定步骤。

### 本期不做

- 不增加多个完整剧本、用户投稿或动态剧本管理。
- 互动选项不改变后续关系阶段、主线或最终结局，不增加关系数值或配对评分。
- 不涉及后端、数据库或用户历史记录；目录和故事页允许微信转发与分享到朋友圈。

## 产品与交互设计

### 原型

- 探索列表中的项目入口沿用现有功能卡片。
- 「恋爱副本」目录采用单一剧本目录：首发呈现「恋爱速通版」一张可打开的卡片；不放置不可点击的假剧本占位。
- 剧本体验采用 `detail / immersive` 连续故事页，沿用人生副本的逐句显示、关键场景回应、快进/继续和结束后重玩的基本交互。

### 首个剧本内容与表达方向

用户明确要保留原视频「恋爱速通崩溃版」的味道：开头迅速给对象、热恋、密集见面和夸张承诺；中段用联系频率变化、焦虑内耗、冲突与忽冷忽热不断加速；后段迅速滑向关系冷却、分手、崩溃和朋友收尾。节奏要快，表达夸张、口语、带反差，自嘲和荒诞笑点为主，不额外加一段健康恋爱范例来平衡。

以下时间轴为情节摘要，不是原话转录：

| 视频时间 | 情节推进 |
|---|---|
| 00:00–00:14 | 直接把观众塞进热恋想象，迅速建立高甜状态 |
| 00:14–00:28 | 急着向朋友公开、展示对象与恋爱状态 |
| 00:28–01:30 | 见面频繁、亲密升级、说出长久承诺，情绪一路冲高 |
| 01:31–02:25 | 一次晚间联系落差引发猜测和焦虑，解释与安抚没有接住情绪 |
| 02:25–03:08 | 类似矛盾反复，短暂热情又让人重新抱希望，关系问题仍然累积 |
| 03:09–04:28 | 对方逐渐冷淡并提出分手；挽回失败后，情绪迅速跌到底 |
| 04:29–05:16 | 朋友出场陪伴、记录崩溃状态，最后用一句反问收尾 |

副本要让母单用户通过剧情看懂「热恋冲太快 → 日常落差 → 内耗拉扯 → 关系结束」的完整速通弧线。剧情、人物和对白另写，借节奏、夸张度与情绪反差，不逐句复刻原视频；不把这一种失衡关系说成所有恋爱都必经的标准流程。

互动出现于少数关键时刻。玩家选择一种回应后看到即时对话/人物反馈；下一幕仍回到相同情节和关系进程。结尾简要回顾故事中经历的环节，可重新体验或回到恋爱副本目录。

### 页面状态

| 页面/状态 | 触发 | 表现与操作 |
|---|---|---|
| 探索 tab | 正常进入首页 | 显示「恋爱副本」入口，点击进入目录；其他分类和既有入口不变 |
| 目录有可用内容 | 首期静态目录加载 | 显示「恋爱速通版」卡片与简短内容说明，点击进入剧本开场 |
| 剧本开场 | 从目录进入或重玩 | 说明本副本讲述主题，提供开始按钮和返回目录 |
| 场景打字中 | 进入新场景 | 显示当前剧情，可点主按钮显示全文 |
| 等待互动 | 当前场景含选择题 | 显示回应选项；选择后立即进入下一幕并展示对应开场反馈，后续回到固定主线 |
| 普通场景 | 当前场景无互动 | 阅读并继续到下一幕 |
| 副本结束 | 读完固定主线 | 展示过程回顾，提供重新体验、回目录 |
| 导航失败 | 页面跳转失败 | 使用项目现有轻提示，停留在当前页供重试 |

目录和故事数据本地静态加载，没有服务端加载、离线失败或权限分支；当前功能沿用项目现有 demo-access 门禁。

## 实施方案

1. 在 `projectCatalog.ts` 的探索项目列表加入恋爱副本卡片，使用现有项目导航与项目卡片样式。
2. 增加独立恋爱副本目录及单剧本入口，不改写人生副本当前体验和目录数据。
3. 新增恋爱副本目录数据和 `ImmersiveStoryDefinition` 剧情配置，并注册到 `src/data/immersiveStories.ts`；故事页复用 `ImmersiveStoryPlayer`，不复制打字、互动、继续和结尾逻辑。入口通过 `storyId` 选择剧本；如需独立页面，只新增负责读取剧本 ID 的轻量包装页。
4. 复用现有 `gk-project-card`、导航和故事主题/背景能力。仅当恋爱题材需要现有播放器不支持的视觉或交互表现时，才扩展共享组件；本期使用项目内 SVG 图标及场景插画背景，不新增位图资产。
5. 完成用户对剧情骨架及第一版体验的反馈后，再调整内容与互动密度。

## 验收标准

1. 探索 tab 中出现恋爱副本卡片，点击进入目录；返回能回到原探索 tab。
2. 目录首期只呈现「恋爱速通版」一项，可开始并完整读到结束页。
3. 故事覆盖经用户确认的恋爱流程内容；逐句显示可快进，场景可继续，互动选项均有清晰反馈。
4. 无论选择何种回应，都进入完全相同的后续主线和固定结尾；无关系分、配对分或隐藏结局。
5. 结束页可重新体验或返回目录；导航失败有反馈且不丢失当前可恢复入口。
6. `npm run type-check` 和 `npm run build:mp-weixin` 通过；由用户在微信开发者工具/真机体验剧情与页面。

## 视频参考到剧本的复用流程

1. **确认来源与可用文字稿**：记录视频链接、平台和主题。先检查来源页面是否提供可用字幕；没有字幕时才下载媒体并进入本机处理。平台下载方式见来源采集器和对应下载器说明。
2. **抽取音频并交叉转写**：用 FFmpeg 统一音频格式，分别交给本机 Qwen、Whisper 等可用 ASR。原始媒体和模型输出保留在本机私有缓存；用户要求交付或任务确需引用时，再将副本整理进任务 `reference/`。机器转写用于理解内容，不默认等于准确逐字稿。
3. **整理情节节拍**：按时间段记录事件、关系变化、情绪起伏、转折和结尾功能；对俚语、错词、漏段或两份结果冲突处回听核对。交付剧本阶段只引用节拍摘要，不复制整段转写。
4. **形成原创剧本骨架**：先确认要借鉴的节奏、情绪和表达风格，再列场景顺序、人物关系、每幕作用、互动点与固定主线。保留用户明确要求的核心味道，人物、对白和具体情节另写；明确作品只是一种故事呈现，不把它写成普遍规律。
5. **用户审阅后写场景配置**：把已确认骨架写成 `ImmersiveStoryDefinition` 的 intro、scenes、choiceFollowup、facts 和 endings。每幕用清楚的标题与继续文案连接；互动只写当下回应，若目标是固定主线就不设置路线或结局分支。
6. **复用播放器并验收**：将故事注册到 `immersiveStories.ts`，目录卡片传入对应 `storyId`；优先只改目录与数据配置。运行 `npm run type-check`、`npm run build:mp-weixin`，再由用户在微信开发者工具或真机检查节奏、阅读和交互。

本任务已完成视频下载、双模型转写、时间轴节拍摘要、原创分幕文案和第一版实现。播放器、打字、选项即时反馈、下一幕选择回响、事实卡、固定主线及结尾复玩/返回能力已在「人生副本」组件中，本副本复用了相关能力。

# 组织与公开 Skill：test 环境集成测试用例

## 目标与范围

通过已部署的真实 test 服务，验证组织邀请、三类 Skill 的完整业务链路、权限隔离、并发和已有数据迁移。覆盖 HTTP 与真实 MCP 客户端；不以直接调用 Service、单元测试或模拟服务代替目标环境验收。本文件是待执行设计，所有用例初始状态为「未执行」。

用户反馈新版本已部署到 test；执行前记录实际服务地址、部署版本/提交、时间及数据库名称，并核对工具清单和响应与本次契约一致。现有任务记录中的旧版部署结论是历史记录，不能据此判断当前版本；如果无法核实实际运行版本，记录为待核实，不把 `/ping` 成功视为版本证据。

## 测试准备与数据边界

- 使用三个已登录的独立 test 账号 A、B、C：A 为组织者，B 为受邀成员，C 为非成员及并发竞争者；配额用例优先使用没有业务 Skill 的独立账号 D。至少一个账号在真实 MCP 客户端连接；HTTP 使用相同账号凭证。凭证和邀请令牌只在受限环境传递，不写入用例记录或日志。
- 所有测试名称使用 `it-<本次唯一批次>-<用途>`，记录各账号起始 Skill 数量、测试创建的组织 ID、Skill ID、版本、邀请对应编号及结果。文件仅用无敏感信息的测试文本，例如 `{"SKILL.md":"IyBUZXN0Cg==","refs/a.txt":"aGVsbG8="}`；准备另一份内容用于更新，并独立计算规范化摘要。
- 当前没有组织退出、解散或移除成员接口。测试组织、成员及邀请无法通过正式 API 清除；执行前确认可接受其留在 test 环境，记录 ID 和残留范围。不要删除既有数据或直接修改数据库。测试 Skill 可由各自 owner 以当前 revision 经正式接口删除；物理删除不可恢复，仅删除本批创建的记录。执行失败时保留清单并报告，不扩大清理范围。
- 配额达到 30 会占用账号名额；先记录 D 起始数 N，确认有足够名额和可清理的测试数据。仅补建至 30，避免修改既有 Skill。公开 Skill 在 test 环境对已登录用户可见，只上传测试内容。
- 过期用例需提前创建独立令牌并等待至少 7 天，或使用已自然过期且归属明确的测试令牌；不得为加速测试直接修改 test 数据库或服务时间。并发测试同步发起请求并保存每个响应与后续读取结果；网络超时单独标记为不确定，通过读取状态核对，不能直接算失败或成功。
- 接口以 [组织契约](../../../../business-repo/frontend-contracts/openapi/organization_api.yaml) 和 [Skill 契约](../../../../business-repo/frontend-contracts/openapi/skill_api.yaml) 为准。HTTP 前缀 `/api/so/mcp`，业务成功同时核对响应信封的 `err_code` 与 `data`；HTTP 状态成功不代表业务成功。MCP 核对工具结果及 `isError`，不记录令牌或文件包正文。

## 执行顺序与用例

优先执行 P0，再执行 P1；所有 ID、revision 均取自前一步实际响应。失败后通过列表、详情和成员列表检查状态，不因某一步失败继续做依赖其状态的写入。

| 编号 | 优先级 | 前置和操作 | 可判定的预期 |
| --- | --- | --- | --- |
| E01 | P0 | 记录 test URL、版本和数据库；A 连接 `/transport` 并执行初始化、工具发现。无凭证和无效凭证访问传输入口。 | 发现 5 个组织工具及 `list_skills`、`get_skill`、`save_skill`、`delete_skill`；无效或缺失凭证被拒绝。版本无法证明时标待核实。 |
| E02 | P1 | 用有效 MCP 场景凭证访问非 MCP 路由；用普通登录凭证访问 MCP。 | 前者被拒绝；后者按已登录账号访问，不能借请求参数指定 owner。 |
| O01 | P0 | A 通过 `create_organization` 创建 O1；A 调用 `list_organizations`、`list_organization_members`。 | 返回正数组织 ID 和名称；A 的组织列表包含 O1 且角色为组织者；成员列表包含 A 且仅出现一次。 |
| O02 | P0 | A 对 O1 生成邀请，检查响应及服务端当前时间；B 使用令牌加入，并分别由 A、B 查询组织及成员列表。 | 返回令牌和约 7 天后的 Unix 秒到期时间；B 加入成功，A、B 均能看到 O1 与成员、各自角色正确；不把令牌记录到报告。 |
| O03 | P0 | B 重复接受同一令牌；C 接受同一令牌。 | B 返回同一组织的成功结果且成员不重复；C 得到已使用错误且未加入。 |
| O04 | P0 | A 再生成独立令牌 T2；已有成员 B 接受 T2，随后 C 接受 T2。 | B 得到已是成员错误，不消费 T2；C 随后成功加入。 |
| O05 | P0 | B、C 分别尝试生成 O1 邀请；新建组织 O2 后，以非成员账号查询 O2 成员和组织 Skill。 | 非组织者不能生成邀请；非成员查询被拒绝；失败后成员及列表状态不变。 |
| O06 | P1 | 使用格式错误令牌、随机合法格式但不存在的令牌、自然过期令牌分别接受。 | 分别返回参数、邀请不存在、邀请过期类错误；未产生成员关系。过期条件未就绪时单列待验证。 |
| O07 | P0 | 用另一测试组织 O3 的一条新令牌，让未加入的 B、C 同时接受。 | 恰有一个不同账号成功，另一个返回已使用或并发失败；成员列表只有获胜者加入。超时需读取后判定，不把不确定结果记为通过。 |
| O08 | P1 | 在另一测试组织 O4，对同一未加入账号准备两条有效令牌，并发接受；之后让另一未加入账号接受未消费令牌。 | 只形成一条成员关系；一条令牌被消费，另一条仍可由其他人成功使用。若返回死锁/数据库错误，整次失败事务不消耗令牌；检查后可重试。 |
| S01 | P0 | A 创建 personal Skill P，保存 ID、revision、digest；A 列表、详情读取；B 以 P 的 ID 读取。 | 创建版本为 1；A 读回文件字节、元数据和摘要一致；B 不能读取，不能从自己的 personal 列表看到 P。 |
| S02 | P0 | A 在 O1 创建 team Skill T；B 通过 team 列表和 ID 读取；未加入 O1 的账号访问 team 列表和详情，并尝试创建。 | B 能看到发布者、版本和文件；非成员列表、详情与创建均被拒绝；详情不泄露文件。 |
| S03 | P0 | A 创建 public Skill U；B 按 public 列表查找并按 ID 读取；B 尝试更新和删除 U。 | B 可发现并读取 U 的文件和 owner 展示信息；非 owner 的更新、删除被拒绝，A 再读确认内容与 revision 未变。 |
| S04 | P0 | A 用 T 的当前 revision 和完整文件包更新内容；B 再读；B 尝试更新/删除 T。 | A 更新后 revision 加 1、摘要及内容一致；B 能读新内容但无权更改或删除；失败后状态不变。 |
| S05 | P0 | A 同一 Skill 依次 personal → team(O1) → public → personal，每次携带最新 revision 和完整文件；B 在各阶段尝试读取。 | ID 和 owner 不变，每次 revision 加 1；team 仅成员可读、public 登录用户可读、personal 仅 owner 可读；原分类列表不再出现该 ID。已下载副本不受撤回影响。 |
| S06 | P0 | A 将 Skill 转入自己未加入的组织，或转入已有同名 Skill 的目标范围；另提交过期 revision。 | 分别拒绝；重新读取确认原分类、组织 ID、文件、摘要及 revision 全部不变。 |
| S07 | P0 | 检查同名：A 在 personal 与 public 各创建同名；B 在 public 创建同名；A、B 在同一组织创建同名；不同组织各创建同名。 | 跨 personal/public、不同发布者 public、不同组织 team 可成功；同组织 team 第二次创建冲突，不覆盖第一条。 |
| S08 | P1 | B 读取 U 的文件并用自己的身份重新创建副本；A 与 B 分别更新各自记录。 | 两条 ID 不同、owner 各自正确，各计入创建者名额；修改任一条不改变另一条内容或 revision。 |
| S09 | P0 | A、B 对 A 的同一 Skill 分别提交删除；A 先用旧 revision，再用当前 revision 删除；再次读、列表、重建同名。 | B 和旧版本删除失败且数据不变；A 当前版本删除成功，详情及列表不再返回，原 ID 不可读取；同范围同名可重新创建，产生新 ID。 |
| S10 | P0 | 对同一 Skill 的同一 revision 并发提交两份不同更新。 | 恰有一次成功、一次版本冲突；最终 revision 仅加 1，文件及 digest 对应获胜请求，失败请求不覆盖。 |
| S11 | P1 | 同组织两名成员并发创建相同名称 team Skill。 | 至多一条成功，另一条同名冲突；列表仅有一条，内容和 owner 对应成功请求。 |
| S12 | P1 | 使用 D 在 personal/team/public 混合创建至 owner 合计 30 条，尝试新建；删除本批一条，再创建一条；对已有记录更新和变更分类。 | 到 30 后新建拒绝；删除本批记录后可创建；更新和分类变更不增加记录且不因已满被拒绝。不要删除 D 的既有记录。 |
| S13 | P1 | 在独立账号接近 30 时并发创建不同名 Skill，记录起始数量和结果。 | 超过 30 是允许结果，不要求必然超额；每个成功请求形成独立记录，失败不产生记录；核对总数与成功数。 |
| V01 | P1 | 测试非法分类、team 缺组织 ID、非 team 携带非零组织 ID、非法 ID/revision、负分页及 size > 100。 | 返回参数错误或相应权限错误，所有已有记录不变；默认分页为 offset 0、size 20。 |
| V02 | P1 | 测试非法名称、缺失或空 `SKILL.md`、非法 Base64、绝对路径/`..`、重复路径、65 个文件、解码超过 256 KiB；另测允许边界。 | 非法包均拒绝且不创建或修改；合法边界可写入并读回。重复 JSON 键须使用原始请求体构造，普通 map 无法表达。 |
| V03 | P1 | 使用可控的测试记录跨页列出 personal、team、public，按名称及 ID 检查顺序，比较 total 与各页。 | 分页无遗漏或重复，返回 offset、size、total；不同账号及组织遵循各自可见范围。已有公共数据随其他用户变化时记录快照限制。 |
| M01 | P0 | 用迁移前备份/记录中的已有 Skill，由原 owner 通过新接口按 personal 列出、按 ID 读取；对照迁移前 ID、owner、文件、digest、revision。 | 字段和内容与迁移前证据一致，非 owner 不可读。缺少迁移前证据时标待核实，不把当前可读当成迁移完整性通过。 |
| X01 | P0 | A 通过 MCP 创建测试 Skill，用 HTTP 详情读取；再由 HTTP 更新，MCP 读取；通过另一账号验证拒绝，再用 MCP 删除。 | 两个入口共享 ID、权限、文件、digest 和 revision；删除后两入口均不可读。同步核对 MCP 工具错误为错误结果。 |
| X02 | P1 | 使用目标客户端完成 A 生成令牌、B 接收令牌并调用加入；在另一设备或独立客户端拉取 B 可见 Skill 并验证文件。 | 真实客户端完成令牌交接及加入；恢复的文件字节和摘要一致；目标路径已存在时不覆盖。缺第二设备时标待验证。 |

## 执行记录与结果判定

每次执行记录：时间、test 地址、可核实的部署版本、数据库、账号代号、批次、用例编号、实际请求入口、响应码/业务码、必要的脱敏状态证据、通过/失败/待验证、测试 ID 和清理结果。不得记录 JWT、明文邀请令牌、私有 Skill 文件内容或原始敏感日志。并发记录每个请求的开始/结束、结果及最终状态；需要时间窗口或第二设备的用例不可用时保留待验证。

P0 全通过且无权限泄露、数据损坏或不可解释的并发结果，才可称本次 P0 集成验收通过；P1 和未覆盖项单独列出。完成后由每个 owner 删除本批 Skill 并复查列表/详情，保留组织、成员和邀请残留清单；无法清理或结果不确定的项目明确登记。迁移证据和目标客户端验收分别报告，不由本地测试推断。

# 检查清单页面 UI/UX 调整

## 实施内容

- 收紧清单选择器标签的间距、内边距和高度，压缩页面主纵向间距。
- 收紧执行卡片、进度区、操作区、检查项、执行总结和完成操作之间的留白；压缩检查项 Markdown 标题、段落和列表默认间距。
- 移除执行区常驻“编辑”按钮，编辑入口由清单标签右键菜单提供；保留“查看详情”、全部完成、重置、备注与完成执行等常用入口。
- 将检查清单页面的手写右键菜单替换为通用 `CuContextMenu`，提供置顶/取消置顶、编辑和删除；菜单边界定位、Esc、外部点击、滚动和键盘导航沿用通用组件行为。
- 从 `useChecklistManagement` 移除该页面专属的 document click 监听，菜单开关改由通用组件事件驱动。
- 未改接口、契约、执行进度存储和业务数据语义。

## 验证

- `npm run typecheck` 通过。
- `npm run build` 通过，Vite 编译 1583 个模块。
- 按用户要求未进行浏览器视觉检查。

## 项目级控件尺寸修正

- 用户反馈从 Topic 切换到检查清单后模块导航又变大。排查确认原因是 `CuModuleNav` 的紧凑尺寸之前被错误地限定在 Topic 页面样式作用域，检查清单和最近任务使用同一组件却继承默认大尺寸。
- 将模块导航的间距、高度、字体和退出项分隔样式迁入项目级 `CuModuleNav` 样式；增加项目级紧凑选择标签样式和尺寸令牌，Topic、检查清单、最近任务的选择/筛选控件统一消费。
- 删除 Topic、检查清单和最近任务页面上重复的标签尺寸定义，页面样式只留业务布局/图标等特化内容。
- 本次调整再次通过 `npm run typecheck`、`npm run build` 与 `git diff --check`；仍不打开浏览器。
- 最近任务页面尚未开始主体 UI/UX 收紧；本轮只把其状态筛选标签接入项目级紧凑标签尺寸。
- 用户指出“添加任务”和“新主题”按钮高度不一致，并明确要求以此前检查清单按钮为标准。撤销上一版自定义 28px 按钮方案，将 Topic、检查清单、最近任务三个创建入口统一为原检查清单使用的 Element Plus `small` 按钮规格。
- 调整后重新通过 `npm run typecheck`、`npm run build`（1583 个模块）和 `git diff --check`；未进行浏览器检查。
- 继续排查 Topic 模块切换高度抖动：此前 `CuModuleNav` 默认允许换行，Topic 页因额外的登录入口更容易折成两行；迁移样式时误删了 Topic 局部的 `nowrap`。已将 `flex-wrap: nowrap` 收敛到项目级模块导航组件，避免不同模块导航高度变化。
- 该修复通过 `npm run typecheck`、`npm run build`（1583 个模块）和 `git diff --check`；按用户要求未开浏览器。
- 用户指出仅导航按钮共用样式仍不足以保证模块切换一致。现将 Topic、检查清单、最近任务的整行导航头部改为同一组 `cu-module-header` / `cu-module-page` 项目级结构：固定 36px 高度、相同导航/操作区布局、同一页面区块间距；移除三页各自重复且不一致的头部布局样式。
- 统一头部后再次通过 `npm run typecheck`、`npm run build`（1583 个模块）和 `git diff --check`；未做浏览器检查。

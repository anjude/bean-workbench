# 源码结构与契约类型审查 · 过程记录

- 任务目录：`task/dev-flow/261007_utools-refactor/`
- 阶段：03 源码结构与契约类型审查
- 时间：2026-10-07

## 做了什么

- 盘点 `src/` 文件树与活跃业务入口，核对 view、store、composable、types、constants、styles 的调用关系。
- 搜索本地枚举、类型、辅助工具、barrel 和图标字体文件的消费点；对照 `src/contracts/types/*` 共享类型。
- 核对 `config.ts`、`App.vue` 中 API baseURL 的选取逻辑。
- 本轮没有修改 uTools 源码。

## 得到的结论

### 目录结构

- 现有结构按技术层分组：7 个 view、6 个 composable、5 个 store，以及全局 `types/`、`constants/`、`utils/`、47 个样式/字体文件；topic、checklist、plan 的文件横跨多个目录，查找时需在层目录间跳转。
- 可评估渐进式 feature-first 组织：`src/features/{topic,checklist,plan,login}/` 放各自 view/composable/store/model/style；`src/shared/` 收公共组件、适配器、请求、工具和全局样式；`src/contracts/` 继续作为原样保留的契约子模块。
- 这不是必须的大搬迁：当前技术分层本身职责明确。先清理确认无引用的遗留物，再决定是否迁移活跃文件；不要把平台适配与 request 分层压扁。
- `src/contracts/` 内含一批 uTools 官方文档，是共享协议仓子模块内容，不应当作 uTools 自有冗余文件直接删除。

### 可明确作为废弃候选的本地文件

- 没有应用引用的类型文件：`src/types/share.ts`、`src/types/components.ts`、`src/types/item-management.ts`、`src/types/md-editor.d.ts`、`src/types/store.d.ts`、`src/types/platform.d.ts`。旧 store/platform 声明中的 UserInfo、FlowItem、SchedulePlan、wx/my/swan/tt 等符号未在应用源码消费。
- 没有应用引用的常量/工具：`src/constants/static-data.ts`、`src/constants/item-categories.ts`、`src/utils/image-upload.ts`、`src/utils/permission.ts`。当前图片编辑调用 `src/utils/adapt/upload.ts`；两项旧工具无调用方。
- 没有导入方的 barrel：`src/constants/index.ts`、`src/composables/index.ts`、`src/plugins/index.ts`。`src/components/index.ts` 有多处调用，应保留；`src/stores/index.ts` 被 Login 使用，如改为直引 user store 可一并删，但收益较小。
- `src/contract.ts` 的 `commonApi`、`itemApi` 实例没有消费者。uTools 插件清单和路由目前没有 item 页面；`frontend-contracts` 中的 item 协议仍是共享资产，不应删除。
- `src/styles/index.scss` 和 `src/styles/variables.scss` 无运行时引用；实际入口是 `src/main.ts` 引入 `src/styles/main.scss`，其 ITCSS 层仍在使用。`src/styles/iconfont/demo.css`、`demo_index.html`、`iconfont.js`、`iconfont.json` 只有演示/元数据用途，应用仅通过 `iconfont.css` 和字体文件渲染字体图标。
- `src/main.ts` 与 `src/components/MarkdownEditor.vue` 都导入 `src/styles/vditor/index.css`，可保留一个统一入口以避免重复声明。

### 契约类型与枚举

- `src/contracts` 已导出 TopicType/TopicLogMark、TaskStatus/TaskPriority、GoalStatus/GoalPriority/GoalType/Quarter、ExecutionMode/ExecutionStatus、ItemCategory/ItemStatus 等 API 枚举。`src/constants/enums.ts` 当前把不少共享枚举再套一层 namespace alias；其中旧 Flow/Schedule/登录订阅枚举、ChecklistCategory 和 AllEnums 没有应用调用，可删除。活跃调用可直接导入契约枚举；`UserPermission` 是本地权限位，不在契约导出的同名枚举中，但目前所属 `permission.ts` 也没有应用调用。
- `src/types/plan.ts` 只有 RecentTask、RecentTaskForm 与 TaskEnums 被应用使用。TaskEnums 可替换为 `@/contracts` 的 TaskStatus/TaskPriority。Goal/KeyResult、分页、PlanApiResponse 等本地声明无消费者，且 Goal/KeyResult API 类型已在契约中。
- `src/types/checklist.ts` 中 ChecklistCategory、ChecklistTemplate、ChecklistSearchFilter、ChecklistExecutionDraft 未被消费；ExecutionMode 和 ExecutionStatus 是契约 alias。ChecklistEntity/执行步骤类型字段与契约模型相同，可考虑改用 `ChecklistApi` 中类型。Overview/Step 是 UI 语义名称映射到 Normal/StepByStep，若保留映射应放在 UI 常量层，不要另造协议枚举。
- `src/types/topic.ts` 中 TopicType、TopicLogMark 是契约纯 alias；TopicLogExtraData 当前只列 feedbackAnswer，而契约 TopicApi.TopicLogExtraData 还含 imageUrls、feedbackAnswerImageUrls、answer，存在类型漂移风险。主题表单校验、预览字段等是 UI 业务类型，可保留或基于契约模型派生。
- `src/types/plan.ts` 与 `src/types/base.ts` 各自定义了一份相同字段的 BaseEntity；`types/base.ts` 的 BaseFormData 是空接口，PaginationParams/Data、ValidationResult 无本地消费。应统一基础实体，并移除无用空基类/分页副本。
- `src/types/plan.ts` 的 RecentTask 额外有 completed 字段，是本地派生状态；不能直接等同契约 RecentTaskDetail，应保留 view model 或在 store 中显式派生。

### API 环境选择

- 虽然已移除 `.env.development` / `.env.production`，`src/App.vue` 仍读取 VITE_BASE_URL，`config.ts` 仍读取 VITE_ENV 与 MODE；`.env.example` 复制为 `.env.local` 后会显式固定 develop。
- 可以完全不用 Vite 环境变量：让 `config.ts` 提供单一固定 baseURL，并移除 `getBaseURLByEnv` 及 App.vue 的环境选择代码；这样 dev 与 build 都指向同一个 API。若仍需不同目标，可在 `config.ts` 定义显式常量环境（如 `API_ENV = 'develop' | 'release'`）选择 `urlMap`，同样无需 `.env` 文件。
- 当前 `baseURL` 默认 release，但 App 会覆盖为 develop（dev）或 release（build）。所以“直接使用 config.ts 的 baseURL”会改变开发环境目标，需确认预期后再实施。

## 被推翻的判断

- 最初可能把分散目录当作必须整体重构 → 主要是清晰的按技术层组织；feature-first 可以改善跨层查找，但属于可选迁移，先移除死文件能获得大部分精简收益且风险更低。

## 待核 / 没答上来

- 是否实施 feature-first 目录迁移，还是先做高置信度死文件与契约 alias 清理。
- API 环境是否固定到 release，或需要保留 develop/release 切换。
- iconfont 字体文件中的 `.ttf` / `.woff` 回退格式是否仍需兼容目标 uTools 版本；本轮仅建议移除 demo 和未引用 JS/JSON。

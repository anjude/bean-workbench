# uTools Superone 重构

## 背景

`utools-superone` 已完成一轮契约接入、Repo 收敛、发布检查与业务清理改造。本任务先精简一级辅助文件，再审查 `src/` 目录组织、遗留文件和契约类型复用方式。

## 需求理解

精简 `utools-superone` 一级目录辅助文件，保持开发/生产 API 环境选择一致、保留 Vue 组件自动导入和构建能力，并让 README 与当前功能一致。

## 目标与边界

### 本期目标

- 移除冗余的显式环境文件，提供有效的 `.env.example` 本地覆盖示例。
- 移除未使用的 API 自动导入插件及空生成声明，保留组件自动导入。
- 移除陈旧技术栈建议与误导性的旧产品介绍。
- 检查 `src/` 是否适合从按技术层分组逐步转成按业务功能组织。
- 清理有明确无引用证据的旧文件和本地重复类型，确认 API 枚举直接使用 `src/contracts`。
- 对照近期任务 `task/dev-flow/261007_utools-release-contract-checks/README.md`，避免重复其已完成的契约、Repo、发布门禁和业务功能范围。
- 不扩展到业务逻辑或页面架构重构，不触碰共享契约和后端。

### 本期不做

- 不扩展到业务逻辑或页面架构重构，不触碰共享契约和后端。
- 不执行发布、分支推进或数据库操作。
- 不批量迁移活跃源码目录；仅删除经过引用扫描确认无消费者的文件与类型。
- Vite 环境选择与配置保持现状，本阶段不调整。

### 已完成：Topic 页面 UI/UX 试点

- 目标：收紧 Topic 页面的间距、按钮和元信息，把选中主题、快速记录与记录内容作为视觉主线。
- 低频的主题/记录操作通过统一的可复用上下文菜单呈现；保留明显的创建、保存和记录详情入口。
- 参考 `business-repo/uni-superone` 的 SuperOne 品牌令牌与克制层级；适配 uTools 桌面交互，不照搬 uni-app 布局。
- 范围：`utools-superone/src/views/TopicList.vue`、`src/styles/07-pages/_topic-list.scss`、通用上下文菜单组件及必要的主题 composable。
- 状态：加载、错误/重试、空主题、无选中主题、空记录、有记录、菜单打开/关闭、操作中反馈均保留。
- 不改 API、共享契约、后端或 Vite 环境。

### 已完成：检查清单首轮迁移与最近任务 UI/UX

- 目标：把 Topic 页面验证过的紧凑信息层级、低频操作右键菜单和轻量交互迁移到检查清单与最近任务，同时保留两个模块各自的核心工作流。
- 检查清单范围：`utools-superone/src/views/ChecklistList.vue` 及其页面样式、`useChecklistManagement`。压缩清单选择标签、执行区、检查项与总结区的纵向留白；用 `CuContextMenu` 替换页面内自绘的清单菜单，置顶/取消置顶、编辑、删除放入右键菜单。保留执行进度、完成/重置、备注、完成执行等高频操作和结果弹窗。
- 最近任务范围：`utools-superone/src/views/PlanList.vue` 及其页面样式、必要的 `usePlanManagement` 适配。压缩状态筛选、任务列表与详情元信息的间距；用 `CuContextMenu` 替换页面内自绘的任务菜单，保留跳转详情、快照、置顶、编辑、删除等现有菜单能力。保留左右主从布局、任务状态切换与创建入口。
- 保存语义：最近任务详情编辑器继续使用现有 1 秒防抖自动保存和保存中提示，不增加重复保存按钮；Cmd/Ctrl+Enter 仅用于具备明确提交动作的编辑器，不改变自动保存逻辑。
- 两页均保留加载、错误/重试、空状态、菜单开关及操作反馈；不改 API、契约、后端、Vite 环境或数据语义。
- 验收：两页面的高频操作清晰可见、低频管理操作可通过右键访问；压缩后关键信息不截断；静态检查通过。不进行浏览器检查。
- 状态：Topic、检查清单、最近任务模块页已使用共享头部、标签与按钮规则；最近任务内容区继续保留左右主从业务结构。

### 已完成：全项目 UI/UX 规则迁移

- 用户明确：Topic 试点已经结束，本阶段目标是把试点验证后的 UI/UX 迁移至整个项目，不能把迁移范围限定为 Topic、检查清单和最近任务三个列表页。
- 共享规则覆盖全项目页面的卡片密度、Markdown 阅读密度、紧凑弹窗、编辑器内距和右键菜单；页面仅保留业务布局和状态差异。
- 任务详情页纳入压缩范围；最近任务右键菜单统一改用 `CuContextMenu`。清单页不再复制紧凑 Markdown 的排版声明。
- 登录页保留认证场景的专属品牌布局；控件视觉仍遵守项目级控件规范。
- 验收只做类型检查、生产构建与 `git diff --check`，遵循用户要求不进行浏览器检查。

1. 移除 Vite 默认 MODE 可替代的 `.env.development` 与 `.env.production`，整理 `.env.example` 与 README。

3. 删除过时的技术栈实施建议和陈旧产品简介。

## 2026-11-17 第 17 轮：修正 3D 点选水道整体左偏一道

- 用户反馈点第三、四、五道，鹅分别落在第二、三、四道，且多次出现。对照 `src/game3d/pages/goose-dash/index.vue` 的 `onArenaTouch`、`src/utils/game/gooseDashScene3d.ts` 的 `laneAtCanvasX` 和编译后的 `bindtouchstart` 绑定：旧实现优先取 `clientX/pageX` 再减去硬编码的「窗口宽 × 0.18」，而微信 canvas 触摸事件自带的 `x` 本来就是相对 canvas 的局部坐标。两套坐标基准混用造成常量左移，约 1.5 个赛道宽，与用户看到的现象一致。
- 改为单一基准：页面优先用 `CanvasTouch.x`；缺 `x` 时用页面坐标减去事件自身校准出的 canvas 左边界，或实测 `boundingClientRect().left`。canvas 尺寸同时由 `boundingClientRect` 与 `fields({ size: true })` 取得，供 `resize` 与点击归一化共用；删掉 `windowWidth * 0.18`。
- `laneAtCanvasX` 改为 `laneAtCanvasRatio`，用 `camera.left + ratio * (camera.right - camera.left)` 反算世界 x，点击几何与渲染相机共用同一视口；比例越界或落在水道外返回 `null`。
- 验证：`npm run type-check`、`npm run build:mp-weixin`、`git diff --check` 通过；另用 4 组画布尺寸（320×600、295×540、350×720、410×660）数值验证五条水道中心各映射到自身车道、画布外返回 `null`。编译产物里已无 `0.18` 与旧方法名。

## 得到的结论

- 点选命中必须落在 canvas 自身坐标系，不能把 CSS 百分比偏移写死进坐标换算：`src/game3d/pages/goose-dash/index.vue`。
- 相机视口是唯一几何来源，页面只传「canvas 宽度比例」：`src/utils/game/gooseDashScene3d.ts` 的 `laneAtCanvasRatio` 与 `resize`。

## 被推翻的判断

- 第 13 轮「触点是页面坐标，减去 18% 窗口宽即得 canvas 局部 x」→ 微信事件对象文档明确 canvas 触摸事件带相对 canvas 的 `x`；继续减偏移让点击整体左移，错位因此反复出现。

# 大鹅快划玩法与实现方案

## 玩法目标

把《顶你个牛》的多赛道队伍对抗与漏防扣分逻辑，改成大鹅在水道中对抗。水面是赛道主题和移动表现；胜负仍由赛道两队鹅群的合力、推进和逐只突破决定，不采用绳子或漩涡机制。

## 已对齐的核心规则

1. 双方各有分数，开局进入五条并列水赛道；每条赛道都能容纳多只鹅。
2. 同一道内，鹅先各自缓慢向对方基地前进；两方鹅身体接触后，接触鹅与靠近它们的同侧支援鹅才组成局部对抗组。对抗力只计算这个接触组，不把整条赛道里相距很远的鹅相加。接触组总力相同时僵持；有差时胜方把整个接触组缓慢推回对方基地。没有接触的鹅继续按自身体型速度前进。
3. 鹅逐只沿水道向对方基地冲刺。鹅越过对方基线时，对方扣分；每只鹅分别触发一次扣分。若分数扣至零则失败。原作公开简介只支持“漏过扣分、分数耗尽结束”这一概括，没有公开完整的力量公式。
4. 鹅型为同一品种的 S、M、L、XL，靠幼年阶段特征和体型大小辨认。S 是绒毛、短脖子的幼鹅，M 是幼年换羽期，L 是成年鹅，XL 是更大更壮的成年鹅。项目内提供独立透明角色图。
5. 队伍有三个鹅位：首鹅在进入队首时开始 3 秒冷却；冷却结束后玩家可以点赛道部署。部署后队列立即前移，第二只成为新队首并开始冷却，第三只进入第二位，第三位按型号概率随机补鹅。玩家可以等待，不会错过或累积波次。机器人和对手使用相同队列与冷却规则。
6. 赛道是全屏竖版游戏场景，上下两端分别是双方基地；分数条与三只鹅预告叠在场景上。移除小程序内容页式标题栏、说明卡片、赛道编号和状态文字，改用鹅的靠近/后退、局部水花和分数条变化讲清局势。
6. 玩家不看力量、速度、扣分值等内部数字，通过鹅的体型、冲刺表现、对抗线变化和双方分数变化理解战况。

## 规则来源与未确认项

- 用户已确认：每道多鹅组成队伍、队伍力量相加、等力僵持、小鹅力量低但过线扣分多、大鹅力量高但过线扣分少、过对方基线才扣分、自动发鹅和预告三只。
- 用户提供的录屏能看到五条竖向赛道、上下双方分数、侧边单位操作区及同道多单位；画面不足以确认原作的力量计算、扣分表和冲刺公式。
- [九游《顶你个牛》玩法简介](https://www.9game.cn/dngn/5698996.html)称游戏有五条赛道、双方放牛、未拦住的牛会扣分、对方分数耗完获胜，并提及合成高等级牛。用户明确本作不做合成；第三方简介不用于确定其他未说明的细节。
- 当前实现以 100 分为起始分，鹅每 3 秒提供一只。S/M/L/XL 的力量分别为 1/2/4/7，速度为 0.046/0.039/0.032/0.026 个赛道长度每秒，过线扣分为 6/4/3/2。全部是内部平衡参数，玩家界面不显示。
- 推进方式：每道汇总双方力量；力量相同时交锋线不动，强势方按力量差比例推线，弱势鹅队以较慢速度退向自家基线；每只强势方鹅到达对方基线后单独扣除该鹅型对应的分。首轮参数尚未经过实机试玩平衡。
- 待定：最终力量/速度/扣分曲线、各型号概率和比赛节奏平衡；机器人选道策略仍需试玩验证，双端同步需要微信目标端验收。

## 单人练习赛

- 玩家从首页直接开始练习，不创建联网房间；机器人队首冷却结束后自动部署，并按各道合力差、战线危险程度与推进势头选择赛道。
- 玩家队首冷却结束后可以部署；三槽预告展示当前队首和后续两只。练习赛与好友对战共用同一套队列冷却、规则和分数计算。
- 好友邀请入口保留，在线房间仍由两名真人对抗；机器人模式只用于单人练习和随时体验完整玩法。

## 策略成立的原因

玩家每次只获得一只系统发放的鹅，但要从多条赛道里选一路部署。大鹅提供较强合力，适合在关键赛道扭转战线；小鹅力量较低，但一旦漏过会造成更大扣分，可用来制造多路突破威胁。于是玩家要权衡集中力量阻止对方推进、补住弱势赛道、或把高扣分价值的小鹅送入有利路线。不同赛道当前鹅群、前线位置和未来三只预告会改变选择，不预设“大鹅永远集中”或“小鹅永远分散”为固定最优。

## 实现方向

1. 游戏仅保留 `game3d` 分包中的 Three.js 页面，作为目录和分享的唯一入口。水道、基地、鹅群、灯光和水面表现由实时几何与动画构成；玩法事件驱动鹅的位移、接触姿态和水花。旧 2D 页面及其专属素材已移除。
2. 规则层与显示层分离。规则层保存鹅型、内部力量、移动速度、过线扣分值、所属玩家、赛道和推进状态；界面不显示隐藏数值，只展示鹅形体型、动作、赛道对抗状态、未来三只预告和双方总分。
3. 以固定步长从共享时钟和部署事件重算每条赛道。先根据鹅间距离建立接触组：异方身体接触才开战，同方近距离跟随才提供支援；组外鹅独立慢速前进。局部合力相等时冻结接触组，有优势时按力差缓慢推移。每只鹅越过对面基地单独扣分，视觉跟随同一位置状态插值，不同步动画帧。
4. 双人房间复用 `useTacitBattle.ts` 和 `RoomSocket` 的建房、加入、快照、版本比较写入、资料交换与重连模式。房主通过 CAS 推进共享时钟，部署使用共享时刻；游戏数据类型升为 v6，旧规则房间提示重新创建，不保留两套规则。单人练习赛复用同一对局规则，不连实时房间。

## 主要页面反馈

- 顶部和底部显示双方昵称与当前分数；发生扣分时给分数条清晰反馈。
- 中间展示五条长水道、上下基地和移动中的鹅群，鹅慢速前进。鹅头朝行进方向，靠近对方基地的过线动画与扣分时点一致。
- 侧边显示未来三只鹅的幼年/成年形态及体型，队首显示发放倒计时；玩家点选水道部署当前待放置鹅。
- 通过战线位置、鹅群数量与冲刺状态反馈力量优势，不额外显示“力量差”等内部数字。

## 验收标准

1. 每条赛道可同时容纳双方多只鹅，队伍总力量相同则僵持，优势队伍推动战线。
2. 每只鹅越过对方基线只扣一次分；鹅型影响内部力量、速度和扣分，但界面不出现这些属性数值。
3. 小鹅扣分高、力量低；大鹅扣分低、力量高；玩家可通过三只预告和部署选道形成分散与集中策略。
4. 玩家只需点赛道部署；每次部署后队列顶位，下一只开始冷却，第三位随机补鹅；分数耗尽结束对局。机器人练习无需等待好友即可开局。
5. 赛道明确表现为五条长水道，上下两端是双方基地；鹅朝对方基地缓慢移动。远处的鹅不会影响对方，鹅接近并接触后才显示水花和受力/后退动作；离开接触范围后局部推力消失。
6. 双人联机后双方看到一致的鹅序列、部署结果、接触组、推移结果与比分；断线重连能恢复当前对局。


## 2026-11-17 视觉与接触模型修订

- 按用户效果图重做为小游戏全屏构图：农场水域场景、上下基地、正好五条等宽长赛道、双方分数条、三只鹅形预告、鹅群水痕与接触水花；界面不铺陈玩法说明。
- 鹅从上下基地朝对方缓慢移动。只有身体接触的敌鹅和跟在附近的同队支援鹅组成局部对抗组；远距离鹅不贡献力量。等力停住，有差时局部鹅群一起缓慢后退。
- 页面及房间协议先后迭代至 `goose-dash-v5`；最新队列规则使用 `goose-dash-v6`，旧房间需重新创建。机器人练习和好友房复用同一套物理接触与队列规则。
- 验收：类型检查与小程序构建通过；开发者工具预览确认小游戏页需开放 `demo-access`，真机观感、移动速度平衡及双端联机仍需用户试玩。

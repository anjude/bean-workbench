# MVP 功能范围建议

> 历史讨论资料：阶段划分供回顾，具体战斗规则和当前范围以 [本地对战 MVP 方案](../../plans/本地对战MVP方案.md) 为准。

## 目标与范围

先验证玩家是否能看懂多赛道局势，并愿意根据手牌和对手部署调整策略、再玩一局。首版以微信小游戏上的玩家对后台策略对手为主；完整产品仍包括割草副本、卡牌养成、合成、好友对战及抖音平台。

以下数量和时长是供试玩调整的建议，不是已确认的最终数值，也不是实施方案。

## 第一阶段：可完整试玩的对战

| 功能 | 建议首版内容 | 玩家能观察到的结果 |
| --- | --- | --- |
| 开始游戏 | 一个进入对战的入口，加载预设卡组，开始对局 | 玩家能进入一场新局，无需先养成 |
| 战场 | 建议 3 条独立赛道、双方基地血量、赛道战力和推进位置 | 玩家能辨认哪条线危险、哪方占优 |
| 手牌 | 建议 4 个手牌格、每 3 秒补 1 张；满手停止刷新，从预设卡池抽取 | 手牌消耗、补充、满手暂停均清晰可见 |
| 投放 | 点选卡牌再点赛道部署，展示选中和投放反馈 | 选中的牌消耗，对应赛道即时体现变化 |
| 卡牌 | 建议 3 种职责：高战力低伤害、均衡、低战力高基地伤害；明确展示属性 | 相同局势下选不同卡牌有可感知取舍 |
| 对冲和推进 | 双方战力按固定规则互耗，优势方逐步推进；突破后按规则扣基地血量 | 玩家看到双方损耗、推进与掉血之间的因果 |
| 后台对手 | 服务端按固定优先级观察赛道压力并部署手牌，设置反应间隔 | 对手有攻防动作，玩家改变部署后局面可能改变 |
| 结束和重玩 | 基地归零立即结束；设置对局超时和明确的平局/胜负规则；结算展示双方基地血量与结果，支持再来一局 | 每局能结束，结果与场上状态一致，重玩从新局开始 |
| 网络状态 | 显示连接中、断线与恢复结果；重连后获取服务端最新状态；无法恢复时允许退出重开 | 不会把断线或重复点击误判为已部署或胜利 |

服务端负责手牌、战斗推进、对手策略和胜负；客户端负责输入与表现。具体对冲公式、伤害、对手优先级、超时判定和重连时限需要在开发方案中给出可执行的规则。先做简单单位和占位画面即可，但对冲、突破和基地受伤必须直观。

## 第二阶段：最小成长闭环

首阶段对战得到正向试玩反馈后，再接入以下功能，验证成长是否让玩家愿意返回对战：

1. **对局奖励。** 胜负均给金币和普通碎片，胜负差距较小；结算只发放一次。
2. **卡牌升级。** 在卡牌页消耗金币和普通碎片，升级一张卡；下次对局使用升级后的属性。
3. **固定配方合成。** 至少提供一条可见配方，明确消耗的低阶卡牌和稀有素材、结果与消耗后卡池变化。
4. **最小割草副本。** 一个短关卡，玩家从已有卡牌中选一名角色，单指移动、自动攻击、怪物生成和伤害；击杀触发三选一局内强化，死亡或通关均有明确结算；产出升级碎片和可合成所需的稀有素材。副本强化不进入对战。
5. **成长存档。** 保存卡牌、材料和结算结果；退出重新进入后仍可查看，重复结算不重复发奖。

这一阶段完成后才能检验“对战遇阻 → 副本获取材料 → 升级或合成 → 再战”的完整产品闭环。素材产出、升级幅度与脚本对手强度需一起调节，避免升级后对局失去策略空间。

## 暂缓的功能

- 真人匹配、邀请好友、排名和赛季：首版先验证人机对战规则。
- 多章节副本、大量角色、复杂技能和丰富局内组合：先验证一个关卡和少量强化。
- 皮肤、社交、复杂商店和运营活动：不影响核心循环判断。
- 激励广告双倍领取与抖音适配：先用微信目标端完成核心玩法验证，之后各自接入和验收；完整产品仍采用纯 IAA。

## 试玩验收建议

- 不依赖讲解，玩家能指出三条线的优势、基地剩余血量，并完成一次部署。
- 连续完成至少三局；手牌刷新、满手暂停、对冲、突破、结束和重玩都按规则表现。
- 使用同一初始卡组，在相同对手策略下尝试不同部署，观察到可解释的局势差异。
- 断线后重连能恢复当前战局；无法恢复时明确告知并允许退出，不能重复结算。
- 第二阶段完成后，能完整走通至少一次获取资源、升级或合成、再次对战，并在重进后保留成长。
- 在微信开发者工具与真实微信目标设备核对操作、画面和网络体验；试玩前对局时长、战力与伤害数值可调整，构建成功不代表玩法验收通过。

## 下一步设计

本清单用于讨论 MVP 范围。进入实现前还需形成可执行的完整开发方案，确定战斗公式、卡牌配置、对手策略、接口与消息、数据存储、状态恢复和验收方式；具体数字应在试玩中迭代。

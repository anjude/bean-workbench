# Demo 首页设置入口

## 背景

首页在入口模式关闭时作为 demo 展示，但目前 header 的设置入口只在 `store.isReal` 时出现；设置页自身也受正式页面门禁限制，导致 demo 用户无法进入设置。

## 需求理解

让 demo 首页和正式首页都显示设置入口，并允许从 demo 首页打开既有设置页。设置页现有的个人资料、主题与常用服务照常展示；管理员工具仍只对管理员可见。

## 目标与边界

### 本期目标

- demo 首页可通过 header 的设置入口打开设置页。
- 正式首页入口行为保持一致。
- 非管理员在设置页仍看不到管理员工具。

### 本期不做

- 不调整设置页内容、用户资料能力、主题能力或管理员权限。
- 不改变其他页面的 demo 门禁。

## 改动范围

### 涉及仓库

- `business-repo/uni-gknow`
- 工作台任务方案与过程记录。

### 涉及库表

- 无。

### 涉及接口

- 无新增接口；设置页既有数据行为不变。

### 涉及前端契约

- 无。

### 页面与状态

- 首页属于 dashboard / 入口页；主任务仍是浏览和进入体验，设置作为 header 次级入口。
- 设置页属于 config / settings。
- 首次加载中：沿用 `gk-page` 全局加载态。
- 应用初始化失败：沿用全局失败态和重试，不显示可用页面入口。
- 正式入口模式：设置入口可见，设置页正常打开。
- Demo 模式：设置入口可见，设置页以 `demoAccess` 放行；非管理员仅显示普通设置，管理员区继续依据 `store.isAdmin` 控制。
- 跳转失败：给出轻提示，留在首页；目标页返回仍使用现有返回导航。

## 实施方案

1. 在 `business-repo/uni-gknow/src/pages/index/index.vue` 去掉设置入口的 `store.isReal` 显示条件，保留现有跳转函数。
2. 在 `business-repo/uni-gknow/src/pages/settings/index.vue` 为 `gk-page` 开启 `demo-access`，沿用页面内现有管理员条件。
3. 为首页设置跳转补充失败 toast。

## 验收标准

- demo 模式首页显示设置入口，点击进入设置页并可返回首页。
- 正式模式首页仍可进入设置页。
- 非管理员在 demo 模式看不到管理员工具；管理员权限判断不变。
- `npm run type-check` 与 `npm run build:mp-weixin` 通过。

## 推荐实施顺序

1. 更新首页入口和设置页 demo 门禁。
2. 完成类型检查与微信小程序构建。
3. 由用户在微信开发者工具中确认 demo/正式模式的实际跳转与返回。

| 序号 | 场景 | 操作 | 预期结果 |
|---|---|---|---|
| 1 | Demo 首页 | 关闭入口模式后在首页点击设置 | 打开设置页，可查看普通设置并返回首页 |
| 2 | 正式首页 | 开启入口模式后点击设置 | 设置页正常打开 |
| 3 | 普通用户 | 以非管理员进入设置页 | 管理员工具不显示 |
| 4 | 跳转失败 | 模拟设置页导航失败 | 显示轻提示并留在首页 |

### 兼容性测试

## 风险与回滚

- 设置页对所有已进入 demo 首页的用户可用；管理员功能仍由页面内既有权限判断隔离。
- 如发现设置内容不适合 demo 入口，可回滚该页 `demo-access` 属性，并保留首页原始可见条件。

## 落地记录

- 首页设置按钮在 demo/正式模式均显示，导航失败时给出 toast。
- 设置页增加 `demoAccess`；管理员区仍只由 `store.isAdmin` 控制。
- `npm run type-check`、`npm run build:mp-weixin` 与 `git diff --check` 通过；微信开发者工具中的实际跳转待用户验收。

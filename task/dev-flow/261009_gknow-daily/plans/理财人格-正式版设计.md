## 已确认的基线

用户已确认当前封面和整体画风：纸色、墨线、二维平面色块、阿白角色、浅青编号、金色主操作。答题与回看沿用这一套，不再次探索视觉方向。封面只出现一个主标题，说明需要交代体验和选择方式。

内容锚点为当前`business-repo/uni-gknow/src/data/financeStockSamples.ts`四题：卖飞后重新买入、买入理由变化、朋友赚得更多、止损计划。题文和选项已获认可，新题需达到同样的自然程度，不能因为采用本稿骨架就视为已通过。

本轮授权是“开始走设计”，不是把候选题、计分、分类和发布自动实施。

## 产品要给用户什么

让用户在几个投资现场认出自己的反应，并在最后看到：自己反复怎样选择、什么情况会改变做法、这两者之间有什么有意思的关系。

这里的“理财人格”是产品中的趣味行为画像。先从选择归纳描述，不把单次动作扩写成能力、收益预测或长期稳定的人格事实。没有实际选择依据的话不写；不把某种投资方法评为更高级。

## 本轮设计边界

先完成股票路线，再单独设计基金与无投资经验路线。依据是用户最初明确反馈“选了股票却出现生活琐事”，以及本轮认可的具体场景；这是一项产品范围提案，不等于用户已批准全部路线或准入限制。

股票路线不使用借钱、兼职到账、旅行预算等生活消费场景代替专业现场。比较对象可以是基金或朋友，但决策冲突仍落在投资行为上。人物身份采用情境邀请，避免断言玩家真实经历。

本轮不扩展全产品入口、不新增服务端、不恢复旧12个鹅标签，也不为未完成的路线显示可点击入口。大众适用性作为后续独立设计事项，不靠给股票玩家换生活题来解决。

## 一轮怎样组织

建议先设计固定12题：六组观察主题，每组两个不同现场。理由是需要重复观察，且当前四题只涉及少量处境；12是本次内容设计预算，不代表足以形成经过验证的测量。

先固定一套，便于定位题感和结果问题；暂不做随机大题库、经验换题或临时加题。选完直接下一题，进度如实显示，允许跳过；不点评上一题，避免下一题变成迎合点评。

六组是给设计者的观察索引，不显示给玩家，不直接对应六个人格标签，也不先规定正反向分数。

| 组 | 观察的冲突 | 两个现场想分清什么 |
| --- | --- | --- |
| 机会 | 错过后面的上涨 / 接受眼前买贵 | 判断是否仍支持行动，旧价格怎样影响决定 |
| 亏损 | 结束亏损 / 保留回本机会 | 同样亏损，不同依据下会怎样处理仓位 |
| 证据 | 新事实 / 已形成的判断 | 原依据改变时能否调整，利好是否同样被审视 |
| 计划 | 事先规则 / 临场舍不得 | 面对亏损与盈利时是否采用不同标准 |
| 他人 | 自己的做法 / 他人的收益与行动 | 是收益差距引发改变，还是别人的行动本身也有影响 |
| 不确定 | 信息没有齐 / 机会不会一直等 | 需要确认到什么程度，会怎样控制试错范围 |

### 12个题位草案

以下只有S01—S04是当前认可的具体题目，S05—S12为场景提案，尚未完成选项审稿。题位顺序交错，两个相似现场不连续出现。

| 题位 | 场景 | 观察组 | 状态与设计重点 |
| --- | --- | --- | --- |
| S01 | 昨天卖掉，今天又涨8%，仍然看好 | 机会 | 已确认；保留8%，不加无关盈利金额 |
| S02 | 买入看好的新业务被取消，持仓跌15% | 证据 | 已确认；看依据被推翻后的行动 |
| S03 | 朋友短线一个月赚过自己一年，发来股票 | 他人 | 已确认；使用“一直买宽基基金的你”邀请代入 |
| S04 | 事先定亏10%卖，实际跌12%，无新消息 | 计划 | 已确认；原规则和临场情绪冲突 |
| S05 | 研究过的一只股票挂单未成交，再看已涨，判断未变 | 机会 | 新题；没有“已经赚过”作退场理由，与S01区分 |
| S06 | 持仓跌15%，当初买入理由仍在，没有事先止损规则 | 亏损 | 新题；与S02区分“依据失效”，与S04区分“违背计划” |
| S07 | 自己的股票没出新消息，群里熟悉的人却陆续卖掉 | 他人 | 新题；没有别人赚更多的刺激，观察行动本身的影响 |
| S08 | 原来不买是因为公司持续亏损，现在公告开始盈利 | 证据 | 新题；利好也可能要核实，不能让唯一体面选项变成“查资料” |
| S09 | 到了自己事先定的止盈位置，走势还强，暂无新消息 | 计划 | 新题；与S04对照盈利/亏损情境里的规则执行 |
| S10 | 套了一阵的股票终于回本，原来的判断没有新变化 | 亏损 | 新题；回本价如何影响退出，不把成本价当知识考点 |
| S11 | 想买一家公司，大体看懂，但一个关键问题没想清 | 不确定 | 新题；关键问题要写具体，避免“资料还不够”的空泛背景 |
| S12 | 看中的股票遇到两份相反解读，两方都有可查的依据 | 不确定 | 新题；把冲突写到足以选择，不能只说“专家意见不一” |

S06与S02/S04、S09与S04构成设计上的对照，不是控制其他条件后可直接归因的实验。写成实际题文后还要检查是否重复、是否容易被玩家猜到“在测什么”。S11/S12若落成文字后过于相似，优先换掉一题，不靠换公司名凑数。

## 每道题的出题约束

### 题面

1. 先确定一个真实决策冲突，再写场景；不用人格名称反推选项。
2. 写清现在的持仓/操作状态、发生了什么、还在犹豫什么。细节只保留会影响选择的条件。
3. 数字有作用才留：8%改变重新买入的门槛；无关的“两千元收益”不留。金额没有本金和用途时不要假装精确。
4. 用情境邀请代入，不把虚构经历断言为玩家的真实经历。
5. 场景短，但不能省到玩家需要补关键事实才能回答。

### 问题与选项

1. 一题确定问情绪、行动还是最终决定；当前这组主问行动。
2. 四个选项处于同一层面，不能混放“发牢骚”“查消息”和“买入/不买入”来推断同一种投资决策。
3. 写成当下的自然短反应，短语即可，不要求完整句子，不加句尾句号。
4. 一个核心动作，可带一句必要念头；不追加分析、辩护或人格解释。
5. 四种选择都要有可理解的动机和代价；不安排明显愚蠢/自私/不负责任的陪衬答案。
6. 检查是否只是同一个人依次会做的几步，或核心动作重复。若不同动机导致同一动作，不能仅凭这题认定是哪种动机。
7. 选项不能全是“理性建议”，也不为表达冲动而替玩家贴贬义标签。
8. 用户愿意认领某个选项，是内容门槛；形式完整、字数短和构建通过都不能替代。

## 从答案到结果

### 先保留事实，再写解释

每次选择记录题目版本、题号、选项、是否跳过。记录“用户选择了什么”，不立刻变成某个人格的一票。答题时不展示归类和评价。

设计阶段为每个选项写两栏：可以支持的解释、不能由它证明的解释。例如S01选择少买回一点，可以支持“在参与与控制投入之间留余地”；不能单凭这一项写成“你永远稳健”“你擅长风险管理”或“你害怕错过”。

### 第一版结果结构

1. **一句主观察**：用户在多个不同现场出现的选择倾向，用平实但有识别度的表达。
2. **两个具体回扣**：引用真实选项，讲清这句话从哪来。
3. **一个条件或反差**：当什么条件变了，用户会改变做法；若证据没有反差，不硬编。
4. **完整选择回看**：保留当前纸卡形式。
5. **重玩/回首页**：沿用当前节奏；分享海报在结果文案得到认可后再设计。

例子仅用于展示结构，不是已命名的人格：“你愿意重新上车，但不愿一次压满”。只有不同现场都真的选择了小规模参与，才有资格展示这句话。对应证据不足时，不输出这个结论。

### 证据规则的设计底线

- 一次选择只描述这次选择，不直接生成主标签。
- 主观察必须有至少两个不同现场的可解释依据；这是产品文案的最低展示约束，不是科学可信度门槛。两个答案即便一致，也可能不足以区分动机。
- 某主题只答一题、跳过太多或出现无法解释的相反选择时，显示局部观察或仅回看，不强凑单一人格。
- “一致”与“矛盾”需结合新消息、原计划、仓位等条件判断，不能直接按相同字母计数。
- 不为了让每个人都拿到一个漂亮结果，把其他选择硬解释成同一标签。
- 不输出准确率、百分位、收益能力或投资适宜性结论。

暂不确定权重、分界值或人格数量：先写完并审过具体选项，再用可观察的答案组合检验结果文案是否站得住。旧版按信号机会计数的算法不会自动继承到新设计。

## 页面与状态设计

| 状态 | 呈现和操作 |
| --- | --- |
| 封面 | 固定当前风格；完整稿确认后仅同步实际题数与结果说明 |
| 作答 | 一个场景重点、一段必要背景、一个问题、四个短选项；直接推进 |
| 已选/快速重复点击 | 明确选中反馈并锁定，沿用当前防重复 |
| 跳过 | 不补选、不默认为某倾向，计入真实进度 |
| 后台/恢复 | 暂停切题，恢复后继续；不在后台连续推进 |
| 图形失败 | 文字保留，必要时文字补足图形事实；不阻塞选择 |
| 证据可解释 | 主观察、真实回扣、条件描述、完整回看 |
| 证据不足/全跳过 | 只提供可支持的局部描述或回看，不制造人格 |
| 重玩 | 清空本轮选择、图文状态和定时器，不带入上一轮结论 |

不存在新API、服务端加载或权限流程。本轮仍全本地，不新增全量作答上报。

## 审稿与验收顺序

1. 先确认这12个场景的范围和观察关系，再补S05—S12具体题文；不一口气把未审题库写入代码。
2. 新题每批2—3道：题感、可认领选项和细节必要性过关后，再进入下一批。
3. 为完整选项补“支持/不能证明”的解释表，检查同一动作不同原因，不先给鹅起名字。
4. 用几组有明显不同选择的模拟记录试写结果；也包括混合、转变和跳过，检查是否引用真实依据。
5. 结果读起来能认出自己，再决定人格命名与分享方式。
6. 产品设计确认后进入开发、type-check、微信构建和真实页面流程检查；技术检查不替代内容验收。

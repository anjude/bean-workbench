## 2026-10-15 微信小程序启动更新检测

- 目标：进入鹅懂个啥后使用微信小程序更新管理器检查新版本；新版本下载完成时提示用户重启应用，用户确认后应用更新。
- 改动范围：`business-repo/uni-gknow/src/utils/adapt/update.ts` 封装微信平台更新管理器；`src/App.vue` 在 `onLaunch` 注册一次。无页面、数据库、后端接口、共享契约和资产变更。
- 状态与回退：无更新时不提示；有更新但下载中时继续使用当前版本；下载完成时弹出「立即更新 / 稍后」，确认才重启；下载失败时提示稍后重新进入，不阻断当前游戏。非微信平台不执行更新检查；重复调用不重复注册监听或弹窗。
- 验收：`npm run type-check`、`npm run build:mp-weixin`、`git diff --check` 通过；构建产物中应用启动入口调用更新检查。正式版发布新版本后的真实更新提示、取消和重启行为在微信端验收。
- API 依据：[uni-app `uni.getUpdateManager()` 文档](https://uniapp.dcloud.net.cn/api/other/update)。

### 落地记录

- 新增 `src/utils/adapt/update.ts`：微信小程序启动时注册一次更新管理器；新包下载完成后询问是否立即重启，确认后调用 `applyUpdate()`；下载失败显示非阻断提示。`src/App.vue` 的 `onLaunch` 完成注册。
- `npm run type-check`、`npm run build:mp-weixin`、`git diff --check` 通过；构建产物 `dist/build/mp-weixin/app.js` 含启动调用，`utils/adapt/update.js` 含更新提示和应用更新逻辑。
- 真实更新事件依赖微信发布新版本，开发构建只能确认接线和编译，不能代替发布后的端上验收。过程结论见 `task/dev-flow/261009_gknow-daily/process/00-方案设计.md`、`task/dev-flow/261009_gknow-daily/process/02-前端开发.md`、`task/dev-flow/261009_gknow-daily/process/03-整体验证.md`。

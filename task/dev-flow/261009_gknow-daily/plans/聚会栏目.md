# 聚会栏目：记分板与摇骰子

- 日期：2026-11-01
- 状态：2026-11-01 按用户要求撤下小程序「聚会」入口、记分板、摇骰子及对应前端实现。本文仅保留历史需求与方案，不代表当前功能；通用 FE Redis 能力和后端未改。

## 背景

用户提出在现有大转盘之外增加聚会工具，首版至少包含记分和骰子类玩法。栏目名称确定为「聚会」。记分数据使用小程序已有 FE Redis 接口临时同步；每位参与者在自己的小程序本地保存结果，不建立长期云端历史，不修改后端。

## 需求理解

在鹅懂个啥小程序「工具」分类下增加「聚会」入口，进入后可选择「记分板」或「摇骰子」。记分板以 6 位数字房间号作为 FE Redis key，通过房间号或微信分享加入；使用已有 FE Redis 读、条件写接口同步，前台每 4 秒轮询快照。摇骰子页面提供单机骰盅，不建立骰子房间、不联网；骰面保存在本机，不替用户规定桌上怎么玩。

## 目标与边界

### 本期目标

- 增加「聚会」工具目录，说明为「记分、摇骰子，聚会马上开玩」。
- 记分板按实际入房人数自动生成玩家，无需房主预设人数；逐轮录入正负分、显示每人累计分、撤销上一轮、结束并保存本局。
- 摇骰子使用全屏单机骰盅。支持 1–6 枚标准六面骰，默认 5 枚。点击开始本盘后只生成一次骰面并合上骰盅；玩家可以反复打开查看骰面，再合上继续游戏，开合不会重新随机。打开时显示每颗骰面与总点数。骰子数量在本盘开始后锁定；玩家明确结束本盘后，才能调整数量并开始下一盘。页面不替用户限制使用哪种桌游玩法。
- 美术以简洁桌面色彩、少量光影和独立轻量 SVG 骰盅图为主；骰盅摇动时有动画，打开时移开遮挡，显示当前固定的骰面与合计。页面全程保持相同骰面，离开后再次进入默认合盅。
- 记分房间使用现有 FE Redis 接口保存共享快照，房间号为 6 位数字；数据通过普通 HTTP 请求即时同步，前台每 4 秒轮询。房间最长逻辑有效期 2 小时，每位参与者本地保存最近 20 局记分记录。
- 记分板首页直接显示 6 位房间号输入框和「加入房间」按钮，同时提供「创建新房间」按钮；进入记分房间后只显示当前房间操作，不混入加入房间选项。玩家列表随实际进入房间的用户自动增加。

### 本期不做

- 不实现麻将番型、牌类自动结算、现金/输赢金额、云端历史和排行榜。
- 不新建后端业务表、独立 Redis key 设计、接口或共享契约；不修改通用实时房间服务。
- 不把功能做成微信小游戏独立工程；它属于 `uni-gknow` 小程序的「工具」分类。
- 不复刻参考截图中的外部角色或素材；只参考骰子选择、摇动、点数及记录的交互信息。

## 原型与页面状态

- 「聚会」入口：实用工具目录中的普通项目卡。
- 「聚会」页：轻量 dashboard，两个直接入口：记分板、摇骰子。
- 记分板页：detail + 临时多人空间。状态包括未创建、创建中、等待/进行中、已完成、重连中、房间失效、房间人数满、保存失败。
- 摇骰子页：状态包括待开本盘、摇动中、骰盅合起、骰盅打开、确认结束本盘、等待下一盘；无网络依赖。当前一盘的骰面固定保存在本机，重新进入页面默认合盅；已开始本盘时不能调整骰子数；结束本盘后才解锁数量并出现下一盘入口。
- 记分板由房主录入分数，其他成员查看；每个加入房间的用户自动成为玩家，只有房主能结束本局。通用房间服务不在服务端验证游戏规则，因此这是轻量聚会记录，不作为可信结算凭证。
- 每盘保存当前玩家的 1–6 枚骰面；打开时同时显示逐颗点数和合计。点数在本盘开始时生成，反复开合只显示同一组点数；仅在结束本盘后清除当前手牌。

## 数据与系统设计

- 前端仓：`business-repo/uni-gknow`。新增工具入口、页面、状态 composable 与样式；不改首页分类结构。
- 前端仓：复用现有 FE Redis `get`、`compare_set`、`set` 接口；以 6 位数字房间号形成房间 key，客户端负责房间到期判断与成员更新。
- 不修改后端仓和共享契约仓；Redis 仅用于临时同步，记分结果由各参与者保存在本机。记分房间不预设人数上限，按实际进入房间的成员生成玩家。
- 记分房间数据：`{ kind: 'party-score-v1', owner, status, players, rounds, createdAt, finishedAt? }`。玩家为本局记分对象，轮次保存每人本轮增减分；累计分由轮次汇总，防止多端分别维护冗余总分。
- 大话骰使用现有本地历史存储保存骰子数量、已结束盘面和当前盘面；骰面只属于本机账号，不占 Redis 房间。返回或重新进入时先合盅，不重新生成骰面。
- 记分多端更新使用 FE Redis `compare_set` 与冲突重读重试；每 4 秒前台轮询快照，页面隐藏时暂停。任何参加者均可修改共享数据，游戏规则不承担安全或财务可信性。

## 验收标准

1. 工具分类可找到「聚会」，打开后可进入记分板和摇骰子。
2. 房主创建房间后，自己自动成为玩家；每个通过分享或房间号进入的用户自动加入玩家列表，无需事先设定人数；录入正负分后，所有已加入设备看到相同轮次与累计分；撤销恢复上一轮；结束后各端本地记录可回看。
3. 微信分享链接携带 6 位数字房间号，可直接加入；也可在记分板输入 6 位房间号加入。无效链接、过期房间与同步失败均显示明确状态和恢复动作。
4. 支持单机一盘一掷：开始本盘只摇一次并合盅；打开可看到固定骰面与点数合计，合上后再开仍为相同骰面；本盘未结束前不能重新摇或改数量；结束本盘后才能调整数量并明确开始下一盘。不要求联网或创建房间，不强加具体桌游玩法规则。
5. 重进仍存活的记分房间可从 Redis 快照恢复；房间过期后不能伪装成空房间或覆盖本机历史。
6. 结束记分房间不写数据库；本地历史清理只影响当前设备。

## 验证方案

- 开发后运行 `npm run type-check` 与 `npm run build:mp-weixin`。
- 检查共享房间状态逻辑：版本冲突、断线重连、TTL 过期、重复点击与本地存储失败。
- 小程序目标端需双账号/双设备验证邀请加入、两端同步、返回重进与本地记录；编译结果不能替代真实房间验收。

## 风险与回滚

- 通用房间最长 2 小时，房间到期后 Redis 数据清理；本地历史是各设备独立副本，不支持跨设备恢复。
- 通用房间服务不验证用户提交的游戏业务数据；版本控制只避免并发覆盖，不防恶意改分。产品界面明确为聚会记分，非结算凭证。
- 回滚时移除聚会目录入口、页面路由及本次新增页面/composable/样式，不触碰已有 FE Redis 接口或其他未提交功能。

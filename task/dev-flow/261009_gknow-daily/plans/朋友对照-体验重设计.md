# 朋友对照 · 体验重设计

- 状态：用户确认方向后已实现，等待实际体验反馈。2026-10-29 用户反馈现版 UI 和功能设计不好，要求参考理财人格；此前的实现完成不代表体验获认可。
- 参考：`business-repo/uni-gknow/src/pages/quiz/finance-personality/index.vue` 和 `src/composables/useFinanceStoryPresentation.ts`。

## 观察

理财人格把用户带进一个具体现场：封面先建立主题，答题时每屏集中在场景、问题和选项，选后短暂反馈并自动进入下一题；结果先给一个容易理解的整体，再提供后续动作。朋友对照当前更像表单和记录管理：每题需要额外点击下一题，结束后直接堆六张答案卡，首页把刷新和记录等操作与主要体验放在一起。用户尚未表达希望逐项照搬哪些细节，视觉参考与玩法机制应分别确认。

## 建议体验

1. 封面：一句话说清“我觉得自己是这样，朋友看到的呢”，用有角色感的封面场景和一个开始按钮；已有记录用低权重入口进入，不在封面解释存储、刷新等机制。
2. 自评：每题一个生活现场，先给情境再给提问，选项直接作答；参考理财人格，选择后短暂反馈并自动进入下一题，允许跳过。最后一题完成后形成邀请页。
3. 邀请：以“我选好了，轮到你看我了”为主题，突出发给朋友；多位朋友可参与。已收到的回答以一行自然的“已有N位朋友填过”进入记录。
4. 朋友进入：明确正在回答谁，直接带入同一套场景；可选没见过，提交后得到与发起人的对照。每个人独立填写，与多人规则一致。
5. 结果：先用一张有视觉重心的结果页说明“你们有哪些地方看法相同、哪些不一样”，针对实际选项展示一到两处具体差异；不虚构人格或关系判断。完整六题作为“看看每一题”的次级入口。
6. 记录：在玩法首页进入，按朋友呈现姓名和最新一次对照摘要，点开后能看到该朋友所有填写记录并进入完整结果；图鉴显示人数并跳玩法首页。

## 状态与边界

- 答题自动前进期间防止重复选择；页面隐藏时暂停，恢复后继续。提交或网络失败保留已答内容，并可重试。
- 完全跳过或只有一方有答案时，不制造一致率和结论；直接说明可比较的题不够。
- 发起人重测仍需提示旧邀请失效，已收录的历史保留；邀请过期、朋友重复进入、记录加载失败都有清楚的恢复路径。
- 继续复用现有Redis多人规则、本机记录和七天期限；前端读取和展示个人答案时遵守当前能力边界。

## 2026-10-29 Redis规则简化（用户新要求）

用户纠正：每个openid一个Redis key，保存七天；每次填完更新该用户key自己的选项，每条对照记录保存双方当时的选项。继续支持一人发起、多位朋友填写，图鉴查看人数与记录。此前的发送人+填写人组合key及单独填写人索引设计不再作为目标方案。

拟采用每人一个玩法value：自己的最新自评、涉及本人的对照记录（对方标识、双方当次答案快照和时间）。朋友填写时，双方都需要保留同一份快照，发起人从自己的key即可读取朋友记录；连续更新按七天设置过期。两次写入间的失败需保留可重试状态；多人同时改写同一value沿用用户此前明确接受的简单读写取舍。具体跨邀请、自评及对照数据结构需要在实现中明确，不能把朋友对发起人的评价误当成朋友自己的自评。

现有实现仍使用发起key、两人组合答卷key和填写人索引；本轮仅明确新目标，代码尚未迁移或验证。

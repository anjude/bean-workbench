# 项目自检与优化方向

- 日期：2026-10-29
- 范围：当前工作区源码、产品文档、类型检查与微信构建。包含未提交的基金路线与鹅在哪里实现；不等同线上版本或微信实机验收。
- 本轮未修改业务源码，未提交、推送或部署。

## 结论

已有两项正式测试、四款目录内小游戏和一个转盘工具。下一轮优先补结果留存、每日内容变化和朋友互动，让现有玩法形成连续体验。以下方向为建议，尚未获实施确认。

## 确认的问题与缺口

1. 图鉴读取异常被吞掉：`src/composables/useGooseAtlas.ts` 的 readRecords 捕获异常返回空数组，refresh 因而始终把 storageError 置为 false。页面已有失败提示却无法覆盖该路径；后续写入还可能把旧记录读取失败当作无记录处理。应区分空数据、格式异常和读取失败，失败时避免覆盖写。
2. 理财人格未接入图鉴：`src/data/gooseAtlas.ts` 测试清单仅含 goose-bti/goose-style，理财人格页面与 composable 没有保存结果。用户离开后无法从图鉴回看股票或基金结果。
3. 烟雾弹时长口径不一致：页面、目录为58秒；`src/pages/collection/index.vue` 的详情及海报仍写60秒。建议统一读取玩法配置。
4. 鹅在哪里本地存储读写缺少异常保护：`src/composables/useGooseGrid.ts` 初始化、通关、引导和音效设置直接调用同步存储。存储异常可打断初始化或结算；应允许本轮继续并提示保存失败。
5. 续玩缺口：理财测试答案只在内存中；找鹅仅保存解锁关卡，不保存当前盘面。建议按玩法版本保存草稿，进入时提供继续或重来。

## 优化优先顺序

1. 先补图鉴错误处理、时长文案、理财结果收录与续玩，修复已发生动作无法留存的体验断点。
2. 每日同题挑战：当前 `src/data/dailyChallenge.ts` 只按日期轮换三个项目，未将日期作为统一题面种子传入玩法。可先在找鹅或点灯做每天固定一盘，重玩保持题面，分享带日期和版本。成绩比较必须基于相同规则与题面。
3. 朋友结果对照：从鹅BTI开始，同一情境展示两人的选择差异及具体相处建议，避免编造匹配百分比。需要明确共享范围、双方参与和结果保存方式。
4. 自定义转盘：允许输入、保存和复用自己的选项，再考虑分享同一组选项。先核对既有转盘偏好模型，控制新增范围。
5. 在扩玩法前补基本漏斗：进入、开始、完成、触发分享、分享链接打开。分享按钮触发不能当作成功送达；先用完成率和分享落地后的开玩率判断改动效果。

## 实现层面的后续评估

- `gk-page.vue` 与 `stores/app.ts` 将所有内容展示绑定登录、用户资料及系统信息成功。弱网启动可能阻挡纯本地玩法。这是既有明确门禁约定，需单独设计安全的配置缓存与失败回退，不能直接绕过。
- 当前产物磁盘占用约1.6M，静态插画约652K，pages.json尚无分包。磁盘尺寸不等于微信上传包体大小；新增资产前应观察开发者工具报告，再决定分包或压缩优先级。
- 尚未验证微信触摸、音频、扫码落点与原生分享，也没有真实使用漏斗数据；不能据代码审阅断言用户流失原因。

## 2026-10-14 回访闭环一期：今日挑战与鹅图鉴

### 目标与边界

让用户有一个轻量、每天不同的回访理由，并能看到持续积累。本期将正式小游戏纳入每日挑战，完成后自动保存一张当日挑战卡到「鹅图鉴」。

本期不做签到奖励、经验等级、随机抽卡、排行榜、好友关系与后端同步；不因漏玩给用户断签或惩罚。挑战历史先存本机，后续确认价值后再规划账号同步。

### 规则

- 每个本地自然日按日期稳定选择一款已启用每日挑战的小游戏；当前候选为「鹅会读心」「鹅的烟雾弹」和「鹅来点灯」，按日轮换。新增小游戏通过项目目录中的 challenge 配置接入。
- 用户从首页进入当日挑战，游戏完成结算时记一条日期卡；中途退出不计完成。
- 同一天重复挑战不重复发卡；烟雾弹保留当日最佳得分，鹅会读心记录完成。
- 次日挑战自动切换。图鉴保存最近 365 天完成卡，无连续签到奖励或缺席惩罚。
- 数据位于本机 storage，不调用后端、不跨设备同步；读取损坏或为空时回退为空图鉴，保存失败时继续正常玩并提示。

### 页面原型与状态

- 首页沿用内容入口型 dashboard：品牌欢迎区之后新增紧凑「今日挑战」卡，展示玩法、简短目标、今日完成状态及图鉴数量；不挤掉现有三大分类直达。
- 新增 `/pages/collection/index` 图鉴页，按日期倒序显示挑战卡；空状态引导去完成今天的挑战。
- 状态矩阵：首次 / 无记录 → 首页显示开始挑战、图鉴为空态；进行中 → 未生成卡，可退出；完成 → 结果页说明已收录，首页标已完成，图鉴新增日期卡；同日再次完成 → 更新烟雾弹最佳分、不重复计数；跨日 → 生成新挑战；storage 异常 → 页面可继续使用、列表回退空态并提示无法保存。

### 文件与验证

- 业务仓：`src/data/projectCatalog.ts` 配置可参与挑战的项目；新增 `src/data/dailyChallenge.ts`、`src/composables/useDailyChallenge.ts`；修改首页、两款小游戏结果页与样式；新增图鉴页、路由和样式。
- 无后端表、接口或共享契约改动。
- 验收：每日分配稳定且会轮换；完成后卡片只生成一次；重玩只更新最佳分；中途离开无记录；跨日切换；空图鉴可进入挑战；原小游戏独立入口和结算不受影响；类型检查和微信小程序构建通过。

- 图鉴使用独立 storage key `gk.goose-atlas.v1`，不读取、不迁移每日挑战记录或其他旧记录。每日挑战仍独立运行。

- 实现位于 `src/data/gooseAtlas.ts`、`src/composables/useGooseAtlas.ts`、`src/pages/collection/index.vue` 和 `src/styles/06-pages/_collection.scss`；游戏与测试结算时写入记录，共用 `gk-result-poster` 增加隐藏触发器和程序化打开方法。

## 2026-10-15 鹅图鉴海报切换修复

- 背景：用户反馈鹅图鉴中只有第一个项目能生成海报，其余项目失败。
- 需求理解：图鉴复用同一个 `gk-result-poster` 实例；海报首次成功后 `posterPath` 一直缓存，后续项目打开时因缓存短路而不会按新项目重新绘制，导致各项目不能生成自己的海报。
- 目标与边界：项目切换后失效旧海报缓存并依据当前项目数据重新绘制；不修改图鉴记录、二维码接口和其他分享入口。
- 改动范围：`business-repo/uni-gknow/src/components/gk-result-poster.vue`（监听海报内容变化并清除预览缓存）；必要时仅调整 `src/pages/collection/index.vue` 的海报内容绑定；无数据库、接口或契约变更。
- 页面状态：首次打开生成中/成功/失败可重试；切换项目后显示新项目内容并重新生成；关闭后再次打开同一项目可复用已生成图；生成过程中的重复点击不重复绘制。
- 验收：先后从至少两个不同已解锁项目打开海报，标题、指标和小程序码均对应当前项目；重开同一项目不重复请求；类型检查与微信小程序构建通过。

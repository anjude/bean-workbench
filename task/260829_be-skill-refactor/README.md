# be 族 skill 四阶段重构

## 背景

`be-*` 后端族群在两轮编号规范化后只是把旧名换成了编号，流水线语义仍然是平的：8 个 skill 用「设计 / 开发 / 交付」三阶段划分，但实际使用时暴露三个问题。

1. **没有独立的方案设计阶段**。方案设计只是原总控 `be-0000-dev-flow` 里的一个「方案确认模式」章节，和代码定位、自动实现、数据库变更、验证命令混在同一份 196 行文档里。需求进来时该先做什么、产出什么、什么条件下才允许动代码，没有成文的门禁。
2. **总控过重**。`be-0000-dev-flow` 同时承担项目上下文、工作模式、阶段编排、测试方案模板、输出格式五件事。任何一处要改都得动这份文件，其他 skill 又各自重复抄了一遍路径约定。
3. **没有工具层**。项目上下文、分支部署语义、数据库只读排查这类横切能力，要么散在总控里，要么埋在原 `be-0101-db-change-flow` 的验证章节里，无法被单个阶段独立调用。

同时，前后端两条线最终要合成一个开发族。这次先给 be 族定下阶段骨架，把前端阶段的编号位留出来，`fe-*` 本次不动。

## 目标

1. 定义一次后端需求的四个阶段：方案设计、后端开发、前端开发、整体验证。
2. 为每个阶段配齐必要的 skill，让阶段之间有明确的进入条件和产物交接。
3. 拆掉过重总控，把共享上下文下沉为工具 skill。
4. 建立工具层 `be-tools-*`，不占阶段号，贯穿所有阶段调用。
5. 把方案产出固化成可回看的文档，落工作台 `task/` 目录。

## 阶段定义

| 阶段号 | 阶段 | 进入条件 | 产物 | 退出条件 |
| --- | --- | --- | --- | --- |
| `00` | 方案设计 | 收到需求描述 | `task/YYMMDD_{主题}/README.md` 方案文档 | 用户确认方案 |
| `01` | 后端开发 | 方案已确认 | 表模型、DDL、领域代码、接口、Wire、契约文件 | 契约已生成，代码可编译 |
| `02` | 前端开发 | 契约文件已生成 | 前端页面、状态、样式（本次 `fe-*` 不动） | 前端按契约接通 |
| `03` | 整体验证 | 前后端改动齐备 | 验证结论、测试方案执行结果 | 验证命令全绿，无遗留阻塞 |

阶段之间不是简单串行。方案确认后可以只走部分阶段，例如纯 SQL 需求走 `00 → 01(0102/0103) → 03`；不影响前端的需求跳过 `0106` 和阶段 `02`。

## 编号规则

```text
be-{阶段号}{阶段内序号}-{能力后缀}    阶段 skill
be-tools-{能力后缀}                  工具 skill，不占阶段号
```

阶段号两位，阶段内序号两位。`xx00` 表示该阶段的入口，具体 skill 从 `xx01` 起。

## 职责边界

三条容易越界的线，重构后按下面切分：

1. **设计 vs 执行**：`be-0102-field-sql-flow` 只负责字段设计和 SQL 产出，`be-0103-db-change-flow` 才碰数据库。前者不连接数据库，后者不重新设计字段。
2. **写 vs 读**：数据库写操作只在 `be-0103-db-change-flow`，`be-tools-db-query` 严格只读，不执行任何 DDL/DML。
3. **生成 vs 消费**：`be-0106-contract-flow` 负责生成契约和输出复制清单，前端如何消费属于阶段 02，不在 be 族内规定。

## 方案产出规范

阶段 00 的方案统一落工作台 `task/YYMMDD_{主题}/README.md`，不再往业务仓 `docs/feature/` 新增（历史文件保留）。原因是跨端需求需要前后端共用同一份方案，业务仓单侧目录放不下。

模板：

```markdown
# {需求主题}

## 背景

## 需求理解

## 目标与边界

### 本期目标

### 本期不做

## 改动范围

### 涉及仓库

### 涉及库表

### 涉及接口

### 涉及前端契约

## 实施方案

## 验收标准

## 推荐实施顺序

### 功能测试

### 回归测试

### 兼容性测试

## 风险与回滚

## 落地记录
```

## 门禁

- 方案未确认，不改代码、不执行 DDL/DML。
- 方案缺任务目的、改动范围、涉及库表、验收标准任一项，不得进入阶段 01。
- live 环境 DDL/DML 必须用户显式授权，不得由全自动模式推断。
- 涉及接口、DTO、枚举、错误码变更，阶段 01 必须走 `be-0106-contract-flow` 后才能进阶段 03。

# 工作台介绍

豆伴工作台是个人 Agent 工作台，把跨端开发、内容生产、基建与自进化能力沉淀在一处，统一承接多个业务仓的全局路由、上下文聚合与跨仓编排。

## 它解决什么

- **多仓协作**：一个入口（`wb-router`）判断需求落到哪个业务仓、协议仓，还是只沉淀到知识库或 skill。
- **跨端开发**：`dev-flow` 族群按「方案设计 → 后端 → 前端 → 整体验证」四阶段推进，前后端各占一个阶段位。
- **内容生产**：beannote（豆小匠）内容线聚焦投资认知，按思考 / 梳理 / 表达三层打磨（族群已归档，编号体系保留）。
- **持续进化**：工作台根据真实使用过程自我改进，把稳定经验回流到 skill、知识库与脚本。

## 结构特征

- `.agents/skills/`：跨项目复用的 skill 实体，随工作台提交做版本管理；通过 `~/.agents` 外链共享给所有接入项目。
- `kb/`：可复用知识库，按公共知识、业务仓与系统分层。
- `task/`：工作台任务与上下文记录。
- `script/`：工作台辅助脚本（含跨平台结构检查 `make check`）。
- `business-repo/`：后端、前端、协议等独立业务仓集合。

## 核心能力

- **全局路由与跨仓编排**：需求进入后由工作台定位业务仓与上下文，跨仓影响统一编排。
- **阶段化开发流水线**：方案、后端、前端、验证四阶段门禁，纯前端跳过后端、纯后端跳过前端。
- **结构化任务追踪**：每个任务目录用 README / handoff / process 记录目标、交接与过程。
- **跨项目 skill 共享**：skill 只维护一份，经符号链接对所有项目生效。
- **自进化**：复现的问题与稳定经验自动回流为知识、skill 或脚本。

> 操作类规范（skill 命名、Git 提交、自进化触发机制、任务管理约定）收在 `AGENTS.md` 与 `task/README.md`，不在此文档赘述。

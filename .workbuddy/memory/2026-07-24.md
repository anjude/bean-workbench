## 修复 backend-superone 公众号草稿接口 panic
- 现象：`POST /api/so/wechat/article/draft` 报 `interface conversion: ... is common_dto.CreateWechatDraftReq, not *common_dto.CreateWechatDraftReq`。
- 根因：`bizctx.HandleReqParam` 把参数按**值类型**存入 `ctx.reqParam`（context.go:97 `reflect.ValueOf(reqParam).Elem().Interface()`），全仓 use_case 均按值断言；唯独 `CreateWechatDraft`（common_use_case.go:219）写成指针断言 `.(*...)`，导致 panic。
- 修复：`common_use_case.go:219-220` 改为值断言 + 取地址传参：`req := ctx.GetReqParam().(common_dto.CreateWechatDraftReq); f.commonService.CreateWechatDraft(ctx, &req)`（底层 service 签名要指针）。已 `go build ./use_case/...` 通过。
- 约定：backend-superone 的 use_case 统一用「值断言 `.(XxxReq)` + 传 `&req` 给要指针的 service」，不要直接指针断言 `.(*XxxReq)`。

## 公众号接口本地调用被微信 IP 白名单拦截（非代码问题）
- 修完 panic 后能进 handler，但微信侧报 `invalid ip 223.104.84.110, not in whitelist`（取 access_token 被拦）。
- 结论：backend 在本地跑时出口 IP 不在公众号后台 IP 白名单，本地直连微信调不通。解决：① 公众号基本配置把本机出口 IP 加白名单（家庭宽带 IP 可能动态变）；② 或把 backend 跑/调在已在白名单的远程测试机（如 8.155.38.83）而非 localhost。

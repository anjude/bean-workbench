### 更正（30 日凌晨，用户追问"brew 应该有的吧"）

**brew 装了**，是我误判。事实核对：

- `/opt/homebrew/bin/brew` 存在（6.0.19），通过 `/etc/paths.d/homebrew`（内容 `/opt/homebrew/bin`）进 login shell 的 PATH。用户终端里 `brew` 正常可用。
- 但 `brew leaves` 只有 `nvm`、`sunnyyoung/tap/wechattweak`、`zsh-completions` 三个，**确实没有 powershell**。所以"pwsh 用不了"的结论不变。
- 误判根因：**助手的 Bash 工具环境是非 login 非交互 shell**，不读 `/etc/paths.d`，PATH 里没有 `/opt/homebrew/bin`；也不读 `~/.zshrc`，没有 `~/sdk/go/bin`。我在这个环境里 `command -v brew` 返回空，就想当然写成了"本机没装"。
- 顺带核实：Go 1.27.0 在 `~/sdk/go`，`.zshrc` 末尾的 PATH + GOPROXY 配置**完好**（用户此前遇到过被 oh-my-zsh 模板覆盖丢失）。用户在自己终端里 `go` 可用，我这个环境里要写 `~/sdk/go/bin/go`。
- 教训：**判断"命令有没有装"之前，先区分是没装还是 PATH 没覆盖**。用 `ls /opt/homebrew/bin/brew`、`zsh -lc 'command -v brew'` 这类方式复核，别只信 `command -v`。
- 顺手验证了脚本兼容性：`/usr/bin/python3`（3.9.6）和工具环境的 3.13.12 都能跑通 `make check`，脚本只用标准库，没踩版本坑。

- 边界模块设计决策（截至本日讨论）：
  - 互动模型：**每人一份（两份），各写各的，对方只读**——边界是"我的使用说明书"而非"我们的约定"，合一份会与"约定"面板撞语义，否决单份共享。
  - 表态机制（用户提出、我认可为核心价值）：对方对每条边界可标 **认同 / 难做到**。认同=安全区确认；难做到=提前亮红灯，直接服务"预防争吵"。标"难做到"推温和通知，被动查阅升级为被动+主动预防。
  - 推荐条目（用户提出）：我给伴侣推一条边界建议，TA 一键收进自己那份——"社交版冷启动"，比系统模板更有人情味；比表态机制多一层管道，建议放 MVP 之后。
  - 数据模型影响：boundaries 表加 `partner_reaction` 列（2人空间天然1:1，加列最简）；或用独立 `boundary_reactions` 表（更可扩展）。
  - MVP 收口候选：两份 + 示例模板(冷启动) + 表态(认同/难做到) + 难做到通知。推荐条目后续。
  - 内容分类沿用：底线 / 喜欢 / 不喜欢 三类。
  - 后端 boundary 接口仍仅为前端约定，未验证服务端实现。
- UI/UX 布局（进行中，待用户确认）：确认两份后详设展示。已排除移动端左右两列并列（窄屏压字）。用户否决左右翻转手势，改纯顶部分段「我的 / Ta的」点击切换。反应按钮置于条目**右侧**（与内容左右布局，右侧竖排 认同/难做到 两按钮）。**兼容概览 chip** = 实时派生计数（partner_reaction='struggle' 的数量），常驻状态指示：点击仅跳转/筛选到冲突条目、不消除数字；归零需冲突真正解决（对方改回认同 / 改删边界）；可选"已读变灰"避免每次喧哗。chip 主战场在「我的」视图。
- **品牌调性优化（结合 carbon 定位收口，已写进 docs/功能设计文档.md「7. 边界」）**：重读 docs/brainstorm 产品规划头脑风暴 + 设计 token（暖米白 #f5f0ea + 琥珀 glow #f0a050，无红/绿 token），发现原设计三处踩品牌红线，修正如下：

## skill 跨项目共享（最终正确方案：实体在工作台，~/.agents 是外链）

用户要求让其他项目的 Agent 也能读到工作台的 skill，且工作台保留对 skill 的版本管理。任务记录 `task/260830_skills-externalize/README.md`。

最终做法：

- skill 实体留在 `bean-workbench/.agents/skills/`，由工作台 git 跟踪（33 个普通文件条目）。
- 在 home 建外链 `ln -s /Users/bean/workspace/bean-workbench/.agents ~/.agents`，多数 Agent 工具读 home 下的 `.agents` 即可拿到同一套 skill；其他项目想在本仓也看到再建 `ln -s ~/.agents <项目根>/.agents`。
- `AGENTS.md`「跨项目共享」、`README.md`、`docs/workspace.md`、`docs/self-evolution.md`、`.agents/README.md` 全部按此方向写。
- 去掉 skill 正文里「单独到 ~/.agents 提交」的说法。

### 踩过的坑：方向建反了

第一版做成实体在 `~/.agents`、工作台 `.agents` 是指向它的 symlink，还给 `~/.agents` 单独 `git init`。这是错的：把 skill 从工作台版本管理里挖走了，`make commit` 带不走，每次还得去另一个仓库提交；而且根本没解决「别人能读到」之外的事。已改回实体在工作台、外链在 home。

顺便清掉了 `.agents/` 里两个残留死链接：一个自引用环 `.agents/.agents`（之前 `ln -s` 在 `~/.agents` 已是链接时又建了一层），一个负向测试忘删的 `.agents/fake-agents -> /tmp/fake-agents`。两者都未被 git 跟踪，直接 `rm -f` 清掉。

### 踩坑：`Path.rglob` 不跟随符号链接

`.agents` 或其子目录一旦是链接，check 脚本的链接检查会空转——skill 里的坏链接全漏检还报「通过」。改为自写递归遍历跟随目录 symlink，用 real path 集合防循环；断链时必需文件检查只列「缺失」，加显式断链提示。

教训：**改了目录结构后，校验脚本必须做负向测试**。这次验证了 symlink 下坏链接、skill 命名错、外链缺失/指向别处/被换成真实目录、skill 仓库未提交五种情况都能报出。

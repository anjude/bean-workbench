## 运行时报错 TypeError: reading 'uid'（根因更正：inline SVG，非 easycom）
- 现象：首页（及任何用 so-custom 的页）渲染报 `Cannot read properties of null (reading 'uid')`，栈指向 `pages/index/index.js` 创建子组件 vnode 处；即使把 `SoCustom` 显式 import 后整包重编译，错误依旧。
- 误判（已推翻）：上一轮归因为 easycom 热重载没重读 pages.json。实测 usingComponents 里 `so-page`/`so-custom` 都正确注入了，组件注册没问题。
- 真正根因：**`so-custom.vue`（及 `settings.vue`）模板里手写了 `<svg>`/`<path>`，uni-app mp-weixin 平台不支持 `<svg>` 原生元素**。编译器把 `<svg>` 当宿主元素 vnode（type 字符串 `"svg"`），mp 渲染器不认识、又当成组件去 `resolveComponent("svg")`，解析不到 → `createVNode(null)` → 报 `reading 'uid'`。`so-custom` 是唯一含 SVG 的组件，且首页正好用它 → 完美对上。用户原话「应该参考 profile 页吧」点醒：carbon profile 用的是 `<uni-icons>`（官方 uni-ui，非 cuIcon 字体），根本不碰 SVG。
- 修法：把两处 inline SVG 换成 `<uni-icons>`（`so-custom` 用 `back`/`home`，`settings` 用 `color`/`info`），图标颜色传 `'var(--so-text-primary)'` / `'var(--so-color-primary)'` / `'var(--so-color-info)'` 跟随主题令牌；删掉 `so-custom` 里已无用的 `.so-bar__icon` 样式。`^uni-(.*)` easycom 规则本就存在，`uni-icons` 自动注入 usingComponents（已在 so-custom.json / settings.json 验证）。
- 教训（重要）：**uni-app mp-weixin 不支持模板里的 `<svg>` 元素**，一律用 `uni-icons` / 字体图标 / CSS / `<image>` 替代。这是平台硬限制，不是配置或热重载问题。
- 验证：`type-check` 通过；`build:mp-weixin` 成功；dist 全仓无 `resolveComponent("svg")`/`resolveComponent("path")` 残留；`so-custom.json`/`settings.json` 的 usingComponents 均含 `uni-icons`。

## 浅色模式可见性：设置按钮（及首页卡片）看不到
- 现象：首页「设置」按钮深色模式可见、浅色模式看不到；同理首页卡片浅色下也几乎看不见。
- 排查：`.theme-light` 与 `:root` 编译后都正确带 `--so-color-primary:#07c160`，令牌没丢；按钮规则也正确编译为 `.home__settings-btn{background:var(--so-color-primary);color:#fff}`。根因不在令牌。
- 根因（两处同类）：① 设置按钮是原生 `<button>`，对 `background` 简写里的 `var()` 支持不稳 → 浅色下 `var()` 解析失败、背景退化透明，白字落白底「消失」；深色下微信原生 button 自带深色默认背景兜底故可见。② 首页卡片 `.home__card` 用 `--so-bg-elevated`(浅色 #fff)，页面/`.so-page` 底色是 `--so-bg-base`(浅色 #fff) → 白卡白底，浅色不可见；深色下卡片 #2a2a2a / 页面 #1a1a1a 故可见。
- 修法：`index.vue` 按钮 `background` 简写改 `background-color` 并先写死 `#07c160` 兜底再 `background-color:var(--so-color-primary)`；`index.vue` `.home` 加 `background-color:var(--so-bg-secondary)`（浅灰打底，与设置页「页面=secondary、卡片=elevated」同模式），不动令牌、设置页不受影响。
- 教训：① 原生 `<button>` 的 `background` 简写慎用 `var()`，用 `background-color` + 硬编码兜底更稳；② 浅色主题里 elevated 表面必须明显异于 base 底色，否则白卡白底。
- 验证：`type-check` 通过；`build:mp-weixin` 成功；编译产物 `index.wxss` 确认按钮含 `background-color:#07c160;background-color:var(--so-color-primary)`、`.home` 含 `background-color:var(--so-bg-secondary)`。待用户整包重编译后目测确认。

## 热重载（HMR）偶发 common_vendor.defineComponent is not a function
- 现象：热重载会话（URL 含 `appservice-hotreload`）下报 `common_vendor.defineComponent is not a function`（index.js:15:46），并级联出 `reading 'uid'`（index.js:46:26 renderProps）。compile 成功后微信模拟器白屏/报错。

- 佐证：纯 CSS 改动（浅色可见性修复）不可能引发 JS 层 `defineComponent is not a function`；SVG 修复此前整包重编译已确认不报错。
- 处置：停掉 dev 进程，**整包重启**（不走热重载）；若仍报，清 `dist/`（及 `unpackage/`、`node_modules/.cache`）后重跑。源码本身 type-check + build 均通过，无需改代码。

## 面板空白真因：首页高度链断点（不是数据问题）
- 豆哥贴出接口返回：err_code=0、list 4 条（加密账号/TODO/测试主题/碎碎念），数据完全正常 → 问题在渲染。

## macOS 适配：backend-superone 的 make nonlive / release
- 触发：豆哥跑 `make nonlive` 报 `powershell: command not found` + `./push.bat: Permission denied`。
- 原 Windows 依赖共 4 处，全部改为可移植写法：
  1. `LINTER := $(shell golangci-lint --version 2> NUL)` → `2>/dev/null`。**副作用：macOS 上会在仓库根生成名为 `NUL` 的字面垃圾文件**（已删）。

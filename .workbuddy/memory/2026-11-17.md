## QBG1 第 19 轮：更正判断，真因是画布尺寸兜底（上传 0.1.3）
- **更正第 17 轮**：「根因是坐标基准混用、整体左偏一道」不成立。0.1.2 真机复现同一症状，用户补充「左边两个道是好的」，与整体平移矛盾。删 18% 偏移、改用相机视口反算方向没错，但没触到误差源；把编译通过 + 数值自洽当成修复完成，是返工直接原因。
- **真因**：`initCanvas` 里 `boundingClientRect` 写入实测 `rect.width`，随后 `fields({node:true,size:true})` 回调又用 `width: info.width || 375` 覆盖。375 是整屏宽，canvas CSS 只占 82%，点击比例被缩小 18% → 命中向中心收缩 → 左二正确、右三各进左邻道。数值复现 `0,1,1,2,3` 与用户描述逐条吻合。
- **修法**：`fields` 只拿 node；rect 实测为唯一尺寸来源（兼容返回数组）；兜底按 CSS 算 `windowWidth*0.82` 与扣减后的高度，删 375/800 和 `canvasPageLeft` 自校准；rect 晚到补一次 resize。
- **复用经验**：命中测试的画布宽必须与渲染相机视口同源；硬编码整屏宽兜底表现为「右侧依次左偏、左侧看似正常」而非整体平移。同一 NodesRef 的多个回调不要互相覆盖尺寸。
- 验证：type-check / build / diff --check 通过；新包无 375/800 残留；两种事件坐标 × 四组窗口尺寸均命中 `0,1,2,3,4`。上传 `0.1.3` 回执 `✔ upload`（主包 1.9 MB + 分包 596.6 KB）。仍未 commit / 提审 / 发布。
- 回填：`process/03-开发与迭代.md` 第 19 轮（含被推翻判断）、任务 `README.md`、`task/registry.md`。

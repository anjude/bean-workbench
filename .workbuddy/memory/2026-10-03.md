- **🚨 小程序自定义组件 emit 不能用原生事件名**（2026-10-05 真根因，血泪）：`so-timeline` emit `longpress` → 编译成 `bindlongpress`，这是微信**原生事件名**，父组件 `@longpress` 收到的是**事件对象**而不是 emit 的 payload → `item` 变 undefined → `item.id` 空 → 后端报 `UpdateTopicLogReq.ID required`。**`tap`/`longpress`/`touchstart` 等原生事件名一律不能用作自定义 emit 名**（`select` 这类不冲突的名字正常）。改名 `logMenu` 后产物确认：组件内 `bindlongpress`，父组件 `bindlogMenu`。
- **误判更正**：同一天我先判成「模板内联 `emit('longpress', item)` 编译后丢参数」——**错的**。内联与具名写法编译出的事件映射结构相同（`e.o(fn, n.id)`），我只凭 wxml 里 `item.f`/`item.g` 的对称性就下结论，证据不足。教训同「backup 那条」：**说某个实现有 bug 之前，必须核到能区分两种假设的那一层**，不然就是把猜测当结论。
- **附带教训**：**`JSON.stringify` 会静默丢掉 undefined 字段** → 少传 id 时后端只看到 `{"top":...}`，报「ID 必填」，错误指向与根因完全错位。必填标量在 composable 里**进 await 之前就取成标量 + 校验**（`requireId()`），别让残缺请求出海。
- **backup 的菜单与排序照抄**（2026-10-05 豆哥：「backup有的抄，别瞎搞」）：日志长按菜单 = `[移到最前, 置顶/取消置顶, 标记, 删除]`（去掉「切换主题」），**「置顶」是常驻二态项**，不是只在已置顶时出现。排序 `sortLogs` = `top DESC → createTime DESC`，置顶排整列最前。
- **🚨 uni-app 自定义组件的布尔 prop 必须写 `:prop="true"`，不能写无值形式**（2026-10-05 豆哥发现返回按钮点了没反应）：`<so-custom is-back>` 编译到小程序后**标签上没有属性、props 里也没有这个键**，组件内 `isBack` 恒 false → 返回按钮根本没渲染（topic-detail/topic-edit/profile/log-detail 全部中招）。改 `:is-back="true"` 后产物出现 `e.p({"is-back":!0})`。同类已修：首页 `<so-page reverse>`、`<so-custom transparent>`。原生组件（`refresher-enabled` 等）不受影响，wxml 本身支持无值属性。
- **「更多」按钮位置：放头部卡右上角，不放导航栏右侧**（2026-10-05 豆哥：「不要在navigate title右边放更多按钮」）。做法：删掉 `so-custom` 的 `#right` 插槽；头部卡改横向两栏 `__head-main`（flex:1;min-width:0）+ `__more`（48rpx 方形热区，`margin:-6rpx -6rpx 0 0` 抵掉卡内边距），图标用 `uni-icons type="more"`，颜色压到 `--so-text-secondary`。编辑态用 `v-if` 收掉——那时底部已有保存条。
- **⚠️ 页面 `index.wxss` 是空的**：uni-app 把样式全打进 `app.wxss`（39KB），页面 wxss 0 字节。查「样式有没有生效」要查 `app.wxss`，别在页面 wxss 里找。
- **类名撞名是真实风险**：topic-detail 的「更多」图标和列表底部「没有更多了」提示撞了同一个 `__more`，两条规则互相污染。页面级 scss 起名按元素职责区分（`__more` 按钮 / `__more-hint` 提示）。核对脚本要排噪：全局组件类（`so-btn*`/`so-card`）加白名单，`:class="{ 'x--y': flag }"` 先 strip 引号花括号。
- **`so-custom.onBack` 不要预判页面栈**（2026-10-05）：原来先 `getCurrentPages?.()` 再决定 `navigateBack`/`reLaunch`。`getCurrentPages` 是**裸全局**，uni-app 自己的运行时 0 处用到它（只用 `getApp`），一旦在组件作用域解析不到就是 ReferenceError，事件回调里被吞掉 → 表现就是「点了没反应、控制台还干净」。改成 `uni.navigateBack({delta:1, fail: () => reLaunch(首页)})`——navigateBack 自己知道能不能退。
- **查「点击无响应」的固定排查顺序**（2026-10-05）：① 有没有 `showLoading({mask:true})` 没 hide（全局遮罩吞一切点击，最像的一种）；② 有没有 `addInterceptor` / 对 navigateBack 的包装；③ 事件名是不是微信原生名；④ 布尔 prop 是不是无值写法；⑤ 页面栈里有没有重复页（退一份看着像没动）；⑥ 最后才看 z-index / 原生组件覆盖。
- **uni-app 动态 props 的完整链路**（补记，用来判断「prop 到底落没落到」）：模板 `:is-back="true"` → 编译成 `u-p="{{b}}"`，`b` 来自 `renderProps()` 返回的 `"uid,propsId,counter"` 字符串（**不是对象**）→ 运行时 `findComponentPropsData()` 按 `split(",")` 从 `propsCaches` 取回原对象 → Vue `setFullProps` 里 `camelize()` 把 `is-back` 变成 `isBack`。所以 kebab 命名的动态 prop 是能正常落地的，别只看编译产物就下结论。
- **导航栏（so-custom）照抄 backup / carbon 的 cu-custom，不要自己发挥**（2026-10-05，豆哥「为什么backup和carbon都没有类似的问题」一语点破）。它们的返回按钮是**一层 view + 原生 `<text>` 字体图标**；我们曾经套了 `uni-icons`（自定义组件，根节点自带 `bindtap`，图标靠自带字体渲染）。**导航栏这类高频热区不要嵌套自定义组件，也不要依赖图标字体**——现在 `so-custom` 的 usingComponents 是空的，返回用 `‹`、主页用 `⌂`、更多用 `⋯` 这些系统字体必有的字符。`onBack` 也是照抄 `BackPage`：`typeof getCurrentPages === 'function'` 守卫 + `__wxConfig.pages[0]` 兜底 + `navigateBack({delta:1})`。热区记得给 `min-width: 72rpx`（照 carbon）。
- **⚠️ 更正此前记的「无值布尔属性编译丢失」（2026-10-05 实测推翻）**：`<so-custom is-back>` 与 `:is-back="true"` 编译产物**完全一致**——无值写法只是不在 wxml 标签上，照样进 `u-p`（`{"is-back":!0}`）。当时只看 wxml 就下结论，没看 `u-p`。**判断 prop 有没有落地，必须追到 `u-p` / propsCaches 那一层。**
- **教训（豆哥两轮否定后的总结）**：卡住时不要在自己的代码里继续推演，先问「backup / carbon 有没有同样的功能、它们怎么写的」——它们是线上跑着的代码。推演两次都错，照抄一次就对。

## uni-superone 基建：utils/adapt 适配层
- 豆哥指令：在 `src/utils` 下建 `adapt/` 适配层——**定义平台无关接口，按平台实现，外层 utils 只依赖接口、不感知平台；将来上浏览器只换 adapt 实现、外层零改动**。参考 carbon 的 `Request`/`CacheManager` 逻辑（carbon 无 adapt 层），但本仓用真正的适配缝（接口+各端实现）。
- 落地结构：
  - `adapt/`：`http-types.ts`(HttpAdapter 接口+HttpRequestOptions/HttpResponse)、`http.ts`(get/setHttpAdapter 注册表，默认 uni)、`http-uni.ts`(uni 实现，包 uni.request→Promise)、`http-browser.ts`(示例，`setHttpAdapter(new BrowserHttpAdapter())` 启用)；`storage-types.ts`(StorageAdapter 接口)、`storage.ts`(get/setStorageAdapter)、`storage-uni.ts`(uni StorageSync 族)、`storage-browser.ts`(localStorage+JSON 序列化示例)；`index.ts` 桶。
  - 外层（平台无关，只用接口）：`http/client.ts`(`Request` 类：get/post/put/delete、请求/响应拦截器、snake/camel 参数转换、errCode===0 成功、登录过期码 -100004 触发 `doRefresh` 串行刷新后重试一次；`setAuthRefresher` 注入真实登录)、`http/types.ts`、`http/param-converter.ts`、`http/index.ts`(注册 token 注入拦截器，从 CacheManager 读)；`storage/manager.ts`(`CacheManager`：get/set/remove/has/clear+日志)、`storage/keys.ts`(CACHE_KEYS)、`storage/index.ts`；`logger.ts`(极简封装)、`index.ts`(桶)、`constant/config.ts`(baseURL 占位，待填真实后端)。
- 缝的关键点：uni 端 StorageSync 原生支持对象、浏览器端 localStorage 仅字符串由实现层 JSON 序列化——差异全封在 adapt，CacheManager 完全无感。请求原语同理：adapt 只跑通一次 HTTP 并归一化，baseURL/参数转换/业务码/拦截器都在外层 client。
